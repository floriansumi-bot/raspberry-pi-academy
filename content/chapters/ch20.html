Your Raspberry Pi 5 is a capable little computer — and like any computer connected to a network, it deserves a few sensible precautions. This chapter walks you through the most important habits: locking down access, keeping software fresh, adding a firewall, and protecting the hardware itself. None of it requires a security background — just a few minutes of your time and a willingness to follow the steps.

Why Bother with Security?

A Raspberry Pi running on your home network is unlikely to be attacked within minutes of being switched on. But over time, a few real risks build up:

  • Anyone on your Wi-Fi — a guest, a compromised smart TV, or a neighbour who knows your password — could log in to the Pi if it still uses the default password.
  • If you ever open the Pi to the internet, even for a few minutes, automated scanners called "bots" will find it and try common passwords within hours.
  • An out-of-date system may have known security holes that are trivially exploited.

The good news is that a handful of straightforward steps make the Pi extremely resistant to the vast majority of threats, without turning your life into a cybersecurity course.

Step One: Change the Default Password

When you first set up Raspberry Pi OS, the installer asked you to create a username and password. If you skipped that step or used something obvious like raspberry, now is the time to fix it.

Careful: The old default username was pi and the old default password was raspberry. Many automated attack scripts try this combination first. If your Pi still uses them, change both immediately.

What makes a strong password?

A strong password is long, random, and unique — used nowhere else. You do not need to memorise a string of symbols; a passphrase made of four or five random words is both memorable and very secure. For example: kettle-purple-moon-46-fence is far stronger than P@ssw0rd!.

In plain words: A passphrase is a password made of several words strung together. Length beats complexity — a 30-character passphrase of common words is harder to crack than an 8-character mix of symbols.

To change your password, open a Terminal on the Pi (or connect via SSH) and run:

passwd
This command opens the "change password" tool for your own user account. It will ask you to type your current password, then ask you to type the new password twice to confirm it. The characters you type will not appear on screen — this is normal and deliberate.
Tip: Use a password manager (such as Bitwarden, which is free) to generate and store a strong, unique password. You only need to remember one master password, and the manager handles everything else.

Checking for other user accounts

On a freshly set-up Pi 5 running Bookworm there should only be your own user account (plus the system root account that runs in the background). It is worth confirming no unexpected accounts exist:

awk -F: '$3 >= 1000 && $1 != "nobody" { print $1 }' /etc/passwd
This command reads the file /etc/passwd (which lists every user account on the system) and prints only the ones with a user ID of 1000 or above. Those are the "real" human user accounts. On a fresh Pi you should see just your own username. If you see names you do not recognise, investigate before continuing.
Note: The root account is a special all-powerful administrator account built into Linux. On Raspberry Pi OS, the root account does not have a password set and cannot be logged into directly — you use sudo instead. Do not set a root password unless you have a specific reason to.

Step Two: Keep the System Updated

Software updates fix security vulnerabilities — holes that attackers could use to take control. Running apt regularly is one of the single most effective things you can do.

In plain words: apt is the Raspberry Pi OS package manager — the tool that downloads and installs software and updates from the official Raspberry Pi and Debian servers.

We covered this in detail in Chapter 6. As a recap, run these two commands:

sudo apt update
sudo apt full-upgrade -y
Line 1 — sudo apt update: Downloads the latest list of available packages and versions from the internet. It does not change anything on your system yet — it only refreshes the catalogue.

Line 2 — sudo apt full-upgrade -y: Installs every available update, including updates that require removing or replacing existing packages (which is what full-upgrade does that plain upgrade does not). The -y flag answers "yes" automatically to any confirmation prompts.
Tip: Make this a habit — run it once a week, or at least once a month. It takes only a minute or two on a fast connection.

Automatic security updates

If you want the Pi to install security-related updates on its own in the background, you can install the unattended-upgrades package:

sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure --priority=low unattended-upgrades
Line 1: Installs the unattended-upgrades tool, which can apply security updates automatically without you needing to run apt manually.

Line 2: Opens a simple text-based configuration screen asking whether you want automatic updates enabled. Choose Yes. The tool will then download and apply official security patches in the background each day.
Note: Unattended-upgrades only installs security updates automatically. Major version upgrades and new software still require your manual approval.

Step Three: SSH Keys — Log In Without a Password

In Chapter 11 you learned to connect to the Pi remotely using SSH (Secure Shell). By default, SSH asks for your password every time. There is a smarter, more secure method: SSH keys. Once set up, you never type a password to SSH in — and you can disable password login entirely, which blocks automated attackers completely.

What is an SSH key pair?

In plain words: An SSH key pair is a pair of matching digital files — a public key (like a padlock) and a private key (like the only key that opens that padlock). You put the public key (the padlock) on the Pi. You keep the private key (the opening key) on your Windows PC. When you connect, your PC proves it holds the matching key — without ever sending the key itself over the network. No password is needed.

The private key must stay on your Windows PC and never be shared. The public key can be placed on any number of servers — it is safe to share because it can only be used to verify the private key, never to impersonate it.

Generating a key pair on Windows 11

Windows 11 comes with a built-in SSH client, so you do not need to install anything extra. Open a PowerShell window on your Windows PC (press Win + X and choose "Terminal" or "PowerShell").

  1. In the PowerShell window, type the following and press Enter: 
    ssh-keygen -t ed25519 -C "my-pi-key"
    ssh-keygen: The key-generation program built into Windows 11.

    -t ed25519: Tells it to use the Ed25519 algorithm — a modern, fast, secure algorithm that produces short keys. This is the recommended choice over the older RSA algorithm.

    -C "my-pi-key": Adds a comment label to the key so you can identify it later (you can use any text you like here).
  2. The program asks: Enter file in which to save the key. Press Enter to accept the default location (C:\Users\YourName\.ssh\id_ed25519). Two files will be created:
    • id_ed25519 — your private key. Never share this file.
    • id_ed25519.pub — your public key. This is the one you will copy to the Pi.
  3. The program then asks for a passphrase. This is an optional extra layer of protection: if someone steals the private key file, they still cannot use it without this passphrase. You can press Enter twice to skip it, but setting a passphrase is recommended — Windows will remember it for you via a feature called the SSH Agent, so you only type it once per Windows session.
Note: If you already have a key pair from a previous project (you see a message like "already exists"), you can reuse it — just press n when asked to overwrite, and skip to the next section.

Copying the public key to the Pi

Now you need to place the public key into a special file on the Pi called ~/.ssh/authorized_keys. There are two ways to do this.

In plain words: The tilde (~) is a shortcut that means "your home folder". So ~/.ssh/authorized_keys means the file named authorized_keys inside the hidden .ssh folder inside your home folder on the Pi.

Method A — using ssh-copy-id (easiest, from Git Bash on Windows)

Windows 11's built-in PowerShell does not include ssh-copy-id, but if you have Git for Windows installed (which gives you Git Bash), you can use:

ssh-copy-id -i ~/.ssh/id_ed25519.pub yourname@raspberrypi.local
ssh-copy-id: A helper tool that reads your public key and appends it to the authorized_keys file on the remote machine automatically.

-i ~/.ssh/id_ed25519.pub: Tells it which public key file to use.

yourname@raspberrypi.local: Replace yourname with the username you chose when you set up the Pi, and raspberrypi.local with the Pi's hostname or IP address. It will ask for your Pi's password one last time to authenticate and copy the key.

Method B — paste it manually (works from plain PowerShell on Windows)

  1. In PowerShell on your Windows PC, display the contents of your public key: 
    Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
    This PowerShell command reads and prints the contents of your public key file to the screen. The output is one long line starting with ssh-ed25519. Select it all and copy it to your clipboard (Ctrl+C).
  2. Now SSH into the Pi using your password as normal: 
    ssh yourname@raspberrypi.local
    Opens an SSH session to the Pi, logging in with your password as before. Replace yourname and raspberrypi.local with your actual username and Pi address.
  3. On the Pi, create the .ssh directory if it does not already exist, and open the authorized_keys file: 
    mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
    Line 1 — mkdir -p ~/.ssh: Creates the hidden .ssh folder in your home directory. The -p flag means "don't complain if it already exists".

    Line 2 — chmod 700 ~/.ssh: Sets the folder's permissions so that only your own user account can read or write it. SSH refuses to work if the folder permissions are too open.

    Line 3 — nano ~/.ssh/authorized_keys: Opens the nano text editor to create (or edit) the authorized_keys file.
  4. In the nano editor, paste the public key you copied from Windows (right-click in the terminal window to paste, or use Ctrl+Shift+V). It must be all on one single line. Press Ctrl + X, then Y, then Enter to save and exit.
  5. Set correct permissions on the file: 
    chmod 600 ~/.ssh/authorized_keys
    Sets the authorized_keys file to be readable and writable only by your own user. SSH will refuse to use the file if anyone else can read it — this permission setting satisfies that requirement.

Testing the key login

Without closing your current SSH session (keep it open as a safety net in case something goes wrong), open a new PowerShell window and try connecting:

ssh yourname@raspberrypi.local
If the key is set up correctly, the Pi will log you in without asking for a password — it silently verified your private key against the stored public key. If it still asks for a password, re-check that you pasted the key correctly on a single line with no extra spaces, and that the file permissions on the Pi are exactly 700 for ~/.ssh and 600 for ~/.ssh/authorized_keys.

Optionally disabling password login (advanced — read carefully first)

Once key login is confirmed to be working, you can disable password authentication entirely. This means only computers that hold the correct private key can log in via SSH — brute-force password guessing becomes impossible.

Careful: If you disable password login and then lose your private key (for example, your Windows PC fails and you had no backup), you will be permanently locked out of SSH. Before doing this, either back up your key files to a USB drive or cloud storage, or make sure you have a keyboard and monitor you can plug into the Pi so you can still log in locally. Confirm key login works perfectly before taking this step.
  1. On the Pi, open the SSH server configuration file: 
    sudo nano /etc/ssh/sshd_config
    Opens the SSH server configuration file in the nano text editor with administrator (sudo) privileges. This file controls how the SSH server behaves.
  2. Find the line that says PasswordAuthentication. If it starts with a #, that means it is commented out (ignored). Remove the # and change the line to read exactly: 
    PasswordAuthentication no
    This line tells the SSH server to refuse password-based login attempts. Only key-based authentication will be accepted. Make sure the line does not start with a # character — a # at the start means the setting is ignored.
  3. Save the file (Ctrl + X, then Y, then Enter), then restart the SSH service: 
    sudo systemctl restart ssh
    Restarts the SSH server so it reads the new configuration. Your current SSH session stays open — the restart only affects new connections from this point onward.
  4. Test immediately by opening a fresh PowerShell window and connecting again. If it works, you are done. If it does not, your existing session is still open so you can undo the change — re-open the file and set PasswordAuthentication yes, then restart ssh again.
Tip: You can also change the default SSH port from 22 to a high, non-standard port number (for example 2222 or 51234). This does not stop a determined attacker but does dramatically reduce the number of automated probing attempts that reach the Pi. To do this, add a line Port 2222 to /etc/ssh/sshd_config, then run sudo ufw allow 2222/tcp before restarting ssh. When connecting you would then use ssh -p 2222 yourname@raspberrypi.local.

Step Four: A Simple Firewall with ufw

In plain words: A firewall is a gatekeeper that decides which network connections are allowed in and which are blocked. ufw stands for "Uncomplicated Firewall" — it is a beginner-friendly tool built on top of Linux's powerful but complex built-in firewall system.

For a home Pi, the default Raspberry Pi OS setup is fairly safe already, but adding ufw gives you explicit control and an extra layer of defence if you ever install a new service by accident.

  1. Install ufw: 
    sudo apt install ufw -y
    Downloads and installs ufw from the official Raspberry Pi OS software repository. The -y flag confirms the installation automatically.
  2. Allow SSH connections — do this before enabling the firewall, otherwise you will lock yourself out of remote access: 
    sudo ufw allow ssh
    Tells ufw to always permit incoming connections on the SSH port (port 22). Without this rule, enabling the firewall would immediately cut off your remote access.
  3. If you are running a web server on the Pi and want to allow normal web traffic, add these rules too — skip them if you have no web server: 
    sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
    Line 1: Allows unencrypted web traffic (HTTP) on port 80.

    Line 2: Allows encrypted web traffic (HTTPS) on port 443.
  4. Enable the firewall: 
    sudo ufw enable
    Turns on the firewall immediately and configures it to start automatically every time the Pi boots. It will warn you that existing SSH connections may be disrupted — type y to confirm. Because you added the SSH rule in step 2, SSH connections will continue to work fine.
  5. Check the current status and active rules: 
    sudo ufw status verbose
    Prints a summary of whether ufw is active and lists all the rules currently in effect — which ports are allowed or blocked, and in which direction. You should see Status: active and a rule permitting SSH.

Here is what a typical ufw status looks like for a Pi used for SSH access and a web server:

To (port) Action From
22/tcp (SSH)ALLOW INAnywhere
80/tcpALLOW INAnywhere
443/tcpALLOW INAnywhere
Everything elseDENY INAnywhere
Note: ufw blocks incoming connections by default while allowing all outgoing connections. This means the Pi can freely browse the web, download updates, and contact external services — only unsolicited connections arriving from outside are filtered.

Step Five: Do Not Expose the Pi Directly to the Internet

This is one of the most important rules in this chapter. Never open ports on your home router to forward traffic directly to your Pi unless you are an experienced network administrator who understands the implications. Here is why:

  • The moment a port is open to the internet, automated scanners will find it — usually within an hour.
  • Even with a strong password and SSH keys, a misconfigured service or an unpatched vulnerability can be exploited.
  • Home internet connections typically have a dynamic IP address that changes, making direct access unreliable anyway.

Instead, use one of these safer approaches:

Tool What it does Best for
Tailscale Creates a private, encrypted virtual network between your devices. Only your approved devices can reach the Pi. SSH access from anywhere; connecting Pi to your laptop and phone securely.
Raspberry Pi Connect Official Raspberry Pi remote desktop and shell service. Free, easy, no router configuration needed. Beginners who want to see the Pi's desktop from another computer.
Cloudflare Tunnel Publishes a web service running on the Pi through Cloudflare's network, with HTTPS and DDoS protection built in. Sharing a website or web app running on the Pi with the public.
Tip: Tailscale is free for personal use with up to 100 devices and is the simplest way to access your Pi securely from anywhere. Install it on Raspberry Pi OS Bookworm using Tailscale's official installer script — do not use a plain apt install as the package is not in the default Raspberry Pi OS repository. Open a Terminal on the Pi and run: 
curl -fsSL https://tailscale.com/install.sh | sh
This downloads and runs the official Tailscale installation script directly from tailscale.com. The script detects your operating system (Debian Bookworm on a Pi 5), adds the correct package repository, and installs Tailscale. After it completes, run sudo tailscale up and follow the link it shows to sign in and approve the Pi in your Tailscale account.
Careful: Running a script piped directly from the internet (the curl … | sh pattern) is only safe when you trust the source completely. Only do this with well-known, reputable services such as Tailscale, and always verify you are typing the URL correctly.

Step Six: fail2ban — Blocking Repeated Bad Login Attempts

In plain words: fail2ban watches your system's log files for repeated failed login attempts and automatically blocks the IP address of whoever is trying. Think of it as a bouncer who notices someone trying the wrong door code five times in a row and then bars the door to them for an hour.

Even if you have SSH keys enabled and password login disabled, fail2ban is good practice: it reduces log clutter and slows down any scanners that probe your Pi.

  1. Install fail2ban: 
    sudo apt install fail2ban -y
    Downloads and installs fail2ban from the software repository. Once installed, it starts running automatically in the background and begins watching the SSH login logs immediately.
  2. Create a local configuration file so your settings survive future package updates: 
    sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
    Copies the default configuration file to a new file called jail.local. fail2ban always reads jail.local in preference to jail.conf, so any customisations you make here will not be overwritten when fail2ban is updated.
  3. Check that the SSH protection is active: 
    sudo fail2ban-client status sshd
    Asks the fail2ban service to report the status of its SSH "jail". You should see that the jail is active and a count of currently banned IP addresses (probably zero on a freshly set-up Pi). If the command returns "sshd is not a valid jail", try sudo fail2ban-client status ssh instead.

The default settings ban an IP address for 10 minutes after five failed login attempts within 10 minutes. You can adjust these values in /etc/fail2ban/jail.local if you wish, but the defaults are sensible for most home Pi setups.

Step Seven: Disable Unused Interfaces with raspi-config

The raspi-config tool lets you switch hardware interfaces (SSH, VNC, the camera connector, and so on) on or off. Disabling anything you are not using is good security practice — an interface that is switched off cannot be attacked.

In plain words: An interface here means a communication channel — for example, the SSH network service, or the I2C bus used by electronic sensors. If you are not using it, turning it off removes a potential entry point.
sudo raspi-config
Opens the Raspberry Pi Configuration tool in the terminal. Use the arrow keys to navigate and Enter to select. Go to Interface Options to enable or disable SSH, VNC, the camera connector, I2C, SPI, and other interfaces. Select Finish when done; the Pi may ask you to reboot.

A sensible starting point for a Pi used as a desktop or SSH server:

Interface Recommended setting Why
SSHEnabledNeeded for remote terminal access.
VNCOnly if you use itDisable if you only use SSH; VNC opens another port.
CameraOnly if connectedDisable if you have no camera module attached.
I2C / SPI / SerialOnly if wiring electronicsDisable if you are not connecting GPIO components.
1-WireOff by default — leave offOnly needed for specific temperature sensors.

Step Eight: Backups as a Security Measure

Security is not only about keeping attackers out — it is also about recovering quickly if something goes wrong. A ransomware attack, a corrupted microSD card, or an accidental deletion can all destroy your work. Backups are your safety net.

We covered backups in detail in Chapter 17. The most important points to remember from a security perspective are:

  • Keep at least one backup off the Pi itself — on a USB drive, another computer, or cloud storage. A backup that lives only on the Pi is lost if the Pi is lost.
  • Test your backups occasionally. A backup you have never restored from is a backup you cannot trust.
  • Use the rpi-clone tool (Chapter 17) to clone the entire microSD card to a USB drive, so you can be up and running again in minutes if the card fails.
Tip: The rclone tool (free, open-source) can automatically copy important files from the Pi to Google Drive, OneDrive, Dropbox, or many other cloud services. Install it with: 
sudo apt install rclone -y
Downloads and installs rclone from the Raspberry Pi OS repository. After installation, run rclone config in the terminal to follow an interactive setup wizard that connects rclone to your preferred cloud service. Once configured, you can back up a folder to the cloud with a single command.

Step Nine: Physical Safety

Software security is only half the picture. The physical setup of your Pi matters too.

Use the correct power supply

The Pi 5 requires a 27 W USB-C Power Delivery supply at 5.1 V / 5 A — the one that came in your iRasptek kit. Using a lower-rated charger (for example, a phone charger rated at 5 W or 18 W) can cause instability and data corruption.

In plain words: The undervoltage warning is a lightning-bolt icon that appears in the top-right corner of the Pi's desktop when the power supply cannot keep up with demand. If you see it, stop what you are doing and switch to the correct supply — running under-voltage can corrupt the microSD card and make the Pi unusable.
Careful: If you see a yellow lightning-bolt icon in the corner of the screen, or the message "Under-voltage detected!" in the terminal, your power supply is not delivering enough power. Switch to the official 27 W USB-C supply immediately. Continuing to run under-voltage risks file system corruption.

Always shut down cleanly

Never simply pull the power cable out of the Pi while it is running. The Pi writes data to the microSD card constantly; cutting power mid-write can corrupt the file system in a way that is difficult or impossible to repair.

Always shut down using one of these methods:

  • From the desktop: click the Raspberry Pi menu → Logout → Shutdown.
  • From the terminal or SSH: 
    sudo shutdown now
    Tells the operating system to close all programs safely, write any unsaved data to the card, and then cut power. The Pi 5 has a power button — after this command completes, the green activity light will go out, and pressing the power button will then remove the remaining standby power.
  • Press the physical power button on the Pi 5 board once — this sends a clean shutdown signal (equivalent to the command above). Do not hold it down for more than a few seconds or it will force-cut power.

Protect the GPIO pins

In plain words: GPIO stands for General Purpose Input/Output — the 40 metal pins along the edge of the Pi board that let you connect physical components like LEDs, sensors, and buttons. We explore them in Chapter 18.
Careful: The GPIO pins run on 3.3 V logic, not 5 V. Connecting a 5 V signal directly to a GPIO input pin can permanently destroy the Pi. Always check the voltage requirements of any component before wiring it up. Also never short (accidentally connect) the 5 V power pins to the ground pins or to each other — this can blow a fuse or damage the board.
  • Always double-check your wiring before applying power when working with GPIO.
  • Keep the Pi away from metal surfaces and loose components that could bridge the pins.
  • Consider using a GPIO pin protector cap or keeping the board in its case (your iRasptek kit came with a case) when you are not doing electronics work.

Security Checklist

Use this checklist to confirm you have taken the most important steps. Work through it once now, and revisit it whenever you install a major new service on the Pi.

  1. Change the default password. Run passwd and set a long, unique passphrase. Store it in a password manager.
  2. Update the system. Run sudo apt update && sudo apt full-upgrade -y and repeat monthly. Optionally install unattended-upgrades.
  3. Set up SSH keys. Generate a key pair on Windows, copy the public key to the Pi, test that key login works.
  4. Optionally disable SSH password login. Set PasswordAuthentication no in /etc/ssh/sshd_config only after confirming key login works.
  5. Enable ufw. Run sudo ufw allow ssh then sudo ufw enable. Add only the ports you genuinely need.
  6. Never forward ports directly. Use Tailscale, Raspberry Pi Connect, or Cloudflare Tunnel for remote access instead.
  7. Install fail2ban. Run sudo apt install fail2ban -y and leave it running in the background.
  8. Disable unused interfaces. Run sudo raspi-config and switch off anything you are not using.
  9. Make regular backups. Keep at least one backup off the Pi. Test it. Use rpi-clone for a full card image.
  10. Use the correct power supply. 27 W USB-C PD only. If you see a lightning-bolt icon, investigate immediately.
  11. Always shut down cleanly. Use the menu, sudo shutdown now, or the power button — never yank the cable.
  12. Be GPIO-careful. Check voltages before wiring. Keep the Pi in its case when not working with electronics.
Note: You do not need to do all of these on day one. The most important three are: change the password, keep the system updated, and use SSH keys. The rest can be added gradually as you become more comfortable.

Key terms

  • passwd — the Linux command that lets you change your user account's password.
  • apt — the Raspberry Pi OS package manager, used to install, update, and remove software.
  • SSH (Secure Shell) — an encrypted protocol for remotely controlling a computer via a terminal.
  • SSH key pair — two mathematically linked files: a private key (kept on your PC) and a public key (placed on the Pi). Together they prove identity without transmitting a password.
  • Ed25519 — a modern SSH key algorithm: fast, secure, and recommended over the older RSA algorithm.
  • authorized_keys — a file on the Pi listing every public key permitted to log in via SSH.
  • sshd_config — the SSH server configuration file, located at /etc/ssh/sshd_config.
  • ufw (Uncomplicated Firewall) — a beginner-friendly firewall tool for Linux that blocks unwanted incoming connections.
  • fail2ban — a tool that automatically bans IP addresses that make too many failed login attempts.
  • Tailscale — a free service that creates a private encrypted network between your devices, making remote access safe without opening router ports.
  • raspi-config — the Raspberry Pi configuration tool used to enable or disable hardware interfaces and other system settings.
  • Undervoltage warning — a lightning-bolt icon shown when the Pi is not receiving enough power; signals a risk of data corruption.
  • GPIO — the 40-pin header on the Pi used to connect physical electronic components; runs on 3.3 V logic.
  • unattended-upgrades — a package that automatically installs security updates in the background.
  • passphrase — a password made of several words; longer than a typical password, easier to remember, and very hard for an attacker to guess.
  • Interface (in raspi-config) — a hardware or network communication channel on the Pi, such as SSH, VNC, or I2C, that can be individually switched on or off.

Chapter summary

  • Change the default password immediately and use a long, unique passphrase stored in a password manager.
  • Run sudo apt update && sudo apt full-upgrade -y monthly — or install unattended-upgrades for automatic security patches.
  • SSH key pairs replace passwords with a public/private key system: generate a pair on Windows with ssh-keygen -t ed25519, copy the public key to ~/.ssh/authorized_keys on the Pi, and optionally disable password login in sshd_config.
  • Install ufw with sudo apt install ufw -y, allow SSH before enabling, then run sudo ufw enable to block unexpected incoming connections.
  • Never open router ports to expose the Pi directly to the internet — use Tailscale (installed via the official curl script), Raspberry Pi Connect, or Cloudflare Tunnel instead.
  • Install fail2ban to automatically ban IP addresses that repeatedly fail to log in.
  • Disable hardware interfaces you are not using via sudo raspi-config to reduce the attack surface.
  • Backups are part of security: keep a copy off the Pi and test it occasionally.
  • Use the correct 27 W USB-C power supply, always shut down cleanly, and treat the 3.3 V GPIO pins with care.
  • The twelve-point security checklist in this chapter gives you a complete, actionable to-do list — the first three items are the most critical.
