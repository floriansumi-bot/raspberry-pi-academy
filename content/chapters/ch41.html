Everything you have built so far has lived inside the Pi — flashing its own LEDs, printing to its own screen. In this final project you will set it free. To do it you will pull together everything you know in Python and meet, for the first time, three new languages that run the web: HTML, CSS, and JavaScript.

Client and Server: The Big Idea

Every website works the same way, whether it is a giant social network or the tiny dashboard you are about to build. There are always two halves: a server and a client.

In plain words: The server is a program that waits for requests and sends back answers — here, it is your Pi. The client is whatever asks the questions — here, the web browser on your phone. The client sends a request ("please give me the latest sensor data"); the server sends a response ("here it is, as JSON"). That back-and-forth, over your Wi-Fi, is the whole of the web in miniature.
In plain words: JSON (JavaScript Object Notation) is a simple, universal text format for data. It looks almost exactly like a Python dictionary — {"temp_c": 21.4, "motion": true} — which is why it is the perfect bridge between your Python server and the JavaScript client. Both ends understand it instantly.

Installing Flask the Bookworm Way

Flask is the small Python library we will use to be a web server. On Raspberry Pi OS Bookworm there is a right way and a wrong way to install it, and the wrong way fails on purpose.

In plain words: Flask is a lightweight Python web framework — a toolkit for writing web servers. With a handful of lines it can serve pages and answer data requests. It is the most popular way to put a Raspberry Pi project on the web.

Why plain pip is blocked

If you simply type pip install flask on Bookworm, you will hit a wall:

error: externally-managed-environment

This is not a bug — it is a deliberate safety rule called PEP 668. Bookworm protects its system Python (which the OS itself relies on) by refusing to let pip install packages into it. If it let you, a bad package could break parts of the operating system.

In plain words: A virtual environment (venv) is a private, self-contained copy of Python that lives in a folder of your project. Anything you pip install goes only in there, never touching the system Python. It is the correct, recommended fix for PEP 668 — clean, reversible, and exactly what professionals use.

Create the project and its venv

Open a terminal and run these commands one at a time:

mkdir dashboard
cd dashboard
python3 -m venv venv

mkdir dashboard: Makes a new folder to hold the whole project.

cd dashboard: Moves into that folder, so the next commands act inside it.

python3 -m venv venv: Creates a virtual environment in a sub-folder called venv. The first venv is the tool; the second is just the folder name we chose for it.

Now activate the environment and install Flask into it:

source venv/bin/activate
pip install flask

source venv/bin/activate: Switches your terminal into the virtual environment. You will see (venv) appear at the start of your prompt — that is how you know it is active. From now on, python and pip mean the private copies inside venv.

pip install flask: Now this works perfectly, because it installs Flask inside the venv, not into the protected system Python. No PEP 668 error.

Note: You only create and install once. But every new terminal starts outside the venv, so each time you come back to work on the project you must re-run source venv/bin/activate first. To leave the venv, simply type deactivate. If you ever prefer not to use a venv at all, sudo apt install python3-flask installs a system-tested Flask instead — but the venv approach is the cleaner habit.

Reading the Sensors as a Module

Following the modular habit from Chapter 40, we will keep all the sensor-reading code in its own file, sensors.py, and the web code in app.py. That way the web server does not need to know how a reading is taken — it just asks for one.

Here is sensors.py. It uses the components from earlier chapters: an ultrasonic distance sensor and a PIR. (If you do not have the hardware to hand, the note below shows how to run the whole dashboard with fake readings so you can still build the web side.)

# sensors.py — read the hardware, return tidy values
from gpiozero import DistanceSensor, MotionSensor

# ECHO via a 330 Ω/470 Ω divider (5 V -> ~2.9 V); TRIG direct
distance = DistanceSensor(echo=24, trigger=23)
pir = MotionSensor(4)

def read_distance_cm():
    """Distance to the nearest object, in centimetres."""
    return round(distance.distance * 100, 1)

def read_motion():
    """True if motion is being detected right now."""
    return pir.motion_detected

def read_temperature_c():
    """Placeholder CPU-ish temperature. Swap for a real sensor."""
    with open("/sys/class/thermal/thermal_zone0/temp") as f:
        return round(int(f.read()) / 1000, 1)

Line 2 — imports: Brings in the two gpiozero sensor classes you have already used.

Line 5 — DistanceSensor(echo=24, trigger=23): Recreates the HC-SR04 from Chapter 38. Remember its ECHO pin outputs 5 V, so it must go through a 330 Ω/470 Ω voltage divider before reaching GPIO 24 — unlike the PIR.

Line 6 — MotionSensor(4): The PIR from Chapter 40 on GPIO 4, OUT wired directly (no divider).

Lines 8–10 — read_distance_cm(): distance.distance gives metres, so we multiply by 100 for centimetres and round to one decimal place. Wrapping it in a named function means the web server just calls read_distance_cm() and gets a clean number.

Lines 12–14 — read_motion(): Returns True or False from the PIR's motion_detected property.

Lines 16–19 — read_temperature_c(): A real, always-available reading: the Pi's own CPU temperature, read from a system file. Swap this for a real room sensor (e.g. an I2C BME280) when you have one — the rest of the dashboard will not need to change, because it only calls this function.

Note: No hardware to hand? Replace the bodies of these functions with fixed or random values, for example return round(random.uniform(20, 24), 1) (with import random at the top). The web side works identically — the whole point of the module is that the server does not care where the numbers come from.

The Shared State Dictionary

The dashboard needs to report several things at once: temperature, distance, motion, and the time of the last alarm. Rather than juggle four separate variables, we keep them together in a single dictionary — one object that is the current state of the system.

In plain words: A dictionary stores data as key: value pairs, like a labelled box of drawers. state["temp_c"] looks in the drawer labelled "temp_c". Using one dictionary as the single source of truth — a shared state object — keeps everything in one place and, conveniently, converts straight to JSON for the browser.
state = {
    "temp_c": None,
    "distance_cm": None,
    "motion": False,
    "last_alarm": "never",
}

def update_state():
    """Refresh every reading in the shared state dictionary."""
    state["temp_c"] = read_temperature_c()
    state["distance_cm"] = read_distance_cm()
    moving = read_motion()
    state["motion"] = moving
    if moving:
        state["last_alarm"] = now_stamp()
    return state

Lines 1–6 — the dictionary: Four labelled values, all starting empty or default. None means "no reading yet"; "never" is a friendly starting value for the last-alarm time.

Line 8 — def update_state():: One function that refreshes the whole dictionary by calling each sensor reader and storing the result under the right key.

Lines 13–15 — updating last_alarm: If motion is happening right now, we record the current timestamp (using a now_stamp() helper like the one from Chapter 40) under "last_alarm". So the dashboard always shows when motion was last seen.

Line 16 — return state: Hands back the whole dictionary, ready to be turned into JSON.

The Flask Server (app.py)

Now the centrepiece. This is the Python file that ties everything together and serves the web. Read the labelled block carefully — every web project you ever build will have this same shape.

# app.py  —  PYTHON (the server)
from flask import Flask, jsonify, render_template
from datetime import datetime
from gpiozero import DistanceSensor, MotionSensor

app = Flask(__name__)

distance = DistanceSensor(echo=24, trigger=23)  # ECHO via 330Ω/470Ω divider
pir = MotionSensor(4)                            # OUT direct, no divider

state = {"temp_c": None, "distance_cm": None,
         "motion": False, "last_alarm": "never"}

def now_stamp():
    return datetime.now().strftime("%H:%M:%S")

def update_state():
    with open("/sys/class/thermal/thermal_zone0/temp") as f:
        state["temp_c"] = round(int(f.read()) / 1000, 1)
    state["distance_cm"] = round(distance.distance * 100, 1)
    state["motion"] = pir.motion_detected
    if pir.motion_detected:
        state["last_alarm"] = now_stamp()
    return state

@app.route("/")
def index():
    return render_template("index.html")

@app.route("/api/data")
def data():
    return jsonify(update_state())

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

Line 2 — from flask import Flask, jsonify, render_template: Imports the three Flask tools we need: Flask (the app itself), jsonify (turn a dict into a JSON response), and render_template (serve an HTML page).

Line 6 — app = Flask(__name__): Creates the web application. __name__ is a built-in Python variable that tells Flask where the app lives, so it can find your templates folder.

Lines 8–9 — the sensors: The same objects as in our module. (For clarity we have inlined them here; you could equally from sensors import update_state to keep app.py tiny.)

Lines 16–23 — update_state(): Refreshes the shared dictionary from the live sensors each time it is called, so every request returns fresh numbers.

Line 25 — @app.route("/"): A decorator. It tells Flask: "when a browser asks for the home page (the URL /), run the function just below." The index() function returns the HTML page.

Line 27 — return render_template("index.html"): Sends the file templates/index.html to the browser. Flask automatically looks in a folder named templates.

Line 30 — @app.route("/api/data"): A second route, for data rather than a page. When the browser asks for /api/data, Flask runs data().

Line 32 — return jsonify(update_state()): Reads the sensors and returns the state dictionary as JSON — the response the JavaScript will fetch.

Line 35 — app.run(host="0.0.0.0", port=5000): Starts the server on port 5000. The crucial part is host="0.0.0.0": it means "accept connections from any device on the network", which is what lets your phone reach it. (The default of 127.0.0.1 would only allow the Pi itself.)

In plain words: A decorator (the @app.route(...) line) is a label you stick above a function to give it an extra job. Here it connects a URL to a function, so visiting that URL runs that function. You do not need to understand how decorators work internally to use them — just match a URL to the code that should answer it.
Careful: host="0.0.0.0" exposes the server to everyone on your local network. That is exactly what we want for a home dashboard, but it means anyone on your Wi-Fi can open it. Flask's built-in server is for development and home projects, not for putting on the open internet. Keep it on your home network.

The HTML Page (templates/index.html)

Now we leave Python and meet the first web language. HTML (HyperText Markup Language) describes the structure of a page: what text and boxes appear, and in what order. It is made of tags in angle brackets, usually in pairs that wrap content.

In plain words: An HTML tag like <p> opens an element and </p> closes it; together they wrap a paragraph. An id (e.g. id="temp") is a unique name for one element, so our JavaScript can find it and change its text. Think of HTML as the skeleton, CSS as the skin and clothes, and JavaScript as the muscles that make it move.

Save this as templates/index.html (create the templates folder inside your project). It contains a little CSS (in the <style> block) and a little JavaScript (in the <script> block) — each clearly labelled below.

<!DOCTYPE html> and <html>: The opening declarations of every web page. Everything lives inside <html>...</html>.

<head>: Holds information about the page that is not shown directly: the character set, the page title, and the viewport line that makes it scale nicely on a phone.

The <style> block (CSS): CSS rules style the page. Each rule names what to style (e.g. .card, meaning every element with class="card") and a set of properties in braces. <span id="temp">--</span>: An empty named slot. The id="temp" is the handle JavaScript uses to drop the real number in.

The <script> block (JavaScript): the live part — explained line by line in its own walkthrough next.

The JavaScript That Makes It Live

The HTML on its own is a still picture. JavaScript is the language that runs inside the browser and brings it to life — here, by repeatedly asking the server for fresh data and rewriting the page. Let's walk through the script block on its own.

// JavaScript (runs in the browser, on the client)
function refresh() {
  fetch("/api/data")
    .then(response => response.json())
    .then(d => {
      document.getElementById("temp").textContent = d.temp_c;
      document.getElementById("distance").textContent = d.distance_cm;
      const motionBox = document.getElementById("motion");
      motionBox.textContent = d.motion ? "DETECTED" : "clear";
      motionBox.className = d.motion ? "value alert" : "value";
      document.getElementById("last_alarm").textContent = d.last_alarm;
    });
}
setInterval(refresh, 1000);
refresh();

Line 2 — function refresh() {: Defines a JavaScript function. JavaScript and Python share the same idea of a function; only the punctuation differs — braces { } instead of indentation, and a semicolon ending most lines.

Line 3 — fetch("/api/data"): The key line. fetch() sends a request to the server's /api/data route — the very route your Flask data() function answers. This is the client asking the server its question.

Line 4 — .then(response => response.json()): The request takes a moment, so .then(...) says "once the answer arrives, do this." Here we convert the response text into a JavaScript object with .json(). The => is JavaScript's compact way of writing a small function (an "arrow function"), much like Python's lambda.

Line 5 — .then(d => {: A second step that runs once the JSON is ready, giving us the data object d — whose keys (d.temp_c, d.motion...) are exactly the dictionary keys from your Python state.

Line 6 — document.getElementById("temp").textContent = d.temp_c;: Finds the page element with id="temp" and sets its text to the temperature. This is updating the DOM — changing the live page in the browser. The DOM (Document Object Model) is the browser's editable picture of the page.

Lines 8–10 — the motion box: d.motion ? "DETECTED" : "clear" is a compact if/else: if motion is true, show "DETECTED", otherwise "clear". We also swap the CSS class to alert so the text turns red when motion is detected.

Line 14 — setInterval(refresh, 1000);: Tells the browser to run refresh every 1000 milliseconds (one second), forever. This polling is what keeps the dashboard live.

Line 15 — refresh();: Calls it once straight away so the page is not blank for the first second.

In plain words: Polling means asking again and again on a timer ("any new data? any new data?"). It is the simplest way to keep a page fresh. Big apps sometimes use fancier "push" methods, but for a home dashboard, polling once a second with setInterval is perfect and easy to understand.

Running It and Viewing on Your Phone

Your project folder should now look like this:

dashboard/
├── venv/
├── app.py
└── templates/
    └── index.html
  1. Activate the venv (if you opened a fresh terminal): cd dashboard then source venv/bin/activate. You should see (venv) in the prompt.
  2. Start the server: run python app.py. Flask prints a couple of lines, including Running on http://0.0.0.0:5000. Leave this terminal open — closing it stops the server.
  3. Test on the Pi first. On the Pi's own browser, visit http://localhost:5000. The dashboard should appear and start updating.
  4. Find the Pi's address. In another terminal run hostname -I to see the Pi's IP address (something like 192.168.1.42).

  7. Stop the server with Ctrl+C in the terminal when you are done.
hostname -I

hostname -I: Prints your Pi's IP address(es) on the network — the number your phone needs in the URL. The capital -I shows all addresses; usually the first one is the Wi-Fi address you want.

Tip: raspberrypi.local:5000 works thanks to a system called mDNS, which lets devices find each other by name on a home network. If your Pi has a custom hostname, use that name instead. If .local does not resolve on your phone, fall back to the numeric IP from hostname -I.

Troubleshooting

SymptomLikely cause & fix
error: externally-managed-environment on pip installYou are not in the venv. Run source venv/bin/activate (look for (venv)), or use sudo apt install python3-flask.
ModuleNotFoundError: No module named 'flask'The venv is not active, or Flask was installed into a different one. Activate the venv, then pip install flask.

Motors and robotics

The natural next step in electronics is movement. A GPIO pin cannot drive a motor directly — motors pull far more current than a pin can give, and their coils kick back voltage spikes that would destroy it. The bridge is a chip called an H-bridge (such as the L298N or DRV8833).

In plain words: An H-bridge is a small driver board that sits between your Pi and a motor. The Pi sends gentle 3.3 V control signals; the H-bridge switches the motor's larger current on your behalf, and can even reverse it so the motor spins both ways. gpiozero has a Motor class built for exactly this. Add wheels and you have a robot.

Learn more languages

You have now touched five languages in this course — Python, Bash, HTML, CSS, and JavaScript. Each opens a door:

Key terms

  • Server - A program that waits for requests and sends back responses; here, Flask running on the Pi.
  • Client - The program that makes requests; here, the web browser on your phone.
  • Request / response - The client asks (request); the server answers (response). The basic exchange of the web.
  • Flask - A lightweight Python web framework used to build the server with a few lines of code.
  • PEP 668 - The Bookworm rule that blocks plain pip install into the system Python; the fix is a virtual environment (or sudo apt install).
  • Virtual environment (venv) - A private copy of Python in a project folder where pip packages install safely, isolated from the system.
  • Route / decorator - @app.route("/api/data") connects a URL to the function that answers it.
  • JSON - A universal text format for data that looks like a Python dictionary; the bridge between Python and JavaScript. Produced with jsonify.
  • Shared state dictionary - A single Python dict holding all current readings, used as the system's single source of truth.
  • HTML - The markup language describing a page's structure, made of tags and elements with optional ids.
  • CSS - The language for styling a page: colours, fonts, layout, in rules like .card { ... }.
  • JavaScript - The language that runs in the browser to make pages interactive.
  • fetch() - The JavaScript call that requests data from a server URL.
  • DOM - Document Object Model; the browser's live, editable model of the page that JavaScript updates.
  • Polling - Asking the server for fresh data repeatedly on a timer (here, setInterval every second).
  • H-bridge - A motor-driver board that lets the Pi control a motor's larger current and reverse its direction.

Chapter summary

  • The web is a conversation between a client (your phone's browser) and a server (Flask on the Pi): the client sends requests, the server sends responses.
  • On Bookworm, install Flask inside a virtual environment (python3 -m venv venv then source venv/bin/activate then pip install flask) because PEP 668 blocks plain pip into the system Python.
  • A single dictionary used as a shared state object holds every reading and converts directly to JSON with jsonify.
  • @app.route decorators map URLs to functions: / serves the HTML page via render_template; /api/data returns the readings as JSON.
  • app.run(host="0.0.0.0", port=5000) exposes the server to the local network so a phone on the same Wi-Fi can reach it at http://<pi-ip>:5000 or raspberrypi.local:5000.
  • HTML structures the page, CSS styles it, and JavaScript makes it live — three separate languages working together in the browser (the client).
  • JavaScript's fetch("/api/data") requests JSON, and setInterval(refresh, 1000) polls every second, updating the page (the DOM) with the latest readings.
  • Reused sensors keep their wiring rules: the HC-SR04 ECHO still needs its 330 Ω/470 Ω divider, while the PIR's OUT still connects directly.
