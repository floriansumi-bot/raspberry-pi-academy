Your Raspberry Pi comes with a lot of software already installed, but sooner or later you will want to add something new — a media player, a game, a useful tool. This chapter shows you exactly how to do that safely and confidently, explains what is happening behind the scenes, and builds the habit of keeping everything up to date so your Pi stays secure and running smoothly.

How Software Gets Onto the Pi

On Windows you usually visit a website, download a .exe file, and run it. On Raspberry Pi OS things work differently — and, once you get used to it, much more conveniently. Almost every program you will ever want is available from a central, trusted collection managed by the operating system itself. You do not need to hunt around the web.

In plain words: A package is a ready-to-install bundle containing a program (or a library the program needs), plus instructions telling the system where to put all its files. Think of it like a flat-pack furniture box: everything is inside, and the assembly instructions are included.
In plain words: A repository (often shortened to "repo") is an enormous, carefully organised online library of packages — a bit like an official app store, except it is run by the people who make your operating system, not a private company. Raspberry Pi OS uses the Debian repositories plus a few Raspberry Pi-specific ones. Every package in there has been tested and is known to work safely together.
In plain words: A package manager is the program that talks to the repository for you. You tell it what you want; it fetches the right package (and any other packages that program depends on), checks that nothing is broken, and installs everything in the right order. The package manager on Raspberry Pi OS is called APT (Advanced Package Tool).

The Terminal: Where You Type Commands

Most software-management tasks are done by typing short commands in the Terminal — a text window where you talk directly to the operating system. Open it by clicking the black screen icon in the taskbar at the top of the desktop. Do not be put off by the plain look; each command is short, and this chapter explains every one.

In plain words: The Terminal (also called the command line or shell) is like a chat window with your Pi. You type an instruction, press Enter, and the Pi carries it out and replies. It feels different from clicking around a graphical interface, but for managing software it is faster and more reliable.

The APT Command — Your Swiss Army Knife

Every APT command that changes something on the system starts with sudo.

In plain words: sudo stands for "superuser do". It temporarily grants you administrator-level power for just the one command that follows. The system will ask for your password the first time you use it in a session. Without sudo, APT cannot write files to protected system folders — which is exactly what installing software requires.
Note: When you type your password after sudo, the cursor does not move and no dots or asterisks appear. This is normal — the password is being recorded silently for security. Type it and press Enter.

Step 1 — Refresh the catalogue: sudo apt update

Before you install or upgrade anything, always tell APT to check the repositories for the latest list of available packages. This does not install anything; it only updates APT's local "catalogue" so it knows what versions are currently available.

sudo apt update
sudo — run the following command as administrator.
apt update — contact every repository listed in your configuration, download the current package lists, and store them locally. You will see lines scrolling by as APT contacts each server. This usually completes in under a minute.

You should run sudo apt update every time before installing or upgrading, and ideally at least once a week.

Step 2 — Install available upgrades: sudo apt full-upgrade

After refreshing the catalogue, you can apply any newer versions of packages that are already installed.

sudo apt full-upgrade
apt full-upgrade — compares what is installed against the freshly downloaded catalogue. If newer versions exist, it downloads and installs them. Unlike the simpler apt upgrade, full-upgrade is also allowed to remove old packages that are blocking an update — which is sometimes necessary on Raspberry Pi OS. You will be shown a summary and asked to confirm with Y then Enter before anything is changed.
Tip: You can chain both commands into one line so you never forget to update first:
sudo apt update && sudo apt full-upgrade
sudo apt update — refreshes the package catalogue.
&& — means "run the next command only if the previous one succeeded without errors".
sudo apt full-upgrade — installs all available updates. The two commands run one after the other automatically, so you only need to confirm once at the end.
Note: A full upgrade can take several minutes if many packages need updating — especially the first time after a fresh install. Leave the Terminal open and let it finish.

Installing a new package: sudo apt install

sudo apt install <package-name>
Replace <package-name> with the actual name of the package you want. APT will look it up in the catalogue, list everything it needs to download (including any dependencies — other packages the program relies on), and ask you to confirm. Press Y then Enter to proceed.

You can install several packages at once by listing their names separated by spaces:

sudo apt install vlc fastfetch
Installs both vlc (the VLC media player) and fastfetch (a tool that displays a summary of your system) in a single operation. APT fetches both together and asks for one confirmation.

Removing a package: sudo apt remove and sudo apt purge

There are two levels of removal:

Command What it removes Configuration files?
sudo apt remove <name> The program itself Left behind — useful if you reinstall later
sudo apt purge <name> The program and all its configuration files Deleted — a completely clean slate

Use remove if you think you might want the program back one day. Use purge for a truly clean removal — for example, if you had configured a server wrongly and want to start fresh.

sudo apt remove fastfetch
Removes the fastfetch program but keeps any settings files it created, so your configuration is preserved if you reinstall it later. 
sudo apt purge fastfetch
Removes fastfetch and deletes its configuration files completely. Use this when you want a clean slate and are sure you will not reinstall the package.

Searching for a package: apt search

If you are not sure of the exact package name, you can search the catalogue. This command does not need sudo because it only reads information — it does not change anything.

apt search chess
Searches all package names and descriptions for the word "chess" and lists every match. You can then pick the exact name you want and use apt install with it.
Tip: The list can be very long. Pipe it through less so you can scroll one page at a time: apt search chess | less — press the spacebar to move forward a page and q to quit back to the prompt.

Learning about a package before installing: apt show

apt show vlc
Displays detailed information about the vlc package: its version number, download size, a plain description, what other packages it depends on, and who maintains it. Useful for checking you have the right package before committing to an install. No sudo needed — this only reads information.

Checking the installed version of a package: dpkg -l

Once a package is installed, you can check exactly which version is on your system:

dpkg -l vlc
dpkg is the lower-level tool that APT sits on top of. You will sometimes see it mentioned in error messages, so it is good to know its name.
-l vlc — list the status and installed version of the vlc package. A line beginning with ii means the package is correctly installed. This command needs no sudo.

Cleaning up afterwards: sudo apt autoremove and sudo apt clean

Over time, APT can accumulate packages that were only installed to support something else (called dependencies) but are no longer needed after you removed the main program. It also keeps downloaded package files in a cache folder even after installation.

sudo apt autoremove
Automatically finds and removes packages that were installed as dependencies but are no longer needed by any remaining program. APT will show you exactly what it plans to delete and ask for confirmation before removing anything. Safe to run regularly. 
sudo apt clean
Deletes the downloaded .deb package files from the local cache (stored in /var/cache/apt/archives/). The packages are already installed, so the cached files are just consuming space on your microSD card. This command reclaims that space. It does not remove any installed programs.
Tip: Run this full sequence once a month to keep your Pi tidy and up to date:
sudo apt update && sudo apt full-upgrade && sudo apt autoremove && sudo apt clean
sudo apt update — refresh the package catalogue.
sudo apt full-upgrade — install all available updates.
sudo apt autoremove — remove dependency packages no longer needed.
sudo apt clean — delete cached installer files to free up disk space.
Each step only runs if the previous one completed successfully (thanks to &&). You will be asked to confirm upgrades and autoremove before they proceed.

Three Concrete Examples

Reading about commands is one thing — seeing them applied to real programs makes everything click. Here are three installs you can try right now.

Example 1 — Fastfetch (a system information display)

Fastfetch prints a colourful summary of your Pi's hardware and software — processor model, RAM, operating system version, uptime, and more. It is a satisfying first install because the result appears immediately.

sudo apt update
sudo apt install fastfetch
fastfetch
Line 1: Refresh the package catalogue so APT knows the latest version is available.
Line 2: Download and install fastfetch. APT will list the package and ask you to confirm with Y then Enter.
Line 3: Run fastfetch. No sudo is needed to run a program — only to install it.

You should see a Raspberry Pi logo made of coloured characters on the left, and columns of information on the right. Any time you open a new Terminal session you can type fastfetch to see that summary instantly.

Example 2 — Ninvaders (a text-based Space Invaders game)

The repository contains several classic text games. ninvaders is a Space Invaders clone that runs entirely in the Terminal window — no extra graphics needed.

sudo apt install ninvaders
ninvaders
Line 1: Installs the ninvaders package. If you have already run sudo apt update in this session, you do not need to run it again before every install.
Line 2: Launches the game. Use the left and right arrow keys to move your ship and the spacebar to fire. Press q to quit.

Example 3 — VLC Media Player

VLC is one of the most popular media players in the world. It plays almost any video or audio format, including streamed internet content.

sudo apt install vlc
Installs VLC and all the supporting libraries (called codecs — small programs that decode different audio and video formats) that it needs. This may take a couple of minutes because there are quite a few dependencies. After installation, VLC appears in the Sound & Video section of the application menu (click the raspberry icon at the top-left of the desktop).
Note: The Raspberry Pi 5 has no headphone socket. Audio from VLC comes out through your HDMI-connected monitor or TV's built-in speakers. If your monitor has no speakers, you can connect a USB audio adapter or USB speaker instead.

The Graphical Alternative: Add / Remove Software

If you prefer not to use the Terminal for installing software, Raspberry Pi OS includes a graphical application called Add / Remove Software. You can find it in the application menu under Preferences.

  1. Click the raspberry icon at the top-left of the desktop to open the application menu.
  2. Go to Preferences and click Add / Remove Software.
  3. Use the search box at the top to type the name or description of what you want.
  4. Click the checkbox next to a result to select it, then click Apply.
  5. Enter your password when prompted and wait for the installation to finish.
Note: The graphical tool is a front-end for APT — it does exactly the same thing under the hood. Many people prefer it when starting out. Either method is perfectly fine and results in the same installed software.

Keeping the Pi's Firmware Up to Date

As well as software packages, the Raspberry Pi has a piece of low-level software called the bootloader (sometimes called firmware). This tiny program is stored in a special chip on the board and is what runs the instant you press the power button — even before the operating system loads. The Raspberry Pi Foundation occasionally releases bootloader updates to improve stability, add features, or fix bugs.

In plain words: EEPROM stands for Electrically Erasable Programmable Read-Only Memory. It is a small chip on the Pi 5 board that stores the bootloader permanently, even when the power is off. Think of it as the Pi's ignition system — it fires up first and hands control over to the operating system.

First, check whether a newer bootloader version is available:

sudo apt update
sudo apt install rpi-eeprom
sudo rpi-eeprom-update
Line 1: Refresh the package catalogue.
Line 2: Make sure the EEPROM update tool is installed. On a fresh Bookworm installation it is usually already present; APT will simply confirm it is at the latest version.
Line 3: Check whether a newer bootloader is available. If everything is current, the output will include BOOTLOADER: up to date and you are done. If an update is available, the output will tell you.

If an update is available, apply it with:

sudo rpi-eeprom-update -a
sudo reboot
sudo rpi-eeprom-update -a — schedules the bootloader update to be applied on the next reboot. The -a flag means "apply". Nothing is changed until the Pi actually reboots.
sudo reboot — restarts the Pi. During the reboot you may briefly see a green screen or a progress display as the new bootloader is written to the EEPROM chip. This is completely normal.
Tip: Check the bootloader every few months. You do not need to do it every week — bootloader updates are infrequent.
Careful: Do not press the power button or cut the power while the Pi is rebooting after an EEPROM update. Wait until the desktop (or login prompt) appears before touching anything. Interrupting a bootloader write is extremely rare to cause permanent damage, but it is best avoided.

When the App You Want Is Not in APT

The Debian / Raspberry Pi repositories are very large — there are over 60,000 packages. But occasionally the program you want is not there, or only an outdated version is available. In that situation you have a few options.

Option 1 — Flatpak

In plain words: Flatpak is a newer packaging system — think of it as a second, parallel app store. Each Flatpak package bundles everything the program needs inside itself, so it works independently of what APT has installed. The main Flatpak hub is called Flathub, and it hosts thousands of applications.

To set up Flatpak on Raspberry Pi OS Bookworm:

sudo apt install flatpak
sudo flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
sudo reboot
Line 1: Install the Flatpak system itself via APT.
Line 2: Register Flathub (the main Flatpak app library) as a trusted source. The --if-not-exists flag prevents an error if you have already done this step before.
Line 3: Reboot the Pi so the Flatpak integration is picked up correctly by the desktop environment.

After rebooting, you can install a Flatpak app like this (using the GIMP image editor as an example):

flatpak install flathub org.gimp.GIMP
flatpak install flathub — download from the Flathub source.
org.gimp.GIMP — the Flatpak application ID for GIMP. Flatpak uses reverse-domain IDs (like org.gimp.GIMP) instead of short names to avoid conflicts between publishers. You can find an app's exact ID by searching on flathub.org.

To run a Flatpak app from the Terminal:

flatpak run org.gimp.GIMP
flatpak run — launch the specified Flatpak application. Flatpak apps also appear in the application menu after installation, so you can just click their icon there instead.
Note: Flatpak packages are larger than APT packages because they bundle their own dependencies. On a 64 GB or larger microSD card this is not usually a problem, but be aware that a single Flatpak app can take several hundred megabytes.

Option 2 — AppImage

In plain words: An AppImage is a single portable file that contains an entire application. You download the file, mark it as runnable, and double-click it — no installation needed, and no administrator password required. You can delete it simply by dragging it to the bin.

To use an AppImage:

  1. Download the .AppImage file from the developer's official website and save it to your Downloads folder.
  2. Open a Terminal and move into your Downloads folder:
cd ~/Downloads
cd — "change directory", i.e. move to a different folder.
~/Downloads — the ~ symbol is a shortcut for your home folder (/home/pi by default). So this moves you into /home/pi/Downloads.
  1. Make the file executable (runnable) and launch it:
chmod +x MyApp.AppImage
./MyApp.AppImage
chmod +x — changes the file's permissions to mark it as executable. You only need to do this once per file. Replace MyApp.AppImage with the actual filename you downloaded.
./MyApp.AppImage — runs the application. The ./ at the start means "look for this file in the current folder" (not somewhere else on the system).
Careful: AppImages and software downloaded directly from websites bypass the safety checks that APT and Flatpak provide. Only download AppImages from the official website of the software you want. If you are not sure whether a source is trustworthy, do not run the file until you have verified it.

Option 3 — A Project's Own Install Script

Some projects — particularly developer tools — provide their own installation script, usually a command beginning with curl or wget that you paste into the Terminal. These are common and generally safe when they come from a well-known project's official documentation, but they run with administrator privileges. Always copy the command from the official project page rather than from a random forum post or social-media message.

Python Software in Particular

Python deserves a special mention. Raspberry Pi OS Bookworm marks the system Python as externally managed, which means running plain pip install directly will show an error. This is intentional — it protects the operating system's own tools from accidental breakage.

In plain words: pip is Python's own package manager — it installs Python libraries (add-on collections of code written in Python). On Bookworm, running pip install directly into the system-wide Python is blocked, because the OS itself relies on certain Python packages being at specific versions.

Instead, choose one of these safe approaches:

Approach Best for How
Thonny's package manager Beginners; installing libraries for use in Thonny In Thonny: Tools > Manage packages
APT python3-* packages Popular libraries available system-wide sudo apt install python3-numpy (for example)
Virtual environment Projects that need specific library versions python3 -m venv myenv then source myenv/bin/activate

Using APT for Python libraries

sudo apt install python3-numpy python3-matplotlib
Installs the NumPy maths library and the Matplotlib plotting library via APT. These are available system-wide to all Python scripts, without needing pip or a virtual environment. Many popular libraries have an apt package named python3-<libraryname>.

Using a virtual environment

A virtual environment is an isolated copy of Python that belongs to one project. You install packages into it freely with pip, and it never touches the system Python.

python3 -m venv myenv
source myenv/bin/activate
pip install requests
deactivate
python3 -m venv myenv — create a new virtual environment in a folder called myenv. You only do this once per project.
source myenv/bin/activate — switch into the virtual environment. Your Terminal prompt will change to show (myenv) at the start, confirming it is active. Any pip install now goes into myenv, not the system Python.
pip install requests — as an example, installs the popular requests HTTP library into the virtual environment only.
deactivate — leave the virtual environment and return to normal. The libraries you installed stay inside myenv for next time.
Tip: To re-enter the virtual environment in a future session, just run source myenv/bin/activate again from the same folder. You do not need to recreate it.
Note: If you are just starting out with Python, use Thonny. It manages its own private environment behind the scenes, so you can install libraries through its menu (Tools > Manage packages) without any of the above complexity. Come back to virtual environments when you are more comfortable.

Enabling System Features with raspi-config

Some software — particularly programs that talk to physical hardware like sensors, displays, or cameras — requires certain features of the Pi to be switched on before they will work. The tool for this is raspi-config.

In plain words: raspi-config is a configuration menu that you open in the Terminal. It lets you turn on or off built-in features of the Pi — for example, the camera, SSH remote access, SPI and I2C communication buses for electronics, and more. Think of it as the Pi's "System Settings" for things that cannot easily be changed from the graphical desktop.
sudo raspi-config
Opens the raspi-config text menu. Use the arrow keys to highlight an option and Enter to select it. Navigate to Interface Options to enable features like the camera, SSH, SPI, or I2C. Navigate to System Options to change the hostname or password. Press Tab to reach the Finish button, then reboot if prompted.
Note: You will rarely need raspi-config as a beginner. It becomes important when you start connecting physical components to the GPIO pins (covered in a later chapter), or when you want to access the Pi remotely from another computer.

Building the Update Habit

Keeping your Pi's software up to date is one of the most important things you can do for security and stability. Updates fix bugs, patch security holes, and sometimes add new features. Think of it like antivirus updates on Windows — routine maintenance that protects you without requiring you to understand all the details.

A simple, sensible routine:

  1. Once a week (or any time before you do important work), open a Terminal and run:
    sudo apt update && sudo apt full-upgrade
  2. Once a month, add the clean-up steps:
    sudo apt autoremove && sudo apt clean
  3. Every few months, check the bootloader:
    sudo rpi-eeprom-update
Tip: The taskbar sometimes shows a small software-update icon (a circle with an arrow). Clicking it runs the equivalent of apt update and offers to apply upgrades without you typing anything — useful on days when you do not want to open the Terminal.
Careful: If an upgrade summary shows it will remove a package you deliberately installed and care about, read the list carefully before typing Y to confirm. This is rare, but it is worth a quick check. If you are unsure, type N to cancel and search online for why that package is being removed.

Key terms

  • Package — a bundle containing a program (or library) and instructions for installing it on your system.
  • Repository (repo) — a large, trusted online library of packages, maintained by the OS team.
  • APT — the package manager built into Raspberry Pi OS; the tool that installs, updates, and removes packages.
  • sudo — a command prefix that grants temporary administrator privileges for a single command.
  • Dependency — a package that another package requires in order to work; APT installs these automatically.
  • apt update — refreshes APT's local catalogue of available packages (does not install anything).
  • apt full-upgrade — installs all available updates for packages already on your system.
  • apt autoremove — removes dependency packages no longer needed by any installed program.
  • apt clean — deletes cached downloaded package files from /var/cache/apt/archives/ to free disk space.
  • dpkg — the lower-level tool APT sits on top of; use dpkg -l <name> to check an installed package's version.
  • EEPROM / bootloader — the low-level firmware in a tiny chip on the Pi 5 board; it runs before the OS and can be updated with rpi-eeprom-update.
  • Flatpak / Flathub — an alternative packaging system (Flatpak) and its main app library (Flathub); apps bundle their own dependencies.
  • AppImage — a portable single-file application that needs no installation; download, mark executable, and run.
  • pip — Python's own package manager; on Bookworm, use it only inside a virtual environment or via Thonny, not directly into the system Python.
  • Virtual environment — an isolated Python workspace created with python3 -m venv, letting you use pip freely without affecting the system Python.
  • raspi-config — a Terminal menu tool for enabling Pi hardware features such as SSH, SPI, I2C, and the camera interface.

Chapter summary

  • Raspberry Pi OS uses APT to install software from trusted online repositories — no need to download files from random websites.
  • Always run sudo apt update before installing or upgrading to ensure APT has the latest package information.
  • sudo apt full-upgrade installs all pending updates; run it weekly to keep the system secure and stable.
  • sudo apt install <name> installs a package; sudo apt remove uninstalls it (or purge for a completely clean removal including config files).
  • Use apt search to find packages by keyword, apt show to read details before installing, and dpkg -l to check what is already installed.
  • sudo apt autoremove and sudo apt clean keep your microSD card tidy by removing unneeded files monthly.
  • The graphical Add / Remove Software tool does the same job as APT commands but with a point-and-click interface — equally valid for beginners.
  • The Pi 5's bootloader firmware can be updated with sudo rpi-eeprom-update -a followed by a reboot; check it every few months.
  • Software not in APT can come from Flatpak (Flathub), AppImage files, or a project's own install script — always use the official source.
  • For Python libraries, use Thonny's built-in package manager, an APT python3-* package, or a virtual environment — never plain pip install into the system Python on Bookworm.
  • Use sudo raspi-config to enable hardware interfaces (camera, SSH, SPI, I2C) that some software requires before it will work.
