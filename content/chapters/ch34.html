A real set of traffic lights is just three lamps switched on and off in a fixed order — and that is exactly the kind of thing a Raspberry Pi is brilliant at. In this project you will wire up a red, an amber and a green LED, then teach your Pi to run a proper UK traffic-light sequence in an endless loop. Along the way you will learn four Python fundamentals you will use forever — lists, for loops, functions and time.sleep() for timing — and the electronics idea of driving several outputs at once while staying inside the Pi's current budget.

What You'll Build & Learn

By the end of this chapter you will have a working model traffic light that cycles forever, and then a smarter version that waits for a pedestrian to press a button before changing. More importantly, you will have met the building blocks that nearly every program is made from.

The Python fundamentals

  • Lists — a single name that holds several things in order, like [red, amber, green]. Instead of three separate variables, you keep your three LEDs together in one tidy container.
  • The for loop — a way to repeat an action once for every item in a list, without copying and pasting the same line three times.
  • Functions — named, reusable blocks of code (with parameters you can pass in) so you can write a step once and call it as often as you like.
  • time.sleep() and sequencing — pausing the program for a set number of seconds so each light stays on long enough to see, in the right order.

The electronics fundamentals

  • Driving multiple outputs — controlling three LEDs from three separate GPIO pins at the same time.
  • One resistor per LED — every LED gets its own 330 Ω current-limiting resistor; you never share one resistor between several LEDs.
  • The current budget — each GPIO pin can safely supply only about 16 mA, and the whole header together should stay under roughly 50 mA. Three well-behaved LEDs fit comfortably; we will do the sums so you can see why.
Note: This chapter assumes you have met the GPIO header, breadboards and the single-LED blink circuit from earlier in the course. If the words "GPIO 17 means physical pin 11" are new to you, it is worth a quick look back before continuing. Everything else we will build up gently from there.

Parts List

You can find every one of these in a basic Raspberry Pi starter kit, or salvage the LEDs and resistors from old electronics (see the "From the e-waste pile" box later).

  • A Raspberry Pi 5, set up and running Raspberry Pi OS Bookworm.
  • 3 × LEDs — ideally one red, one amber/yellow and one green, but any three colours work.
  • 3 × 330 Ω resistors — colour bands orange-orange-brown-gold. One per LED, no exceptions.
  • A half-size or mini breadboard.
  • 4 × female-to-male jumper wires — three for the GPIO signals, one for the shared ground.
  • (For the pedestrian variant only) 1 × push button and 1 more jumper wire.
In plain words: a female-to-male jumper wire has a little socket on one end (the "female" end, which slides over a GPIO pin) and a stiff pin on the other (the "male" end, which pushes into a breadboard hole).

The Current Budget: Why Three LEDs Is Fine

Before we wire anything, let us understand the single most important safety idea in this chapter. The GPIO pins are wonderful, but they are delicate. They can only push a small amount of electrical current before they overheat and fail.

In plain words: current is how much electricity flows per second, measured in milliamps (mA). Think of voltage as water pressure and current as the actual amount of water moving through the pipe. Too much current through a thin wire — or a GPIO pin — makes it overheat.

Two limits matter on the Pi 5:

  • Per pin: keep each GPIO pin under about 16 mA.
  • Whole header: keep the total drawn from all the 3.3 V pins combined under about 50 mA.

How much does one LED with a 330 Ω resistor actually draw? We can work it out with Ohm's Law (current = voltage ÷ resistance). A standard LED "uses up" about 2 V, leaving 3.3 − 2 = 1.3 V across the resistor. So:

1.3 V ÷ 330 Ω ≈ 0.0039 A ≈ 4 mA per LED

Four milliamps is well under the 16 mA per-pin limit, so each pin is happy. Three LEDs together draw about 3 × 4 = 12 mA — comfortably under the 50 mA whole-header limit. This is exactly why we can light three LEDs straight from the Pi, and exactly why each LED still needs its own resistor: that resistor is what keeps the current down to those safe few milliamps.

Careful: if you removed the resistors and connected the LEDs straight to 3.3 V, each would try to pull far more than 16 mA. The LED could burn out, and the GPIO pin behind it could be destroyed — permanently, with no fuse to save it. One 330 Ω resistor per LED, always. Never share a single resistor between two LEDs either: each LED needs its own, or they will rob current from one another and behave unpredictably.

The Circuit: Common-Cathode Layout

All three LEDs share one thing: the ground (GND) connection. The long leg (anode, +) of each LED connects through its own resistor to its own GPIO pin. The short leg (cathode, −) of every LED connects to a shared ground rail, which runs back to a single GND pin on the Pi. Because all the cathodes meet at a common point, this is called a common-cathode layout.

In plain words: common-cathode just means "all the negative legs join together." It saves wires — you only need one ground wire back to the Pi instead of three.

We will use these three GPIO pins (the BCM/GPIO numbers your code uses, with the physical header position in brackets):

LEDGPIO (BCM)Physical pin
RedGPIO 25Pin 22
AmberGPIO 8Pin 24
GreenGPIO 7Pin 26
Careful: power off and unplug your Pi before doing any wiring. Shut down from the menu (Raspberry Pi menu > Shutdown), wait for the green activity light to go out, then pull the power lead. Remember the Pi 5 GPIO is 3.3 V logic only — never feed 5 V into a GPIO pin. Fit one 330 Ω resistor per LED, and double-check every wire before you plug the power back in.

Step-by-step wiring

  1. Power off. Shut the Pi down fully and unplug it before touching any wires.
  2. Place the three LEDs. Push each LED into the breadboard so its two legs land in different numbered rows. Keep the long legs (anodes) all on one side and the short legs (cathodes) all on the other side of the centre gap.
  3. Fit one resistor per LED. For each LED, push a 330 Ω resistor so one leg shares the row with that LED's long leg, and the other leg sits in a free row where a GPIO wire can reach it.
  4. Run the three GPIO wires. Connect GPIO 25 (pin 22) to the red LED's resistor, GPIO 8 (pin 24) to the amber resistor, and GPIO 7 (pin 26) to the green resistor.
  5. Build the ground rail. Connect all three LED short legs (cathodes) to the breadboard's blue − rail. Then run one jumper wire from the − rail back to a GND pin (pin 20) on the Pi.
  6. Check LED direction. Long leg toward the resistor/GPIO side; short leg toward ground. A backwards LED simply will not light — no harm done, just turn it around.
  7. Reconnect power only once every wire is checked, then boot to the desktop.

Fundamental 1: Meet the List

Before the full program, let us learn each fundamental on its own with a tiny example. Open Thonny and try these in the editor.

A list is one name that holds several values in order, written inside square brackets and separated by commas. Here is a list of three LED objects:

from gpiozero import LED

red = LED(25)
amber = LED(8)
green = LED(7)

lights = [red, amber, green]

Lines 3–5 — red = LED(25) etc.: create three separate LED objects, one per GPIO pin. Each variable controls one physical LED.

Line 7 — lights = [red, amber, green]: bundles all three into a single list called lights. The square brackets make it a list; the order is remembered, so lights[0] is the red one, lights[1] is amber, and lights[2] is green. (Lists count from zero — that catches everyone out at first.)

In plain words: a list is like an egg box. The box has one name, but holds several eggs in numbered slots. You can reach into slot 0, slot 1, slot 2, and so on.

Fundamental 2: The for Loop

Now that the LEDs live in a list, a for loop lets us do the same thing to every one of them without repeating ourselves. Try this:

from gpiozero import LED
from time import sleep

lights = [LED(25), LED(8), LED(7)]

for light in lights:
    light.on()
    sleep(0.5)
    light.off()

Line 4 — lights = [LED(25), LED(8), LED(7)]: creates the three LEDs straight inside the list — no need for separate variables if we do not want them.

Line 6 — for light in lights:: this is the loop. It runs the indented block once for each item in lights. On the first pass, light means the red LED; on the second, amber; on the third, green. light is just a temporary name we chose for "the current item."

Lines 7–9 — light.on() / sleep(0.5) / light.off(): switch the current LED on, wait half a second, then switch it off. Because the loop repeats, you see each LED flash in turn — a chase effect — from one short block of code.

Tip: the indentation (the spaces at the start of lines 7–9) is what tells Python which lines belong inside the loop. Thonny adds it automatically when you end a line with a colon. Keep it consistent — four spaces is the Python convention.

Fundamental 3: Functions with Parameters

A function is a named block of code you can run whenever you like, just by calling its name. A function can take parameters — values you hand in each time — so the same function can do slightly different jobs. Here is a function that turns exactly one light on and the others off:

from gpiozero import LED
from time import sleep

red = LED(25)
amber = LED(8)
green = LED(7)
lights = [red, amber, green]

def show(on_light, seconds):
    for light in lights:
        light.off()
    on_light.on()
    sleep(seconds)

show(green, 3)
show(amber, 1)
show(red, 3)

Line 9 — def show(on_light, seconds):: def starts a function definition. We name it show and give it two parameters: on_light (which LED to light) and seconds (how long to wait). These are placeholders filled in each time we call the function.

Lines 10–11 — for light in lights: light.off(): a small for loop that switches all the LEDs off first, so we always start from a clean state.

Line 12 — on_light.on(): switches on just the LED that was passed in.

Line 13 — sleep(seconds): pauses for the number of seconds passed in, holding that light on.

Lines 15–17 — show(green, 3) etc.: call the function three times with different arguments. Green for 3 seconds, amber for 1, red for 3. Writing the logic once and calling it three times is the whole point of a function.

In plain words: a function is a recipe with blanks to fill in. show is the recipe; on_light and seconds are the blanks (parameters); show(green, 3) fills them in (those are the arguments) and runs the recipe.

The UK Traffic-Light Sequence

UK traffic lights follow a very specific four-phase cycle. The one phase people forget is the red-and-amber together step, which warns drivers that green is coming so they can get ready to move.

PhaseLights onMeaning
1RedStop
2Red + AmberStop, but get ready — green is next
3GreenGo (if the way is clear)
4AmberPrepare to stop

The Full Program

Now we put the fundamentals together. Open a new file in Thonny, type this in, and save it as traffic.py.

from gpiozero import LED
from time import sleep

# One LED object per pin, kept together in a list
red = LED(25)
amber = LED(8)
green = LED(7)
all_lights = [red, amber, green]

def all_off():
    for light in all_lights:
        light.off()

def phase(reds, ambers, greens, seconds):
    all_off()
    if reds:
        red.on()
    if ambers:
        amber.on()
    if greens:
        green.on()
    sleep(seconds)

print("Traffic lights running. Press Stop to quit.")
while True:
    phase(True,  False, False, 4)   # Red: stop
    phase(True,  True,  False, 1)   # Red + Amber: get ready
    phase(False, False, True,  4)   # Green: go
    phase(False, True,  False, 1)   # Amber: slow down

Lines 1–2: import LED from gpiozero and sleep from the built-in time module so we can pause between phases.

Lines 5–8: create the three LEDs and store them in the list all_lights — our list fundamental in action.

Lines 10–12 — def all_off():: a small function that loops over the list (a for loop) and switches every LED off. Calling all_off() is now a one-word way to reset everything.

Line 14 — def phase(reds, ambers, greens, seconds):: the heart of the program. Four parameters say which lights should be on (each is True or False) and for how long.

Line 15 — all_off(): start every phase from a clean, all-off state so old lights never linger.

Lines 16–21 — the three if checks: switch on only the lights asked for. if reds: means "if reds is True, turn the red LED on." This lets the very same function produce all four phases, including Red+Amber together.

Line 22 — sleep(seconds): hold this phase for the requested time — sequencing with time.sleep().

Line 25 — while True:: repeat forever, so the lights cycle endlessly like the real thing.

Lines 26–29 — four phase(...) calls: the UK sequence, in order, with the Red+Amber phase included. Because the timings are just arguments, you can tweak them without touching the function.

Running it

  1. Save the file as traffic.py in your home folder (File > Save).
  2. Run it with the green ▶ button or F5.
  3. Watch the cycle: red, then red+amber together, then green, then amber, repeating. The console prints a start message.
  4. Stop with the red ◼ button when you have seen enough. All LEDs go off.

The Elegant Version: TrafficLights

The program above works perfectly and taught us lists, loops and functions. But gpiozero already knows about traffic lights! It has a ready-made object called TrafficLights that bundles a red, amber and green LED together for you. Here is the entire sequence again, far shorter:

from gpiozero import TrafficLights
from time import sleep

lights = TrafficLights(red=25, amber=8, green=7)

while True:
    lights.red.on()
    sleep(4)
    lights.amber.on()      # red still on -> the Red+Amber phase
    sleep(1)
    lights.off()
    lights.green.on()
    sleep(4)
    lights.green.off()
    lights.amber.on()
    sleep(1)
    lights.amber.off()

Line 1 — from gpiozero import TrafficLights: imports the ready-made traffic-light object.

Line 4 — lights = TrafficLights(red=25, amber=8, green=7): creates one object that owns all three LEDs. The red=, amber=, green= parts are keyword arguments — they make it crystal clear which pin is which colour. Wiring is unchanged: each LED still has its own 330 Ω resistor.

Lines 7–8 — lights.red.on() then sleep(4): you reach each colour through the object: lights.red, lights.amber, lights.green are ordinary LEDs you can turn on and off.

Line 9 — lights.amber.on(): because red is still on, switching amber on as well gives the Red+Amber phase for free.

Line 11 — lights.off(): a handy shortcut that switches all three off at once.

Lines 12–17: green for 4 s, then amber alone for 1 s, before the loop returns to red.

Tip: TrafficLights even has a built-in demo. Try lights.blink() to flash all three together, or explore the gpiozero documentation at gpiozero.readthedocs.io for more ready-made objects like LEDBoard, which groups any number of LEDs.
Note: both versions drive the same wiring and obey the same current budget. The hand-written version teaches you the fundamentals; the TrafficLights version shows how a good library lets you say what you mean in fewer lines. Real programmers move between both styles all the time.

The Pedestrian-Crossing Variant

Real crossings change for people, not just on a timer. Let us add a push button: while no one presses it, the lights stay green for traffic; press it, and the lights run through amber to red so pedestrians can cross, then back to green.

Wire a push button alongside the LEDs. With gpiozero's Button, the default wiring is one leg to a GPIO pin and the other leg to GND (gpiozero switches on an internal pull-up resistor, so a press reads as "pressed" without any extra parts). We will use GPIO 2 (physical pin 3) for the button.

FromToVia
Button leg 1GPIO 2 (pin 3)jumper wire
Button leg 2 (opposite side)GND (pin 20 / ground rail)jumper wire
Careful: power off again before adding the button. The button needs no resistor of its own, but the three LEDs still each need their 330 Ω resistor — nothing about the LED rules changes.
from gpiozero import TrafficLights, Button
from time import sleep

lights = TrafficLights(red=25, amber=8, green=7)
button = Button(2)   # other leg to GND; internal pull-up by default

def let_pedestrians_cross():
    print("Button pressed - stopping traffic")
    lights.amber.on()
    sleep(1)
    lights.amber.off()
    lights.red.on()
    sleep(5)            # walk time
    lights.red.off()
    lights.green.on()   # traffic flows again

# Start with green for the traffic
lights.green.on()
print("Lights green. Press the button to cross.")

while True:
    button.wait_for_press()
    lights.green.off()
    let_pedestrians_cross()

Line 1: import both TrafficLights and Button from gpiozero.

Line 5 — button = Button(2): the button on GPIO 2. By default pull_up=True, so wire the other leg to GND; pressing pulls the pin low and gpiozero reports it as pressed.

Lines 7–15 — def let_pedestrians_cross():: a function holding the whole "stop the traffic, let people walk, then resume" sequence: amber, red for a walk time, then back to green.

Lines 18–19: before the loop, set green for traffic and print an instruction.

Line 21 — while True:: loop forever, waiting for presses.

Line 22 — button.wait_for_press(): pauses the program right here until the button is pressed. No busy-waiting, no wasted effort — the program simply sleeps until someone wants to cross.

Lines 23–24: turn green off and call our crossing function. When it finishes, the loop returns to waiting for the next press.

Note: we have used Button only lightly here. Buttons, debouncing and reaction-time games are the whole subject of the next chapter — so if the button misbehaves or seems to "press itself" twice, that is the bouncing problem you will learn to fix next.

Troubleshooting

SymptomLikely cause & fix
One LED never lightsIt is probably in backwards. Long leg (anode) must face the resistor/GPIO side; short leg (cathode) faces ground. Pull it out and turn it round.
No LEDs light at allCheck the single ground wire from the − rail to the Pi's GND pin — if that is loose, none of the LEDs can complete their circuit.
Wrong colour lights for a phaseA GPIO wire is on the wrong resistor. Match GPIO 25→red, GPIO 8→amber, GPIO 7→green, and check your code uses the same numbers.
LED is very dim or flickersA wire is barely making contact, or you used a much larger resistor than 330 Ω. Re-seat the wires; confirm orange-orange-brown-gold bands.
No module named 'lgpio'Run sudo apt install python3-lgpio in a terminal, then restart Thonny.
An LED stays dimly lit when it should be offUsually a stray wire bridging two rows on the breadboard. Trace each row and remove the accidental bridge.

From the E-Waste Pile

You do not need to buy LEDs and resistors — old electronics are full of them. Almost any dead gadget with indicator lights is a free supply.

  • LEDs live in broken toys, old routers and modems (status lights), printer control panels, and cheap fairy lights. Desolder them gently with a soldering iron; the longer leg is still the anode.
  • Resistors are scattered across almost every circuit board. Read the colour bands (orange-orange-brown-gold is your 330 Ω) or measure them with a multimeter on the Ω setting.
  • Test before you trust: a multimeter in diode mode lights a good LED dimly when the red probe touches the anode; swap the probes if it stays dark.
Careful: only ever harvest from low-voltage, unplugged equipment. Never open mains power supplies, microwave ovens, CRT televisions/monitors, or anything with large capacitors or lithium batteries — these can hold a dangerous or lethal charge even when unplugged. Stick to battery toys, USB gadgets and dead routers.

Make It Your Own

You have the fundamentals now — here are four ways to take the project further:

  • Two-way junction. Add a second set of three LEDs for the cross-road and run the two sets in opposite phases (one red while the other is green). A list of two TrafficLights objects and a loop will keep it tidy.
  • Adjustable timing. Move all the sleep durations into variables at the top (go_time = 4, warn_time = 1) so you can tune the whole cycle in one place.
  • A green "walk" man. Add a fourth and fifth LED (red and green) for the pedestrian signal, and light the green walk LED while traffic is on red.
  • Level crossing. Swap the sequence for two red LEDs that alternate (blinking left-right) like a railway level crossing — a great excuse to practise blink() and a list.
Tip: every extension above still obeys the current budget. If you ever add many LEDs (say a whole row), add up the milliamps: stay under ~16 mA per pin and ~50 mA across the header, or switch to a driver chip designed to handle more.

Key terms

  • List — a single name holding several values in order, written in square brackets; items are numbered from 0.
  • for loop — repeats a block of code once for each item in a list (or other sequence).
  • Function — a named, reusable block of code, defined with def, that you run by calling its name.
  • Parameter / argument — a parameter is a named "blank" in a function definition; an argument is the actual value you pass in when you call it.
  • time.sleep() — pauses the program for a given number of seconds; the basis of timed sequencing.
  • while True — a loop that repeats forever, used here to cycle the lights endlessly.
  • Common cathode — a wiring layout where all the LED negative legs (cathodes) join a shared ground.
  • Current budget — the safe limits on current: ~16 mA per GPIO pin and ~50 mA across the whole header.
  • TrafficLights — a ready-made gpiozero object grouping a red, amber and green LED, created with TrafficLights(red=, amber=, green=).
  • LEDBoard — a gpiozero object that groups any number of LEDs so you can control them together.

  • A list keeps related things (our three LEDs) together under one name, indexed from 0.
  • A for loop runs the same code for every item in a list — perfect for switching all the LEDs off at once.
  • Functions with parameters let you write a step once (like phase()) and reuse it with different values.
  • time.sleep() holds each phase long enough to see, giving you control over sequencing.
  • The UK cycle is Red → Red+Amber → Green → Amber, including the easily forgotten Red+Amber "get ready" phase.
  • Every LED needs its own 330 Ω resistor; never share one or omit it.
  • Respect the current budget: ~16 mA per pin, ~50 mA total; three resistor-limited LEDs draw only ~12 mA together.
  • A common-cathode layout shares one ground wire for all three LEDs.
  • gpiozero's TrafficLights(red=, amber=, green=) bundles the three LEDs into one elegant object that does the same job in fewer lines.
  • Adding a Button (one leg to a GPIO pin, the other to GND) turns the project into a pedestrian crossing — a gentle taste of the next chapter.
  • Always power off and unplug before wiring, and keep to 3.3 V on every GPIO pin.
