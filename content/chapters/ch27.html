An empty jam jar, a frosted bottle, a single colourful LED rescued from a broken toy — together they become a soft, glowing mood lamp that drifts gently through colours and even has a flickering "lava" mode. In this project you will learn how to mix any colour from red, green, and blue light using PWM duty cycle for brightness, and you will meet three powerful Python ideas: functions that take parameters and return values, the while True loop, and the random module that gives your lamp a life of its own.

How an RGB LED Makes Colour

An RGB LED is really three tiny LEDs — one red, one green, one blue — built into a single clear package with four legs. By lighting them at different brightnesses and letting their light blend, you can make almost any colour your eye can see. This is exactly how a TV or phone screen works, just with millions of tiny dots instead of one.

In plain words: Additive colour mixing means adding coloured light together. Red + green light makes yellow; red + blue makes magenta; all three together make white. This is different from mixing paint (where more colours make brown) because light adds up instead of soaking up.

PWM Duty Cycle as Brightness

A GPIO pin can only be fully on (3.3 V) or fully off (0 V) — there is no "half voltage" setting. So how do we make an LED glow at half brightness? The answer, again, is PWM: switching the pin on and off very fast.

In plain words: The duty cycle is the fraction of each cycle that the pin spends switched ON. A duty cycle of 1.0 means on all the time (full brightness); 0.5 means on half the time (looks half as bright); 0.0 means always off. The switching is so fast (default 100 times a second) that your eye blends it into a steady, dimmer glow rather than a flicker.

gpiozero hides all the switching. For an RGB LED it lets you set each colour channel to a number between 0 and 1 — that number is the duty cycle, and therefore the brightness. We will set colours like (1, 0.5, 0), meaning "red full, green half, blue off" — which is orange.

Common-Cathode vs Common-Anode

RGB LEDs come in two flavours, and you must know which you have, or your colours come out inverted.

  • Common-cathode: the three colours share a single negative (cathode) leg, which goes to GND. Each colour lights when its pin goes HIGH. This is the gpiozero default (active_high=True).
  • Common-anode: the three colours share a single positive (anode) leg, which goes to 3.3 V. Each colour lights when its pin goes LOW. You tell gpiozero this with active_high=False.
In plain words: "Common" means shared. A common-cathode LED shares its negative leg (cathode = negative), so the shared leg goes to ground. A common-anode LED shares its positive leg (anode = positive), so the shared leg goes to 3.3 V. The longest leg is usually the shared (common) one.
Tip: Not sure which you have? Wire it up assuming common-cathode (the default), then run a quick "red only" test. If asking for red gives you cyan (the opposite), you have a common-anode — just add active_high=False when you create the RGBLED. No rewiring needed beyond moving the shared leg between GND and 3.3 V.

One Resistor Per Channel

Just like a single LED, each colour inside the RGB package is a real LED with almost no resistance of its own — so each one needs its own current-limiting resistor to stop it (and the GPIO pin) burning out.

Careful: You need three resistors — one in series with each of the red, green, and blue legs. A single shared resistor on the common leg will not protect each colour properly and will make the brightness change as you mix colours. Use a 330 Ω resistor (orange-orange-brown-gold) per channel. As always, the Pi's GPIO is 3.3 V logic — never feed more than 3.3 V into a pin.
Note: Blue and green LEDs have a higher forward voltage than red, so with equal resistors the blue and green can look a little brighter than red for the same setting. That is normal and easy to correct in software — see "Make it your own".

From the E-Waste Pile

Two of this project's parts come straight from the recycling: the diffuser and the light itself.

The jar (diffuser)

Any clear or frosted glass container scatters the LED's light into a soft glow. A jam jar, a frosted bottle, or a small drinking glass all work. Frosted glass diffuses best; for a clear jar, a sheet of baking paper or tissue wrapped inside softens the light beautifully.

No RGB LED to hand? Use three separate single LEDs — one red, one green, one blue — wired to the same three GPIO pins, each with its own resistor and a shared GND. gpiozero's RGBLED object treats them exactly the same.

Careful: Salvage only from low-voltage, battery-powered items. Never open a mains adapter, a microwave, or a CRT (tube) TV/monitor — their capacitors can hold a dangerous charge even when unplugged. Never cut or crush a lithium battery. A jar should be clean, dry, and free of cracks.

Testing a salvaged LED

  1. Find the legs. A single LED's longer leg is the anode (+), the shorter leg (with the flat side) is the cathode (−). An RGB LED has one long shared leg and three shorter colour legs.
  2. Test with a coin cell. Through a 330 Ω resistor, touch a 3 V coin cell across each LED (+ to anode). A working LED glows; swap the legs if it stays dark.
  3. Identify the channels. On an RGB LED, touch each short leg in turn (sharing the long leg) to find which is red, green, and blue, and note the order.

Wiring the RGB LED

Careful: Power off and unplug your Pi before wiring. Shut down from the desktop menu, wait for the green light to go out, then remove the power lead. Use one resistor per colour channel. The Pi's GPIO is 3.3 V logic only. Re-power only once your wiring is checked.

We will use GPIO 17 for red (physical pin 11), GPIO 27 for green (pin 13), and GPIO 22 for blue (pin 15). The shared common leg goes to a GND pin (for a common-cathode LED).

Wiring steps

  1. Shut down and unplug the Pi. Wait for the green light to go out.
  2. Seat the LED. Push the RGB LED into the breadboard so each of its four legs is in its own row. Note which leg is the long (common) one.
  3. Fit the three resistors. Place one 330 Ω resistor reaching from each colour leg's row to a free row where a jumper can meet it.
  4. Wire red. Jumper from pin 11 (GPIO 17) to the free end of the red channel's resistor.
  5. Wire green and blue. Jumper from pin 13 (GPIO 27) to the green resistor, and pin 15 (GPIO 22) to the blue resistor.
  6. Wire the common leg. Jumper from the LED's long shared leg row to a GND pin (pin 9). For a common-anode LED, take this leg to 3.3 V instead and remember active_high=False in code.
  7. Check, then re-power and boot up.

Python Fundamentals: Parameters, Return, while True, random

Let us learn the new Python ideas with tiny examples before building the lamp.

Functions that take parameters and return a value

In Chapter 26 our functions did things. Now we want functions that calculate and hand back a result, using the return keyword.

def dim(colour, amount):
    r, g, b = colour
    return (r * amount, g * amount, b * amount)

half_red = dim((1, 0, 0), 0.5)
print(half_red)   # (0.5, 0.0, 0.0)

Line 1 — def dim(colour, amount):: Defines a function with two parameters: a colour (an (r, g, b) tuple) and an amount to scale it by.

Line 2 — r, g, b = colour: Unpacks the tuple into three separate variables.

Line 3 — return (...): The return keyword hands a value back to whoever called the function. Here we hand back a new tuple with each channel multiplied by amount.

Line 5 — half_red = dim((1, 0, 0), 0.5): Calls the function and stores the returned value in half_red. This is the key difference from before: the function gives us something back to use.

In plain words: A parameter is a value you pass into a function. A return value is the answer the function passes back out. Think of a function as a little machine: parameters go in the top, a result comes out the bottom.

Gentle 0–1 maths

gpiozero expects each colour channel as a number from 0 to 1. Keeping everything in that range makes the maths easy: multiply by a fraction to dim, and you never leave the safe range. If a calculation might stray outside 0–1, we clamp it:

def clamp(value):
    return max(0, min(1, value))

print(clamp(1.3))   # 1
print(clamp(-0.2))  # 0

Line 1–2 — def clamp(value): return max(0, min(1, value)): min(1, value) caps anything above 1 down to 1; max(0, ...) lifts anything below 0 up to 0. The result is always safely between 0 and 1.

Lines 4–5: Show it clamping 1.3 down to 1 and −0.2 up to 0 — keeping our brightness values legal for gpiozero.

The while True loop

A mood lamp should glow until you switch it off. The while True: loop runs its body over and over, forever.

from time import sleep

while True:
    print("still glowing...")
    sleep(2)

Line 3 — while True:: True is always true, so this loop never ends on its own. The indented body repeats until you stop the program (the red Stop button) or press Ctrl+C.

Lines 4–5: The repeating body — print a message, wait two seconds, and round again. In the lamp, this is where we will fade colours.

The random module

To give the lamp a life of its own we use Python's random module, which makes unpredictable numbers.

import random

print(random.random())          # a float from 0.0 up to 1.0
print(random.uniform(0.2, 0.8)) # a float between 0.2 and 0.8
print(random.choice(["a", "b"]))# one item picked at random

Line 1 — import random: Brings in Python's built-in random-number toolkit.

Line 3 — random.random(): Returns a random decimal from 0.0 up to (but not including) 1.0 — already perfect for a brightness value.

Line 4 — random.uniform(0.2, 0.8): A random decimal between the two numbers you give. Handy for keeping the lamp from going fully dark or fully bright.

Line 5 — random.choice([...]): Picks one item from a list at random — we will use it to pick a random mood.

Meet the RGBLED Object

gpiozero's RGBLED wraps all three channels into one object. You give it the three pins, and then set .value to an (r, g, b) tuple where each number is 0–1.

from gpiozero import RGBLED
from time import sleep

led = RGBLED(red=17, green=27, blue=22)

led.value = (1, 0, 0)   # red
sleep(1)
led.value = (0, 0, 1)   # blue
sleep(1)
led.value = (1, 0.5, 0) # orange (red full, green half)
sleep(1)
led.off()

Line 1 — from gpiozero import RGBLED: Imports the ready-made RGB LED object.

Line 4 — led = RGBLED(red=17, green=27, blue=22): Creates the object, telling gpiozero which GPIO pin drives each colour. By default active_high=True (common-cathode) and PWM is on, so brightness control just works.

Line 6 — led.value = (1, 0, 0): Sets red to full (1), green and blue off (0) — pure red. Each number is the channel's duty cycle.

Line 8 / 10 — blue, then orange: Changing the tuple changes the mix. (1, 0.5, 0) is red full, green at half brightness, blue off — orange.

Line 12 — led.off(): Turns all three channels off.

Note: If your colours come out wrong (asking for red gives cyan), you have a common-anode LED — create it with RGBLED(red=17, green=27, blue=22, active_high=False) and connect the shared leg to 3.3 V.

The Full Program

Now we build the mood lamp: preset moods stored as data, functions that build and fade colours, a while True loop to keep it running, and a random "lava" mode. Open a new file in Thonny.

from gpiozero import RGBLED
from time import sleep
import random

# If your colours look inverted, set active_high=False (common-anode)
led = RGBLED(red=17, green=27, blue=22)

# A small list of preset moods: name to (r, g, b) each 0..1
MOODS = {
    "sunset":  (1.0, 0.3, 0.0),
    "ocean":   (0.0, 0.4, 1.0),
    "forest":  (0.0, 0.8, 0.2),
    "candle":  (1.0, 0.5, 0.1),
    "violet":  (0.5, 0.0, 0.8),
}


def clamp(value):
    """Keep a number safely between 0 and 1."""
    return max(0.0, min(1.0, value))


def fade(from_colour, to_colour, steps=50, pause=0.02):
    """Smoothly fade from one (r, g, b) colour to another."""
    fr, fg, fb = from_colour
    tr, tg, tb = to_colour
    for i in range(steps + 1):
        amount = i / steps              # 0.0 grows to 1.0
        r = fr + (tr - fr) * amount
        g = fg + (tg - fg) * amount
        b = fb + (tb - fb) * amount
        led.value = (clamp(r), clamp(g), clamp(b))
        sleep(pause)


def random_colour():
    """Return a random (r, g, b) that is not too dark."""
    r = random.uniform(0.2, 1.0)
    g = random.uniform(0.2, 1.0)
    b = random.uniform(0.2, 1.0)
    return (r, g, b)


def mood_cycle():
    """Slowly fade through every preset mood, then repeat."""
    current = (0, 0, 0)
    while True:
        for name, colour in MOODS.items():
            print("Fading to", name)
            fade(current, colour)
            current = colour
            sleep(1)


def lava_mode():
    """Drift through random colours forever, like a lava lamp."""
    current = random_colour()
    while True:
        target = random_colour()
        fade(current, target, steps=80, pause=0.03)
        current = target


# Choose your mode here:
print("Mood lamp starting. Press Stop to switch off.")
mood_cycle()
# lava_mode()   # comment out mood_cycle() above and use this instead

Lines 1–3 — the imports: RGBLED for the light, sleep for timing, and random for unpredictability.

Line 6 — led = RGBLED(red=17, green=27, blue=22): Creates the RGB LED on our three pins. Made once, near the top, so every function can use it.

Lines 9–15 — MOODS = {…}: A dictionary of preset moods, each a name mapped to an (r, g, b) tuple with values 0–1. Storing colours as data lets us add moods without touching the fading code.

Lines 18–20 — clamp(): A function that returns a value safely between 0 and 1, so a fade can never ask the LED for an illegal brightness.

Lines 23–33 — fade(from_colour, to_colour, …): The heart of the lamp. It takes two colours as parameters plus how many steps and how long to pause. The loop runs steps + 1 times; amount = i / steps grows gently from 0.0 to 1.0. The lines r = fr + (tr - fr) * amount mix that fraction of the way from the start colour to the end colour for each channel — gentle 0–1 maths in action. Setting led.value each step and pausing briefly makes a smooth fade.

Lines 36–41 — random_colour(): A function that returns a random colour using random.uniform(0.2, 1.0) for each channel, so the colour is lively but never fully dark.

Lines 44–52 — mood_cycle(): Uses while True to loop forever. Each round, the for name, colour in MOODS.items(): line walks through every preset, fading from the current colour to the next, then remembering it as the new current.

Lines 55–61 — lava_mode(): Another while True loop, but instead of presets it fades to a fresh random colour each time — slow, gentle, and never repeating. This is where parameters, return values, the forever loop, and randomness all come together.

Lines 65–67 — choosing a mode: Calls mood_cycle() to start. To run the lava mode instead, comment out that line and uncomment lava_mode().

Running It

  1. In Thonny, choose File → Save and save the file as mood_lamp.py in your home folder.
  2. Click the green Run button (the triangle ▶) or press F5.
  3. Watch the LED gently fade between the preset moods. The Thonny console prints the name of each mood as it arrives.
  4. Place the LED and breadboard inside (or beside) your jar to see the soft, diffused glow. For a clear jar, tuck a little baking paper or tissue inside.
  5. To try the lava mode, stop the program, swap which mode line is active (comment mood_cycle(), uncomment lava_mode()), and run again.
  6. To switch the lamp off, click the red Stop button (the square ■).
Careful: Use only the cool, low-power LED inside the jar — never a candle or anything hot in a sealed glass container. The LED runs barely warm, which is exactly why it is safe in a recycled jar.

Troubleshooting

SymptomLikely cause & fix
Colours are inverted (red looks cyan)You have a common-anode LED. Add active_high=False to RGBLED(...) and connect the shared leg to 3.3 V.
Only some colours lightA resistor or jumper for that channel is loose, or that colour leg is in the wrong row. Recheck each channel separately.
One colour is far brighterNormal — blue/green have a higher forward voltage than red. Scale that channel down in the colour tuples to balance.
LED flickers visiblyA loose common-leg wire, or PWM disabled. Ensure RGBLED is created normally (PWM is on by default).
Nothing lights at allCheck the common leg goes to GND (common-cathode) and that all three resistors and the LED are seated. Confirm the LED legs are in separate rows.
No module named 'lgpio'Install the backend: sudo apt install python3-lgpio, then restart Thonny.
Fade looks jerky / steppyIncrease steps or reduce pause in the fade() call for a smoother transition.

Make It Your Own

  • Add a button to change moods. Wire a push button (Chapter 12) and use button.when_pressed to jump to the next preset on demand.
  • Balance the colours. Add a balance() function that scales the green and blue channels down a little so white looks truly white on your particular LED.
  • A breathing night light. Use led.pulse() (built into RGBLED) for a slow fade in and out, like calm breathing.
  • More moods. Add new entries to the MOODS dictionary — because moods are stored as data, the fading code never has to change. Try "midnight": (0.0, 0.0, 0.4) or "rose": (1.0, 0.2, 0.4).
Tip: Notice the same big idea from Chapter 26: colours and moods live as data (a dictionary of tuples), while the behaviour (fading) lives in functions. Add a new colour and everything just works. Separating data from behaviour is one of the most useful habits a programmer can build.

Key terms

  • RGB LED - A single package containing red, green, and blue LEDs whose blended light can make almost any colour.
  • Additive colour mixing - Adding coloured light together; red + green + blue at full makes white.
  • Duty cycle - The fraction of each PWM cycle a pin spends switched on; it sets the LED's brightness (0 = off, 1 = full).
  • PWM (Pulse-Width Modulation) - Switching a pin on and off fast; the duty cycle controls perceived brightness.
  • Common-cathode - An RGB LED whose three colours share a negative leg connected to GND; gpiozero default (active_high=True).
  • Common-anode - An RGB LED whose three colours share a positive leg connected to 3.3 V; needs active_high=False.
  • RGBLED - The gpiozero object that controls all three channels; set .value = (r, g, b) with each number 0–1.
  • Parameter - A value passed into a function for it to use.
  • Return value - The result a function hands back to its caller with the return keyword.
  • while True loop - A loop that runs forever until the program is stopped; ideal for a lamp that glows continuously.
  • random module - Python's built-in toolkit for unpredictable numbers (random.random(), random.uniform(), random.choice()).
