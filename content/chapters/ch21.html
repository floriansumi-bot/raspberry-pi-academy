Your Raspberry Pi 5 is a sturdy little machine, but like any computer it benefits from a small amount of regular care — and every computer occasionally misbehaves. This chapter gives you everything you need to keep your Pi running smoothly, understand what its warning lights mean, and solve the most common problems without needing to call anyone for help.

Routine Care: Keeping Your Pi Healthy

A well-maintained Raspberry Pi can run continuously for years. The three pillars of routine care are keeping the software up to date, watching the temperature, and making sure the storage card is treated gently. None of this takes more than a few minutes a week.

Keeping Software Up to Date

Raspberry Pi OS receives regular updates that fix security holes, squash bugs, and occasionally add new features. Applying them is a two-command process that you can run from the Terminal application any time.

In plain words: A package is a bundle of software that your Pi can install, update, or remove. The package manager (apt) is the tool that fetches and installs those bundles automatically, handling all the complicated dependency juggling behind the scenes.
sudo apt update
sudo apt full-upgrade -y

Line 1 — sudo apt update: Asks your Pi to download a fresh list of available packages from the internet. It does not install anything yet; it just refreshes the catalogue so the next command knows what is new.

Line 2 — sudo apt full-upgrade -y: Downloads and installs every update that is now available. The full-upgrade variant (rather than the older upgrade) is recommended for Raspberry Pi OS because it is allowed to remove or replace packages when needed to apply a complex update. The -y flag answers "yes" automatically to any confirmation prompts so you do not have to sit and watch.

Tip: Run these two commands roughly once a week, or at least once a month. Good moments to remember: before starting a new project, or just after you turn the Pi on for the day.

After a major upgrade you may see a message saying a reboot is needed. If so, type:

sudo reboot

Tells the Pi to restart cleanly. All running programs close gracefully, the system powers down, and then boots back up with the new software active.

Tip: You can also check whether a reboot is pending by looking for the file /run/reboot-required. If that file exists after an upgrade, a reboot is needed. You can check with: test -f /run/reboot-required && echo "Reboot needed" || echo "No reboot needed".

Checking the Temperature

The Pi 5's processor is powerful, and under heavy work it generates heat. If you have a cooler fitted — such as the official Active Cooler, the little heatsink-and-fan combination that clips to the board, or a fan built into your case — it handles this well, but it is good to know how to check the temperature yourself. (A cooler is strongly recommended on the Pi 5; if yours did not come with one, the official Active Cooler is inexpensive and easy to fit.)

In plain words: Throttling means the processor deliberately slows itself down to avoid overheating. It is a safety mechanism, not a failure — but it does make your Pi feel sluggish, so you want to avoid it.
vcgencmd measure_temp

Reads the temperature sensor built into the Pi's processor chip and prints it to the screen. A typical result looks like temp=47.2'C. The vcgencmd command is a special Raspberry Pi utility for querying the hardware directly.

Here is a quick guide to what the temperature readings mean:

Temperature What it means Action needed
Below 60 °C Cool and happy None — all is well
60–75 °C Warm under load Normal during intensive tasks; no action needed if it drops when idle
75–80 °C Getting hot Check airflow around the case; make sure the fan is spinning
Above 80 °C Throttling will occur Improve cooling; see the Troubleshooting section below
Tip: You can watch the temperature update in real time every two seconds by running: watch -n 2 vcgencmd measure_temp. Press Ctrl + C to stop.

Checking for Throttling and Undervoltage

The Pi reports throttling events in a special status register. You can read it with one command:

vcgencmd get_throttled

Reads a hidden status word from the Pi's hardware and prints a hexadecimal (base-16) number. The most reassuring result is throttled=0x0, which means nothing bad has happened since the last reboot.

The number returned is a bitmask — a code where each digit position carries a separate meaning. You do not need to memorise the arithmetic; just use this table:

Result value What it means Likely cause
0x0 All clear — no throttling ever recorded Everything is fine
Bit 0 set (e.g. 0x1) Undervoltage right now Power supply is too weak or cable is poor quality
Bit 1 set (e.g. 0x2) Arm frequency capped right now Temperature or voltage is borderline
Bit 2 set (e.g. 0x4) Currently throttled Too hot — check cooling
Bit 16 set (e.g. 0x10000) Undervoltage occurred since last reboot Power dip happened at some point
Bit 18 set (e.g. 0x40000) Throttling occurred since last reboot Temperature spike happened at some point

Values can be combined — for example 0x50005 means undervoltage and throttling are happening right now and both have also occurred since last boot.

The Lightning-Bolt Warning Icon

On the Raspberry Pi OS desktop you may occasionally see a small yellow lightning-bolt icon appear in the top-right corner of the screen. This is the desktop's visual alert for undervoltage — the Pi is not receiving enough power. It is the graphical equivalent of the bits above. The good news: a proper 27 W USB-C power supply (5.1 V / 5 A) made for the Pi 5 — the official Raspberry Pi supply, or the equivalent one included with many starter kits — prevents virtually all undervoltage warnings when used correctly. If you do see the lightning bolt:

  • Make sure you are using a proper 27 W USB-C supply made for the Pi 5, not a phone charger.
  • Check that the USB-C cable is pushed firmly into both the Pi and the power supply.
  • Avoid using a USB hub to power the Pi — it must be powered directly from its own supply.
Careful: Persistent undervoltage can cause data corruption on your microSD card. If you see the lightning bolt regularly, fix the power supply before doing anything else.

Checking Free Storage Space

Your microSD card has a finite amount of space. If it fills up, programs start behaving strangely or refusing to run.

df -h

df stands for "disk free". The -h flag means "human-readable", so sizes are shown in megabytes (MB) and gigabytes (GB) rather than raw byte counts. The output shows every storage area ("filesystem") mounted on your Pi, how big it is, how much is used, and how much is free. The line you care about most is the one whose "Mounted on" column reads / — that is your main microSD card.

A typical healthy result looks like this:

Filesystem      Size  Used Avail Use% Mounted on
/dev/mmcblk0p2   58G   12G   43G  22% /

This example shows a 64 GB card with 12 GB used and 43 GB free — plenty of headroom. If the "Use%" column climbs above 85–90%, it is time to tidy up. The device name /dev/mmcblk0p2 refers to the second partition on your microSD card — this is normal and expected.

Tidying Up: Freeing Disk Space

Over time, packages you install leave behind cached files and old versions. Two commands clean most of this up safely:

sudo apt autoremove -y
sudo apt clean

Line 1 — sudo apt autoremove -y: Removes packages that were installed automatically as dependencies of something else but are no longer needed by anything. These orphaned packages are safe to delete.

Line 2 — sudo apt clean: Deletes the downloaded package files that apt keeps in a cache folder after installation. The software itself is still installed; only the now-unnecessary installer files are removed. This can reclaim hundreds of megabytes.

Tip: Combine all four maintenance commands into one tidy habit: sudo apt update && sudo apt full-upgrade -y && sudo apt autoremove -y && sudo apt clean. The && symbol means "run the next command only if the previous one succeeded".

Checking CPU and Memory Usage

If your Pi feels sluggish, it is useful to see what is using the processor and memory. The simplest way is the htop tool — a live, colourful dashboard of everything running on the Pi.

htop

Opens an interactive view showing all running processes, how much processor time each one is using (%), and how much memory each one is consuming. The bars at the top show overall CPU usage across all four processor cores and total memory use. Press Q to quit back to the terminal. If htop is not installed, run sudo apt install htop first.

Tip: If you want a quick, non-interactive snapshot of the top resource users without opening a live view, type top -b -n 1 | head -20. This prints a one-shot summary of the twenty busiest processes and exits immediately.

Understanding Your Pi's Status LEDs

The Raspberry Pi 5 has a red LED and a green LED on the board. Learning what they signal is often the fastest way to diagnose a problem.

LED colour Behaviour What it means
Red (PWR) Solid on Power supply is good — normal
Red (PWR) Off entirely No power reaching the board; check the cable and supply
Red (PWR) Flickering Undervoltage — power supply is struggling
Green (ACT) Irregular flashing Actively reading or writing to the microSD card — normal during boot and use
Green (ACT) Steady on or off after initial flash Boot has stalled — corrupted card, wrong image, or card not seated properly
Green (ACT) Specific blink patterns (e.g. 4 flashes, pause) A boot error code — count the flashes; see the Boot Error Codes table below

Boot Error Codes (Green LED Blink Patterns)

If the green LED flashes in a regular repeating pattern during boot rather than irregularly, count the flashes between the pauses. Each number points to a specific problem:

Flash count What it means What to do
3 flashes start.elf not found or corrupted Re-flash the microSD card with Raspberry Pi Imager
4 flashes start.elf cannot be launched Re-flash the microSD card with Raspberry Pi Imager
7 flashes kernel.img not found Re-flash the microSD card with Raspberry Pi Imager
8 flashes SDRAM (memory) not recognised Try a different microSD card; if that fails, the board may need checking
Note: All single-digit blink-code problems are almost always fixed by re-flashing the microSD card. The Pi 5's bootloader is very reliable; what fails is usually the card or the image written to it.

Reading Logs: What Is the Pi Telling You?

When something goes wrong, your Pi keeps a record of what happened in its system logs. You do not need to understand everything in them — just knowing how to glance at the end of the log is often enough to find a clear error message.

In plain words: A log is like a diary that the operating system writes automatically. Every time a service starts, crashes, or encounters a problem, it writes a timestamped entry. Reading logs is the first step professionals take when diagnosing any Linux system.

Viewing Recent Log Entries

journalctl -xe

journalctl is the command for reading the system journal (log). The -x flag adds helpful explanatory text around error entries. The -e flag jumps to the end of the log (the most recent entries) rather than starting from the beginning. Use the arrow keys to scroll up and down; press Q to quit.

Viewing Boot Messages

dmesg | tail -30

dmesg prints the kernel ring buffer — the messages the Linux kernel itself generated, especially during boot. The | symbol (called a "pipe") sends that output to the next command. tail -30 shows only the last 30 lines, which are usually the most relevant. Look for lines containing the words error, fail, or warning.

Tip: If you see an unfamiliar error message, copy the exact text and search for it in a web browser. The Raspberry Pi forums at forums.raspberrypi.com and general Linux Q&A sites almost always have someone who has seen the same thing before.

Viewing Logs for a Specific Service

If a particular program (called a service when it runs in the background) is misbehaving, you can read just its log:

journalctl -u ssh -n 50

Shows the last 50 log lines specifically for the ssh service (the remote-access tool). Replace ssh with the name of any other service — for example bluetooth or NetworkManager — to see its log instead. The -u flag means "unit" (the systemd name for a service) and -n 50 means "show the last 50 lines".

The raspi-config Configuration Tool

Raspberry Pi OS includes a dedicated configuration tool called raspi-config. It gives you a simple menu-driven interface for changing the most important system settings without needing to edit any configuration files by hand.

In plain words: A configuration file is a plain text file that tells the operating system how to behave. Editing them directly requires care. raspi-config does the editing for you safely.
sudo raspi-config

Opens the Raspberry Pi Configuration menu in the terminal. Use the arrow keys to move up and down, Enter to select, and Tab or the left/right arrows to move between the menu buttons at the bottom (such as <Select> and <Finish>). Press Escape or choose <Finish> to exit. Changes often take effect after a reboot.

The most useful things you can do in raspi-config:

Menu section What it does
System Options > Password Change your login password
System Options > Hostname Give your Pi a memorable name on the network (e.g. mypi)
Interface Options > SSH Enable or disable remote terminal access
Interface Options > VNC Enable graphical remote desktop access
Localisation Options > Timezone Set the correct local time zone
Localisation Options > WLAN Country Set the Wi-Fi country code (required for Wi-Fi to work)
Advanced Options > Expand Filesystem Make the OS use all available space on the microSD card
Note: Raspberry Pi Imager normally expands the filesystem automatically when it writes the card. However, if you ever re-flash manually and notice the available space seems smaller than expected, run sudo raspi-config and choose Advanced Options > Expand Filesystem.

Troubleshooting: The Big Reference Table

Below is a comprehensive table of the most common Raspberry Pi problems, their likely causes, and how to fix them. Work through the "Fix" steps in order — the simplest checks come first.

Problem Likely cause(s) Fix
Nothing on the screen — blank display Wrong micro-HDMI port used; monitor on wrong input; cable not fully inserted; Pi not booted yet See detailed steps below the table
Pi will not boot (green LED solid or wrong blink pattern) Corrupted microSD card; card not seated properly; wrong OS image written to card See detailed steps below the table
No Wi-Fi — cannot connect to any network Wi-Fi country not set; or trying to connect before country was configured in the imager See detailed steps below the table
Cannot SSH — "connection refused" or "host not found" SSH not enabled; wrong hostname or IP address; not on the same network See detailed steps below the table
Pi running hot or feeling slow Throttling due to heat or poor power; fan not spinning; case blocking airflow See detailed steps below the table
microSD card corruption / Pi freezes randomly Sudden power loss; poor-quality power supply; card wear See detailed steps below the table
"externally-managed-environment" error when using pip Bookworm protects the system Python from pip by default See detailed steps below the table
App will not install / "package not found" Package list is stale; package name wrong; package not in default repositories Always run sudo apt update first, then retry the install command
No sound from HDMI monitor Monitor speakers not selected as audio output; monitor has no speakers Right-click the speaker icon in the taskbar and select the HDMI audio device; or use USB speakers
Pi loses the correct time after a power cut No RTC battery installed; NTP time sync not working Connect to the internet to sync time automatically; or fit a real-time clock battery to the RTC connector

Nothing on the Screen / Blank Display

This is the most common beginner shock. Work through these steps in order:

  1. Check which micro-HDMI port you are using. The Pi 5 has two micro-HDMI sockets side by side. The primary port is the one closest to the USB-C power socket (labelled HDMI 0 on the board). Plug your cable into that port first. If you are already in it, try the other one.
  2. Check your monitor's input source. Most monitors have multiple inputs (HDMI 1, HDMI 2, DisplayPort, etc.). Use your monitor's menu button or input-select button to switch to the HDMI input your cable is connected to. This is the single most common reason for a blank screen.
  3. Check the cable is seated firmly. The micro-HDMI connector is small — push it in until it clicks. Do the same at the monitor end.
  4. Wait for the Pi to finish booting. The first boot after a fresh installation can take 60–90 seconds before the desktop appears. Watch the green ACT LED: if it is flashing, the Pi is working. Be patient.
  5. Try a different HDMI cable or a different monitor. Cables do fail. If you have another monitor or TV in the house, try plugging in there.
  6. Look at the green LED. If it shows a repeating pattern of short flashes (for example, 4 flashes then a pause), count them — each pattern is a boot error code. See the Boot Error Codes table above. In most cases, re-flashing the card (see the section on re-flashing below) will fix it.
Note: There is no 3.5 mm headphone socket on the Pi 5. Audio output is via HDMI or USB. If your monitor has no built-in speakers, you will need USB speakers or a USB audio adapter for sound.

Pi Will Not Boot

  1. Reseat the microSD card. Power the Pi off by unplugging it. Remove the microSD card from its slot on the underside of the board, then push it back in firmly until you feel it click. Reconnect power.
  2. Check whether the card is recognised. During boot the green LED should flash irregularly. If it does not flash at all after 30 seconds, the Pi cannot read the card.
  3. Re-flash the microSD card. Connect the card (using a USB card reader, or your computer's built-in SD slot) to your main computer — Windows, macOS, or Linux. Use the Raspberry Pi Imager application (download free from raspberrypi.com/software, available for all three) to write a fresh copy of Raspberry Pi OS to the card. This takes about 5–10 minutes. Then reinsert the card in the Pi and try again. Re-flashing erases the card but is completely safe and free — it is the fastest fix for most boot problems.
Careful: Re-flashing erases everything on the microSD card. If there are files on it you want to keep, copy them to your main computer first using a USB card reader or an SD slot. See the "Backing Up Your Files" section later in this chapter.

No Wi-Fi

The Pi 5 has built-in dual-band Wi-Fi, but it will refuse to connect if the country code has not been set. This is a legal requirement — Wi-Fi radios must operate within the power limits of the country they are in.

  1. Click the Raspberry Pi menu (top-left), go to Preferences > Raspberry Pi Configuration.
  2. Click the Localisation tab.
  3. Click Set WiFi Country and choose your country (United Kingdom, France, Germany, etc.).
  4. Click OK, then reboot when prompted.
  5. After rebooting, click the Wi-Fi icon in the top-right corner of the taskbar and select your network.

You can also set the country from the Terminal:

sudo raspi-config nonint do_wifi_country GB
sudo reboot

Line 1: Runs the Raspberry Pi configuration tool in non-interactive (command-line) mode and sets the Wi-Fi country to the United Kingdom (GB). Replace GB with your two-letter country code: FR for France, DE for Germany, CH for Switzerland, NL for the Netherlands, and so on.

Line 2: Reboots the Pi so the new country setting takes effect. Wi-Fi will be available after the restart.

Cannot SSH (Remote Access)

In plain words: SSH (Secure Shell) lets you control your Pi's terminal from another computer over the network, without needing a monitor plugged into the Pi at all.
  1. Make sure SSH is enabled. On the Pi desktop, go to Preferences > Raspberry Pi Configuration > Interfaces and ensure SSH is set to Enabled. Alternatively, in the Terminal:
sudo raspi-config nonint do_ssh 0

Enables SSH using raspi-config in non-interactive mode. The 0 means "enable" (and 1 would mean "disable"). After running this, SSH is active immediately — no reboot required.

  1. Check you are on the same network. Your Pi and the computer you are connecting from must be connected to the same router — either both on the same Wi-Fi, or the Pi on Ethernet into the same router. SSH will not work across different networks.
  2. Find the Pi's IP address. Run the following command on the Pi (when you have a monitor and keyboard connected), then use the printed address when connecting from your main computer.
hostname -I

Prints the Pi's current IP address (or addresses) on the network. The first number (e.g. 192.168.1.42) is the one to use when connecting from another computer. You can then connect from your main computer by opening a terminal (Command Prompt or PowerShell on Windows; Terminal on macOS or Linux) and typing ssh yourusername@192.168.1.42 — the command is identical on all three.

  1. Use the right hostname. If you do not have a monitor available, try connecting using the Pi's hostname: ssh yourusername@raspberrypi.local. If you changed the hostname in raspi-config, use that name instead (e.g. ssh yourusername@mypi.local).
  2. Check for a firewall. By default, Raspberry Pi OS does not run a firewall, so this is rarely the problem. But if you installed one, make sure port 22 is allowed.
Tip: You can verify your internet connection from the Pi's terminal at any time with:
ping -c 4 raspberrypi.com

Sends four small test packets to the Raspberry Pi website and waits for replies. If you see responses with times in milliseconds, the internet connection is working. If you see "Network unreachable" or "Name or service not known", the Pi is not online — check your Wi-Fi or Ethernet connection first.

Running Hot or Feeling Slow

  1. Check the temperature with vcgencmd measure_temp and the throttle status with vcgencmd get_throttled. A non-zero throttle value confirms the Pi has slowed down.
  2. Check the fan is spinning. The Active Cooler fan should spin when the Pi is warm. Listen for it, or look through any ventilation slots in the case. If the fan is silent when the Pi is hot, it may not be connected properly — the fan connector attaches to a small header on the Pi's board. Power the Pi off and reseat the connector.
  3. Check for airflow. Make sure the case's ventilation slots are not blocked by books, walls, or fabric. The Pi needs air to flow over it.
  4. Check the power supply. Throttling can be caused by undervoltage, not just heat. Confirm you are using the included 27 W supply (not a phone charger), and the cable is undamaged.
  5. Check what is using resources. Run htop to see which programs are consuming the most CPU or memory, and close what you do not need. You can also use the System Monitor application in the Raspberry Pi menu under Accessories.

microSD Card Corruption

The microSD card is the most fragile part of the Pi setup. Corruption — where files become garbled or unreadable — usually happens when the card loses power while it is in the middle of writing data.

Symptoms include: the Pi freezes randomly, refuses to boot, shows a "kernel panic" message, or the file system appears read-only.

How to prevent it:

  • Always shut down properly using the desktop menu (Raspberry Pi menu > Shutdown > Shutdown) or the terminal command sudo shutdown -h now. Wait for the green LED to stop flashing before disconnecting power.
  • Use the physical power button on the Pi 5 board: a single press triggers a clean shutdown.
  • Use a good-quality power supply (a proper 27 W USB-C supply for the Pi 5 is correct). Cheap phone chargers that struggle to deliver enough power cause micro-dropouts that corrupt cards.
  • Consider upgrading to an NVMe SSD on the PCIe connector for projects that involve heavy disk writing — SSDs are far more durable than microSD cards.

How to fix it: If the card is already corrupted, the quickest fix is to re-flash it using Raspberry Pi Imager on your main computer (Windows, macOS, or Linux) as described in the section below. Before you do, if the Pi still boots at all, back up your files first.

Tip: If the Pi boots but reports the filesystem is read-only, you may be able to check and repair it without re-flashing. Shut the Pi down cleanly, remove the microSD card, and insert it into your main computer. On Windows, run the disk error-checking tool (right-click the drive in File Explorer > Properties > Tools > Check). On macOS, use Disk Utility's First Aid. On Linux, run fsck on the card's partition from a terminal. This sometimes fixes minor corruption.

The "externally-managed-environment" Error with pip

On Raspberry Pi OS Bookworm, if you try to install a Python library directly with pip install something, you will see an error like:

error: externally-managed-environment

This is not a bug. Raspberry Pi OS Bookworm deliberately blocks pip from installing packages into the system Python environment, to protect the operating system from accidentally broken libraries. This is the correct and intentional behaviour.

You have three safe ways around this:

Option 1 — Use apt (best for well-known libraries):

sudo apt install python3-requests

Many popular Python libraries are available as official Raspberry Pi OS packages with the prefix python3-. Replace requests with the name of the library you need (for example python3-numpy or python3-pillow). This is the safest and most reliable method because the package has been tested to work with your exact version of Python.

Option 2 — Use a virtual environment (best for projects):

python3 -m venv myproject-env
source myproject-env/bin/activate
pip install requests

Line 1: Creates a self-contained Python environment in a new folder called myproject-env. This environment is completely separate from the system Python, so nothing you install inside it can break the operating system. You only need to do this once per project.

Line 2: "Activates" the environment — from this point on, python3 and pip refer to the versions inside this folder, not the system ones. You will see the environment name appear in brackets at the start of your prompt: (myproject-env). You need to run this activation line each time you open a new terminal and want to work on this project.

Line 3: Now that the virtual environment is active, pip install works normally and installs only into this safe, isolated folder. To deactivate the environment when you are done, simply type deactivate.

Option 3 — Use Thonny (easiest for beginners): The pre-installed Thonny code editor manages its own Python environment separately from the system. Open Thonny, go to Tools > Manage packages, and search for the library you want. Thonny installs it into its own space without triggering the error.

An App Will Not Install

  1. Always run sudo apt update first. If your package list is more than a few days old, apt may look for a package version that no longer exists and fail with a confusing error. Refresh the list first, then retry.
  2. Search for the correct package name. Package names are case-sensitive and sometimes use hyphens where you might expect underscores. Use the search command below to find matching packages.
  3. Check your internet connection. Run the ping command shown earlier in this chapter to confirm you are online. If there is no response, fix your network first.
apt-cache search image viewer

Searches the local package catalogue for any package whose name or description contains the words "image viewer". This is useful when you know what kind of software you want but are not sure of the exact package name. No internet connection is needed — it searches the already-downloaded list. Replace the search words with whatever you are looking for.

Backing Up Your Files

The simplest backup is to copy your important files to a USB drive or to your main computer. For whole-system backups — a complete snapshot of everything on the card — you have two practical options.

Copying Files to a USB Drive

First, plug a USB drive into any of the Pi's USB ports. It will appear in the file manager automatically. Then, to copy your documents folder to it from the terminal, use:

cp -r /home/yourname/Documents /media/yourname/MYUSBDRIVE/

cp is the copy command. The -r flag means "recursive" — it copies a folder and everything inside it, including any sub-folders. Replace yourname with your actual username (the name you created when you set up the Pi). Replace MYUSBDRIVE with the actual name of your USB drive, which you can see in the file manager when you plug it in. The path /media/yourname/MYUSBDRIVE/ is where Raspberry Pi OS automatically makes USB drives accessible.

Tip: To find out your exact username, type whoami in the terminal and press Enter. The Pi will print your username.

Whole-Card Image Backup (from your main computer)

The most thorough backup is a complete image of the entire microSD card, made from your main computer. This captures the operating system, all installed programs, and all your files — so you can restore everything exactly as it was if the card ever fails. The right tool depends on your computer's operating system, but the idea is the same on all three.

  1. Shut down the Pi cleanly (Raspberry Pi menu > Shutdown), wait for the green LED to stop flashing, then remove the microSD card.
  2. Insert the card into a USB card reader (or your computer's built-in SD slot) and plug it into your computer.
  3. Make the image with the tool for your operating system:
    • Windows: download and install Win32 Disk Imager (free, from sourceforge.net/projects/win32diskimager). Open it, choose an image file name and location to save to (e.g. pi-backup-2025-06.img on your desktop or an external drive), select the correct drive letter for your microSD card, then click Read.
    • macOS: open Terminal, run diskutil list to identify the card's disk (e.g. /dev/disk4), then run sudo dd if=/dev/diskN of=~/pi-backup-2025-06.img bs=4m (replace diskN with the right number).
    • Linux: open a terminal, run lsblk to identify the card (e.g. /dev/sdb), then run sudo dd if=/dev/sdX of=~/pi-backup-2025-06.img bs=4M status=progress (replace sdX with the right letter).
  4. Wait for the read operation to complete. The result is a single .img file that is an exact copy of your card.
  5. Store this .img file somewhere safe — an external hard drive or cloud storage. If your Pi's card ever fails, you can write this image back to a new card to restore everything: with Win32 Disk Imager's Write button on Windows, the same dd command with if and of swapped on macOS or Linux, or Raspberry Pi Imager's "Use custom" option on any operating system.
Careful: Whichever tool you use, make absolutely sure you select the correct microSD card. Choosing the wrong drive — the wrong drive letter in Win32 Disk Imager, or the wrong /dev/disk in a dd command — can overwrite or destroy data on a different disk. The dd command in particular is unforgiving, so double-check the device name before you press Enter.
Note: The .img backup file will be the same size as your microSD card (e.g. 64 GB). Make sure the destination has enough free space.

When a Clean Re-Flash Is the Fastest Fix

Experienced Raspberry Pi users have learnt that re-flashing the card — wiping it and starting fresh — is often the fastest solution to a stubbornly misbehaving Pi. Do not be afraid of it. Here is why it is not as drastic as it sounds:

  • It is free and takes about 10 minutes using Raspberry Pi Imager.
  • Your personal files are easy to back up first — just copy the contents of /home/yourname/ to a USB drive or your main computer before you re-flash.
  • A fresh system has no accumulated clutter, broken configurations, or partial updates — it is a clean slate.
  • Raspberry Pi Imager lets you pre-configure your username, password, Wi-Fi credentials, and SSH settings before writing, so the re-flashed Pi comes up connected and ready to use.

If you have spent more than an hour trying to fix a problem and are going in circles, take a step back, back up your files, and re-flash. You will almost certainly solve the problem in less time than you have already spent on it, and you will feel a satisfying sense of a fresh start.

Note: Re-flashing is not a defeat. It is a professional technique. Even experienced Linux administrators re-image systems to fix stubborn problems. The difference between a beginner and an expert is often just knowing when to take this shortcut.

Key terms

  • apt — the package manager for Raspberry Pi OS; it installs, updates, and removes software.
  • Throttling — the processor deliberately running slower than normal to avoid overheating or to cope with insufficient power.
  • Undervoltage — when the Pi is not receiving enough electrical voltage, usually due to a weak power supply or poor-quality cable.
  • vcgencmd — a Raspberry Pi-specific command-line tool for querying hardware status, including temperature and throttling.
  • journalctl — the command for reading the system journal (log) on Raspberry Pi OS and other modern Linux systems.
  • dmesg — displays messages from the Linux kernel, especially those generated during startup.
  • SSH (Secure Shell) — a method of remotely controlling a computer's terminal over a network using an encrypted connection.
  • Virtual environment (venv) — a self-contained Python installation that is separate from the system Python, making it safe to install any libraries without risk of breaking the OS.
  • externally-managed-environment — the Bookworm-era protection that prevents pip from installing directly into the system Python; solved by using a venv, apt, or Thonny.
  • ACT LED — the green activity LED on the Pi board; irregular flashing means the microSD card is being read or written.
  • PWR LED — the red power LED on the Pi board; solid on means power is good; flickering or off means a power problem.
  • Re-flashing — erasing a microSD card and writing a fresh operating system image to it; the fastest fix for many boot problems.
  • df -h — a command that shows how much disk space is used and free on each storage device, in human-readable sizes.
  • htop — an interactive terminal program that shows a live view of CPU and memory usage for every process running on the Pi.
  • raspi-config — a menu-driven tool built into Raspberry Pi OS for changing system settings such as the hostname, Wi-Fi country, and enabled interfaces.
  • Win32 Disk Imager — a free Windows program that can read an entire microSD card into a single backup image file, and write that image back to a card to restore it. On macOS and Linux the equivalent is the built-in dd command (or Raspberry Pi Imager's "Use custom" option, which works on any operating system).
  • Boot error code — a repeating pattern of green LED flashes during startup that points to a specific hardware or software problem; almost always fixed by re-flashing the card.

Chapter summary

  • Run sudo apt update && sudo apt full-upgrade -y weekly to keep your Pi secure and up to date.
  • Use vcgencmd measure_temp to check temperature and vcgencmd get_throttled to check for throttling; a result of 0x0 means all is well.
  • The yellow lightning-bolt icon on the desktop means undervoltage — always use the included 27 W power supply, not a phone charger.
  • Check free disk space with df -h and clean up with sudo apt autoremove -y && sudo apt clean.
  • Use htop to see which programs are consuming the most CPU or memory when the Pi feels slow.
  • The red LED shows power status; the green LED shows microSD card activity — a frozen green LED or a regular blink pattern during boot points to a card problem.
  • A blank screen is most often caused by the wrong micro-HDMI port, the wrong monitor input, or a loose cable — not a broken Pi.
  • No Wi-Fi almost always means the Wi-Fi country has not been set; fix it in Raspberry Pi Configuration under Localisation, or with sudo raspi-config.
  • The "externally-managed-environment" pip error is intentional; use apt install python3-packagename, a virtual environment, or Thonny instead.
  • Always shut down cleanly to protect the microSD card from corruption; the physical power button on the Pi 5 triggers a safe shutdown.
  • Make a complete image backup of your microSD card from your main computer — Win32 Disk Imager on Windows, the dd command on macOS or Linux — and store it somewhere safe.
  • Re-flashing the microSD card with Raspberry Pi Imager is free, takes ten minutes, and fixes the vast majority of stubborn problems — back up your files first, then do not hesitate.
