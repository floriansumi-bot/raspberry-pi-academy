Your Raspberry Pi holds everything — programs, settings, photos, scripts — as files organised into folders. In this chapter you will learn to create, view, copy, move and delete files confidently from the terminal, explore the important folders that make up your Pi's filing system, and then unravel one of Linux's most important ideas: the permission system that decides who is allowed to read, change or run each file. By the end you will know exactly what that cryptic drwxr-xr-x string means, and why your Pi sometimes asks "are you sure you're allowed to do that?"

The Filing Cabinet in Your Pi

Think of your Pi's storage as a giant filing cabinet. At the very top is a single folder called the root of the filesystem, written as a lone forward-slash /. Every other folder and file lives somewhere inside that root, connected in a tree of branches — similar to the folder tree you see in Windows Explorer, just with different names. When you open a terminal you land in your home folder, which is /home/pi (assuming your username is pi, the default on Raspberry Pi OS).

In plain words: A filesystem is just the organised layout of all files and folders on your storage card — the same idea as the folders you see in Windows, just with a forward-slash at the top instead of a drive letter like C:\.

You already met the cd (change directory) and ls (list) commands in Chapter 6. This chapter builds on those foundations.

Important System Folders

Linux uses a standard set of top-level folders that every Raspberry Pi shares. You do not need to memorise all of them, but knowing the main ones prevents confusion when commands refer to them.

Note: On Raspberry Pi OS Bookworm the boot configuration file lives at /boot/firmware/config.txt (not the older location /boot/config.txt). If you ever need to tweak the Pi's hardware settings, that is the right file to edit with sudo nano /boot/firmware/config.txt.

Editing Text Files with nano

The terminal text editor that comes pre-installed on Raspberry Pi OS and is easiest for beginners is called nano. It works entirely inside the terminal window — no mouse needed — and shows its most important keyboard shortcuts along the bottom of the screen at all times.

Opening or Creating a File

To open an existing file, or to create a new one if it does not exist yet, type nano followed by the filename:

nano mynotes.txt
Opens mynotes.txt in the nano editor. If the file does not exist yet, nano creates a blank one for you. The file is not actually saved to disk until you explicitly save it.

Once inside nano, you can type normally. The cursor moves with your arrow keys. The very bottom of the screen shows a list of shortcuts — the ^ symbol means the Ctrl key.

The Essential nano Shortcuts

Shortcut What it does
Ctrl + OWrite Out (save). nano asks you to confirm the filename — just press Enter to accept.
Enter (after Ctrl-O)Confirms the filename and writes the file to disk.
Ctrl + XExit nano. If you have unsaved changes, nano asks whether to save them first.
Ctrl + KCut the current line (stores it in a clipboard).
Ctrl + UPaste the cut line back.
Ctrl + WSearch (Where is?). Type a word and press Enter to find it.

Tip: The workflow to remember is: type your text → Ctrl-O → Enter → Ctrl-X. That is "save then quit". You will do this hundreds of times.

A Quick Practice Run

  1. Open a terminal and type nano hello.txt then press Enter.
  2. Type a sentence, for example: Hello from my Raspberry Pi!
  3. Press Ctrl + O. A prompt appears at the bottom asking "File Name to Write: hello.txt".
  4. Press Enter to confirm. You will see "[ Wrote 1 line ]" at the bottom.
  5. Press Ctrl + X to exit back to the normal terminal prompt.
  6. Type ls and you will see hello.txt is now in your folder.

Viewing Files Without Editing Them

Sometimes you just want to read a file, not change it. Linux gives you several commands for this, each suited to different situations.

cat — Print the Whole File

cat hello.txt
Prints every line of hello.txt straight to the screen. "cat" is short for "concatenate" — it was originally designed to join files together, but it is most commonly used to quickly view short files.
Tip: cat is best for short files. If the file is hundreds of lines long, the text will scroll past faster than you can read it. Use less instead.

less — Scroll Through a Long File

less /etc/os-release
Opens the file /etc/os-release (which contains information about the operating system version) in a scrollable viewer. Use the arrow keys or Page Up / Page Down to scroll. Press Q to quit and return to the terminal.
In plain words: less is like a reading mode for the terminal — the file stays still on screen until you choose to scroll or quit. The name is a tongue-in-cheek joke: an older tool was called more, and less can do more than more.

head and tail — See the Beginning or End

head -n 10 /etc/os-release
tail -n 10 /etc/os-release
Line 1: Shows only the first 10 lines of the file. The -n 10 part means "10 lines" — you can change the number to whatever you need.
Line 2: Shows only the last 10 lines of the file. This is especially useful for log files, where the most recent events appear at the bottom.
Tip: If something goes wrong and you want to check the system log, the best command on Raspberry Pi OS Bookworm is journalctl -n 50 — this shows the last 50 log entries from the system journal. (Older guides may say tail /var/log/syslog; that file only exists if you have installed extra logging software.)

Identifying a File's Type

On Linux, file extensions like .txt are just a naming convention — the system does not rely on them. If you are ever unsure what kind of file something is, use the file command:

file hello.txt
file /bin/ls
Line 1: Analyses hello.txt and reports something like "ASCII text" — confirming it is a plain text file you can read safely.
Line 2: Analyses the ls program and reports it as an "ELF 64-bit LSB executable" — a compiled program, not a text file. You would never try to read this with cat.

Creating Empty Files with touch

Sometimes you want to create a blank file without opening an editor — for example to mark a placeholder in a folder or to quickly test a command. The touch command does exactly this:

touch myfile.txt
Creates an empty file called myfile.txt in the current folder. If the file already exists, touch simply updates its "last modified" timestamp without changing its contents. The file is harmless and can be deleted any time.

Copying, Moving, Renaming and Deleting Files

Copying Files — cp

cp hello.txt hello_backup.txt
Makes an exact copy of hello.txt and calls the copy hello_backup.txt. Both files now exist side by side.

To copy a file into a different folder:

cp hello.txt Documents/hello.txt
Copies hello.txt into your Documents folder. The original file stays where it is.

To copy an entire folder and everything inside it, add the -r flag (which means "recursive" — go into every sub-folder too):

cp -r myproject myproject_backup
Copies the folder myproject and all its contents into a new folder called myproject_backup.

Moving and Renaming — mv

The mv command does double duty: it both moves a file to a new location and renames it. Linux treats these as the same action — a rename is simply moving a file to the same folder but with a new name.

mv hello.txt greetings.txt
Renames hello.txt to greetings.txt. The file itself does not move — only its name changes.
mv greetings.txt Documents/greetings.txt
Moves greetings.txt into the Documents folder. It disappears from the current folder.
Careful: mv does not ask for confirmation. If you move a file to a location where another file with the same name already exists, the existing file is silently overwritten and cannot be recovered. Double-check your target path before pressing Enter.

Deleting Files — rm

rm hello_backup.txt
Permanently deletes hello_backup.txt. There is no Recycle Bin on the Linux command line — once deleted, the file is gone.
Careful: The Linux terminal has no undo and no Recycle Bin. Files deleted with rm are gone immediately and permanently. Always double-check the filename before pressing Enter. As a beginner, consider making copies of important files before experimenting.

To delete a folder and everything inside it:

rm -r myproject_backup
Deletes the myproject_backup folder and every file and sub-folder inside it. The -r flag means "recursive" — without it, rm refuses to delete a folder.
Careful: Never type rm -rf / or rm -rf * in your home folder. The -f flag means "force" and skips all warnings. Combined with a wide pattern, this can erase your entire system. If you ever see instructions online asking you to run a command like that, stop and ask someone you trust first.

Creating Folders — mkdir

mkdir myprojects
mkdir -p myprojects/python/lesson1
Line 1: Creates a new folder called myprojects inside the current directory.
Line 2: Creates the full path myprojects/python/lesson1 in one go, even if none of those folders exist yet. The -p flag means "make parent folders as needed".

Finding Files with find

As your Pi accumulates files it becomes harder to remember exactly where something is. The find command searches for files and folders matching a pattern.

find ~ -name "hello.txt"
Searches your entire home folder (the ~ shortcut) for anything named exactly hello.txt. The result is the full path to every matching file, for example /home/pi/hello.txt.
find ~ -name "*.txt"
Searches your home folder for every file whose name ends with .txt. The quotes around "*.txt" are important — without them the shell might expand the * before find sees it, giving unexpected results.
find ~ -name "*.py" -type f
Searches for files (not folders) ending in .py (Python scripts). The -type f part means "only match regular files", which stops find from listing folder names that happen to end in .py.
Tip: find can be slow if you search the entire system starting from /. Narrow the search by starting from your home folder (~) or a specific sub-folder whenever possible.

Using Wildcards Safely

In plain words: A wildcard is a special character that stands in for "anything". The most common one is the asterisk *, which matches any number of any characters in a filename.

Wildcards let you work with many files at once without typing each name:

ls *.txt
cp *.txt Documents/
rm *.log
Line 1: Lists every file in the current folder whose name ends with .txt.
Line 2: Copies all .txt files into your Documents folder.
Line 3: Deletes every file whose name ends with .log.
Careful: Always run ls *.log (or whatever pattern you plan to use) before running rm *.log. This way you can see exactly which files match the pattern before you commit to deleting them.

Hidden Files — Dotfiles

In Linux, any file or folder whose name starts with a dot (.) is hidden. These are called dotfiles, and they usually store personal settings and configuration for programs. They are hidden simply to keep your home folder looking tidy — there is nothing secret about them.

A plain ls does not show hidden files. To see them:

ls -a
ls -la
Line 1: The -a flag means "all" — lists every file including hidden ones. You will see entries like .bashrc, .profile, and the special entries . (the current folder itself) and .. (the parent folder).
Line 2: Combines -l (long listing with details) and -a (all files). This is the most complete picture of a folder's contents.
Note: The file .bashrc in your home folder is one of the most important dotfiles — it runs automatically every time you open a new terminal and is where you can add your own shortcuts and settings. You will meet it again in the scripting chapter.

Symbolic Links — Shortcuts on the Command Line

In plain words: A symbolic link (or symlink) is exactly like a Windows shortcut — it is a tiny file that points to another file or folder somewhere else. When you open or run the symlink, the system automatically follows it to the real file.

You will see symlinks in ls -l output because they show as type l (lowercase L) at the start of the permission string, like this:

lrwxrwxrwx 1 pi pi 20 Jun 15 10:30 myscript -> /home/pi/scripts/myscript.sh
This is sample output from ls -l, not a command to type. The l at the start shows it is a symlink. The arrow (->) shows where it points: typing ./myscript will actually run /home/pi/scripts/myscript.sh.

To create your own symlink:

ln -s /home/pi/scripts/myscript.sh ~/myscript
Creates a symlink called myscript in your home folder that points to the real file at /home/pi/scripts/myscript.sh. The -s flag means "symbolic" — without it you would create a different (harder to manage) type of link.

Understanding Permissions

Every file and folder on your Pi has a set of permissions — rules that say who is allowed to read it, change it, or run it as a program. This is how Linux keeps your personal files private and prevents one program from accidentally (or maliciously) damaging another.

Users and Groups

In plain words: A user is an account on the computer — like your pi account. A group is a named collection of users who share certain permissions, for example a group called audio for everyone allowed to use the sound hardware.

Every file has three categories of people its permissions apply to:

  • Owner — the specific user who owns the file (usually whoever created it).
  • Group — a named group of users. The file's group might be pi, audio, video, and so on.
  • Others — everyone else on the system who is not the owner and not in the group.

Read, Write and Execute

For each of those three categories, there are three possible permissions:

Permission Letter For a file For a folder
ReadrYou can view/open the file's contents.You can list what is inside the folder.
WritewYou can change or delete the file.You can add, rename or delete files inside.
ExecutexYou can run the file as a program or script.You can enter (cd into) the folder.

When a permission is absent, a dash - appears in its place. So rw- means "read and write, but not execute".

Reading an ls -l Line

Run ls -l in any folder and you will see something like this:

ls -l
Shows a detailed listing of files in the current folder, one file per line, with permissions, owner, size and date.

A typical output line looks like this (this is example output, not a command to type):

-rw-r--r-- 1 pi pi 1024 Jun 15 10:30 hello.txt
This single line describes the file hello.txt. Every part has a specific meaning — the diagram below decodes it field by field.

The Permission String in Detail

Let us decode -rw-r--r-- character by character:

Position Character Meaning
1-File type: - = ordinary file, d = folder (directory), l = symlink (a shortcut)
2rOwner can read the file
3wOwner can write (change) the file
4-Owner cannot execute the file (dash = permission absent)
5rGroup members can read the file
6-Group members cannot write
7-Group members cannot execute
8rOthers (everyone else) can read the file
9-Others cannot write
10-Others cannot execute

Changing Permissions with chmod

In plain words: chmod stands for "change mode" — "mode" is the old Unix word for permissions. It lets you add or remove read, write and execute permissions from a file.

The Symbolic (Friendly) Form

The easiest way to use chmod is with letters and symbols. The format is: who + action + permission.

LetterStands for
uUser (the owner)
gGroup
oOthers
aAll three (u + g + o)
+Add a permission
-Remove a permission
=Set exactly these permissions (replacing whatever was there)

Here are the most common things you will do:

chmod +x myscript.sh
chmod -x myscript.sh
chmod u+x myscript.sh
chmod go-w hello.txt
chmod a+r photo.jpg
Line 1: Adds the execute permission for everyone — makes myscript.sh runnable as a program. This is the command you will use most often when you write your own scripts.
Line 2: Removes the execute permission from everyone.
Line 3: Adds execute permission for the owner only (leaving group and others unchanged).
Line 4: Removes write permission from the group (g) and from others (o), so only the owner can change the file.
Line 5: Adds read permission for absolutely everyone.

The Numeric (Octal) Form

You will sometimes see permissions written as three digits, for example 755 or 644. This is the older "numeric" or "octal" notation. Each digit is a sum of three values: 4 = read, 2 = write, 1 = execute. You add the values for each group:

NumberMeaningEquivalent
74+2+1 = read, write, executerwx
64+2+0 = read and writerw-
54+0+1 = read and executer-x
44+0+0 = read onlyr--
0no permissions at all---

So chmod 755 myscript.sh means: owner gets 7 (rwx), group gets 5 (r-x), others get 5 (r-x). The owner can read, write and run it; everyone else can only read and run it.

chmod 755 myscript.sh
chmod 644 hello.txt
Line 1: Sets the classic permissions for an executable script — owner has full control (read, write, execute), everyone else can read and run but not modify.
Line 2: Sets the classic permissions for a data file — owner can read and write, everyone else can only read.
Tip: As a beginner, stick with the symbolic form (chmod +x) — it is much easier to read and remember. The numeric form is handy to recognise when you see it in tutorials online.

Checking Detailed File Information with stat

ls -l gives you a quick summary, but if you want to see every detail about a file — its exact size in bytes, its precise timestamps, and all its permissions in one place — use the stat command:

stat hello.txt
Prints a detailed report about hello.txt including: its full size in bytes, the date it was created, last read, and last changed, and its permissions shown both in the rwx form and as a numeric (octal) code. This is especially useful when troubleshooting "why can't I open this file?" problems.

Changing Ownership with chown

In plain words: chown stands for "change owner". It transfers ownership of a file from one user (or group) to another.
sudo chown pi hello.txt
sudo chown pi:pi hello.txt
Line 1: Makes the user pi the owner of hello.txt. The sudo at the front is needed because changing ownership is a privileged action (explained in the next section).
Line 2: Makes pi both the owner and the group of the file. The format is user:group.

You will rarely need chown in everyday use. The most common situation is when a file is created by a system command that runs as a different user, and you want to reclaim ownership so you can edit it freely.

sudo, Root, and Why Your Password Is Asked

You have seen the word sudo appear in several commands. Now it is time to understand exactly what it means.

The Root User

Every Linux system has a special all-powerful user account called root (also sometimes called the superuser). Root has no restrictions — it can read, write, delete or change any file on the entire system, including system files that keep the Pi running.

To protect the system from accidents, you do not normally log in as root. Instead, you log in as your ordinary pi account, which has limited powers. If you try to read or modify a system file as pi, Linux politely refuses with a "Permission denied" message.

What sudo Does

In plain words: sudo stands for "superuser do". Put it at the start of any command, and that command runs with full root powers — just for that one command. Then your account returns to being a normal user.
sudo apt update
Runs the apt update command (which refreshes the list of available software updates) with root privileges. Without sudo, this would fail with a "Permission denied" error because updating software requires writing to system folders that ordinary users cannot touch.

When you type a command beginning with sudo, the terminal asks for your own password (the password for the pi account, not a root password). After you enter it correctly, sudo remembers for a few minutes, so you will not be asked again for every command in a row.

Note: When you type your password at a sudo prompt, nothing appears on the screen — no dots, no asterisks. This is intentional: it prevents someone nearby from seeing how long your password is. Just type it and press Enter.

The Difference Between pi and root

pi (your normal account)root (superuser)
Can read your own filesYesYes
Can read other users' private filesNoYes
Can install softwareNo (needs sudo)Yes
Can edit system filesNo (needs sudo)Yes
Can accidentally break the systemUnlikelyVery easily
Careful: Use sudo only when you genuinely need it — for installing software, editing system configuration files, or working with hardware. Do not get into the habit of putting sudo in front of everything. Running everyday commands as root is risky because a typo can do far more damage than it would as a normal user.

Switching to the Root Shell (and Why to Avoid It)

It is possible to open a shell that runs entirely as root with sudo -i or sudo su. Your prompt changes from a $ to a #, which is the traditional signal that you are operating as root. Experienced administrators sometimes do this for a batch of system tasks, but as a beginner it is safer to use sudo one command at a time and then return to your safe pi account.

Note: The list of users who are allowed to use sudo is controlled by a special configuration file at /etc/sudoers. The default pi user on Raspberry Pi OS is already in that list, which is why sudo works for you out of the box. You should never edit this file with a plain text editor — always use sudo visudo, which checks for mistakes before saving.

Making a Script Executable

In later chapters you will write your own shell scripts — text files full of commands that run one after another, like a recipe. Before the Pi will actually run a script, you need to mark it as executable. Here is a preview of that process:

  1. Create a simple script file: 
    nano greet.sh
    Opens a new file called greet.sh in nano. The .sh extension is the convention for shell scripts, though Linux does not strictly require it.
  2. Type these two lines inside nano: 
    #!/bin/bash
echo "Hello from my Pi script!"
    Line 1: This special first line is called a shebang (or hashbang). It tells the Pi which program should interpret the script — in this case /bin/bash, the standard command shell. It must always be the very first line of the file, with no blank line before it.
    Line 2: The echo command prints text to the screen. When you run the script, you will see this message.
    Save with Ctrl+O, then Enter, then exit with Ctrl+X.
  3. Check the file's current permissions: 
    ls -l greet.sh
    Shows the permissions for greet.sh. You will see something like -rw-r--r-- — no execute permission yet, so the Pi will not run it as a program.
  4. Grant execute permission: 
    chmod +x greet.sh
    Adds the execute bit for everyone. Now the Pi knows this file is a runnable program. If you run ls -l greet.sh again you will see -rwxr-xr-x.
  5. Run the script: 
    ./greet.sh
    Runs the script. The ./ at the start means "look in the current folder" — you need this because the Pi does not automatically look in the current folder for programs to run (a safety measure to prevent accidentally running a malicious file placed in the current directory). You should see Hello from my Pi script! printed on screen.
Tip: The ./ prefix is something beginners often forget. If you type just greet.sh without the dot-slash, the terminal will say "command not found" even though the file is right there. Always use ./scriptname.sh to run a script in the current folder.

Putting It All Together — A Practical Workflow

Here is a short walkthrough that ties together everything in this chapter. Imagine you want to create a small project folder, write a note, protect it, and back it up.

  1. Create a project folder: 
    mkdir ~/myproject
    Creates a folder called myproject directly inside your home folder. The ~ is a shortcut that always means "your home folder" — on a default Pi setup that is /home/pi.
  2. Move into it and create a notes file: 
    cd ~/myproject
nano notes.txt
    Line 1: Changes into your new myproject folder.
    Line 2: Opens a new notes file in nano. Type something, save with Ctrl+O and exit with Ctrl+X.
  3. Check what you have: 
    ls -la
    Shows all files including hidden ones, with full permission details. You will see notes.txt listed with permissions like -rw-r--r--.
  4. Make the notes file readable only by you: 
    chmod go-r notes.txt
ls -l notes.txt
    Line 1: Removes the read permission from the group (g) and from others (o). Now only the owner (pi) can read this file.
    Line 2: Confirms the change — you should now see -rw------- in the permissions column.
  5. Back up the whole folder: 
    cp -r ~/myproject ~/myproject_backup
    Makes a complete copy of your project folder (and everything inside it) with the name myproject_backup in your home folder.
  6. Verify the backup exists and check its contents: 
    ls ~/myproject_backup
    Lists the contents of your backup folder to confirm that notes.txt (and any other files) made it across safely.

Key terms

  • Filesystem — the organised layout of all files and folders on your storage card; a single tree rooted at /.
  • Home folder — your personal folder, /home/pi on a default Pi setup; the folder you land in when you open a terminal.
  • nano — a simple, beginner-friendly text editor that runs inside the terminal; keyboard shortcuts are shown along the bottom of the screen.
  • cat — a command that prints the entire contents of a file to the screen.
  • less — a command that opens a file in a scrollable viewer; press Q to quit.
  • head / tail — commands that show only the first or last few lines of a file.
  • file — a command that identifies what type of data a file contains, regardless of its extension.
  • touch — a command that creates an empty file, or updates the timestamp of an existing file without changing its contents.
  • cp — the copy command; use -r to copy entire folders.
  • mv — the move/rename command; there is no undo.
  • rm — the delete command; files deleted with rm are gone permanently with no Recycle Bin.
  • mkdir — creates a new folder; use -p to create several nested folders at once.
  • find — searches for files and folders matching a name pattern, starting from a folder you specify.
  • Wildcard (*) — a special character meaning "any number of any characters", used to match multiple filenames at once (e.g. *.txt).
  • Dotfile — a file or folder whose name starts with a dot, making it hidden from ordinary ls listings; usually stores program settings.
  • Symbolic link (symlink) — a file that acts as a shortcut pointing to another file or folder elsewhere; shown as type l in ls -l output.
  • Permission — a rule controlling who can read (r), write (w), or execute (x) a file.
  • Owner — the specific user account that owns a file (usually whoever created it).
  • Group — a named collection of user accounts that share a set of permissions on files assigned to that group.
  • chmod — the command to change a file's permissions; symbolic form (chmod +x) is easiest, numeric form (e.g. chmod 755) is also common.
  • chown — the command to change which user and group owns a file.
  • stat — a command that shows full details about a file including exact timestamps, size and permissions.
  • root — the all-powerful system administrator account on Linux; it has no permission restrictions and can do anything on the system.
  • sudo — a prefix that runs a single command with root (superuser) privileges, then immediately returns to your normal user account.
  • Shebang — the special first line of a script (#!/bin/bash) that tells the system which interpreter should run the file.
  • Executable — a file that has been given the execute (x) permission, meaning the system is allowed to run it as a program.

Chapter summary

  • Your Pi's files are arranged in a single tree starting at /; your personal files live in /home/pi, and system files live in /etc, /usr, /var and other protected folders.
  • nano is the beginner's terminal text editor: open with nano filename, save with Ctrl+O then Enter, and exit with Ctrl+X.
  • Use cat for short files, less for long ones (press Q to quit), and head/tail to see just the start or end; use file to find out what type of data a file contains.
  • touch creates an empty file; mkdir creates a folder; use mkdir -p to create a chain of nested folders in one step.
  • cp copies, mv moves or renames, and rm permanently deletes — there is no undo or Recycle Bin for rm.
  • Use find ~ -name "*.txt" to search your home folder for files matching a pattern.
  • Wildcards like *.txt match multiple files; always preview with ls before using a wildcard with rm.
  • Hidden files (dotfiles) start with a dot and are only shown when you add -a to ls; symlinks (type l) act as shortcuts to another file.
  • Every file has three permission groups — owner, group, others — and three permission types: read (r), write (w), execute (x); ls -l shows the full 10-character string.
  • chmod +x file makes a file executable; chmod go-r file removes read access from group and others; chmod 755 is the classic permission for a shared script.
  • root is the all-powerful system account; sudo lets you run one command with root powers without switching accounts permanently — use it only when necessary.
  • Mark a script executable with chmod +x and run it with ./scriptname.sh — the ./ prefix is required.
