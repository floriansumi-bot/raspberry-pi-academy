Bats and dolphins find their way in the dark by sending out a squeak and timing the echo that bounces back. In this chapter you will give your Pi the very same superpower using a cheap ultrasonic sensor, then turn it into a car parking assistant — a row of green, amber and red lights plus a buzzer that beeps faster the closer you get. Along the way you will learn one of Python's biggest ideas: classes and objects, write your own little helper class, build functions that return values, and meet the single most important safety circuit in this whole course — the voltage divider that stops a 5 volt sensor from frying your 3.3 volt Pi.

What You'll Build & Learn

By the end of this chapter you will have a working parking assistant: point the sensor at a wall (or have a friend hold a book in front of it), and as the object moves closer the lights change from green to amber to red while a buzzer beeps faster and faster — exactly like the reversing aid in a modern car.

To get there you will learn these named fundamentals:

Python fundamentals

  • Classes & objects — the idea that a "thing" in your program can bundle together its own data and its own actions. The sensor itself is an object; you will also write your own small class, called ParkingZone, to keep your code tidy.
  • Functions that return values — functions that hand a result back to the line that called them, using the return keyword, so you can use that result elsewhere.
  • A little maths — converting metres to centimetres, round()ing numbers neatly, and using number ranges (is the distance between 20 and 40 cm?) to decide what should happen.
  • Mapping a measurement to a behaviour — turning a continuous reading (distance) into a small set of clear states (safe / caution / stop).

Electronics fundamentals

  • The HC-SR04 ultrasonic distance sensor — how it fires a pulse of sound and times the echo, and how gpiozero's DistanceSensor object turns that into a distance in metres.
  • The voltage divider — the critical two-resistor circuit that drops the sensor's 5 V ECHO signal down to a Pi-safe 3.3 V. Skipping this can permanently damage your Pi, so we give it a whole section of its own.
  • Driving several outputs at once — three LEDs and a buzzer working together, each LED with its own resistor.
In plain words: Ultrasonic means sound that is too high-pitched for humans to hear (above about 20,000 Hz). The HC-SR04 chirps at around 40,000 Hz — silent to you, but a perfect ruler for measuring distance.

Meet Classes & Objects

You have actually been using objects since Chapter 12 without us making a fuss about it. Every time you wrote led = LED(17), you created an object. Let's now name the idea properly, because it is one of the most powerful in all of programming.

In plain words: A class is a blueprint. An object is one real thing built from that blueprint. LED is the class (the blueprint for "any LED"); led = LED(17) builds one specific object — the LED on pin 17. From a single class you can make as many objects as you like.

Think of a class as a cookie cutter and objects as the cookies. The cutter (class) defines the shape; each cookie (object) is a separate, real cookie you can decorate differently.

An object bundles together two things:

  • Data it remembers about itself — called attributes. For an LED, whether it is currently lit (led.is_lit).
  • Actions it can perform — called methods. For an LED, led.on(), led.off(), led.blink().

You reach an object's attributes and methods with a full stop (a "dot"): led.on() means "the on action belonging to led". The sensor we build today is an object too — we will ask it sensor.distance (an attribute) to find out how far away something is.

Writing your own class — a tiny first example

Before we touch any wiring, let's write a class from scratch so the idea sinks in. Open Thonny and type this small program. It models a simple Counter — something that remembers a number and can count up.

class Counter:
    def __init__(self, start=0):
        self.count = start

    def increase(self):
        self.count = self.count + 1
        return self.count

# Make two separate counter objects from the one blueprint
goals = Counter()
score = Counter(start=10)

print(goals.increase())   # 1
print(goals.increase())   # 2
print(score.increase())   # 11
print(goals.count)        # 2 (the goals object remembers its own number)

Line 1 — class Counter:: Starts the blueprint. By convention class names begin with a capital letter (Counter, LED, DistanceSensor). Everything indented underneath belongs to the class.

Line 2 — def __init__(self, start=0):: A special method called the initialiser. Python runs it automatically the moment you build an object, to set it up. The odd-looking name is two underscores, the word init, two more underscores. self is the object being built; start=0 is an optional value the maker can pass in.

Line 3 — self.count = start: Stores a piece of data on this particular object. self.count is an attribute — each object gets its very own count, kept separate from every other object.

Line 5 — def increase(self):: Defines a method (an action the object can do). Every method's first parameter is self, which is how the method knows which object's data to work on.

Line 6 — self.count = self.count + 1: Adds one to this object's own count.

Line 7 — return self.count: Hands the new value back to whoever called the method — our first taste of a function that returns a value, covered properly in the next section.

Lines 10–11 — goals = Counter() and score = Counter(start=10): Build two completely separate objects from the same class. goals starts at 0; score starts at 10. They do not interfere with each other.

Lines 13–16: Calling goals.increase() only changes goals; score keeps its own tally. That independence is the whole point of objects.

Tip: The word self trips up every beginner. Just remember: inside a class, self always means "this particular object". You never type self when you call a method (goals.increase()), only when you define one. Python fills it in for you.

That is the whole idea. A class gathers related data and actions under one roof so your programs stay tidy as they grow. We will write a real, useful class — ParkingZone — for the project later on.

Functions That Return Values

Some functions just do something (like print(), which puts text on the screen). Others work something out and hand the answer back so you can use it. The keyword for handing an answer back is return.

In plain words: return is how a function gives you an answer. print() shows a value on screen and then it is gone; return passes a value back into your program so you can store it, test it, or pass it on.

Here is a tiny example that turns metres into centimetres and rounds the result. Type it in and run it.

def metres_to_cm(metres):
    cm = metres * 100
    return round(cm, 1)

reading = metres_to_cm(0.4267)
print(reading)            # 42.7
print(reading + 5)        # 47.7  (we can do maths with the returned value)

Line 1 — def metres_to_cm(metres):: Defines a function that takes one input, metres.

Line 2 — cm = metres * 100: There are 100 centimetres in a metre, so we multiply.

Line 3 — return round(cm, 1): round(cm, 1) rounds the number to one decimal place (42.67 → 42.7), and return sends that tidy value back. The moment Python hits return, the function ends.

Line 5 — reading = metres_to_cm(0.4267): Calls the function and captures the returned value into a variable called reading. Now reading holds 42.7.

Line 7 — print(reading + 5): Because the value was returned (not just printed inside the function), we can keep using it — here we add 5. A function that only print()ed could not do this.

Note: A function with no return hands back a special value called None, meaning "nothing". If you ever see None where you expected a number, you probably forgot a return.

How the Ultrasonic Sensor Works

The HC-SR04 is a small blue board with two silver cylinders that look like little eyes (one is a speaker, one is a microphone) and four pins: VCC, TRIG, ECHO and GND.

It measures distance just like a bat:

  1. Your Pi sends a brief electrical pulse to the TRIG (trigger) pin.
  2. The sensor chirps out a burst of ultrasound (silent to us) and starts a stopwatch.
  3. The sound travels out, bounces off whatever is in front, and comes back.
  4. When the echo returns, the sensor raises its ECHO pin HIGH for exactly as long as the round trip took.
  5. The Pi times how long ECHO stays HIGH and, knowing the speed of sound (about 343 metres per second in air), works out the distance.

Because the sound travels there and back, the Pi divides the time in half before converting it to a distance. Happily, gpiozero's DistanceSensor object does every bit of this timing maths for you — you just read sensor.distance.

Here is the simplest possible distance program — but do not wire it up or run it yet. First you must build the safety circuit in the next section, or you risk damaging your Pi.

from gpiozero import DistanceSensor
from time import sleep

sensor = DistanceSensor(echo=24, trigger=23)   # ECHO via a voltage divider!

while True:
    distance_m = sensor.distance      # an attribute of the sensor object, in metres
    print(round(distance_m * 100, 1), "cm")
    sleep(0.5)

Line 1 — from gpiozero import DistanceSensor: Imports the ready-made object that handles all the trigger/echo timing.

Line 4 — sensor = DistanceSensor(echo=24, trigger=23): Builds the sensor object. We connect ECHO to GPIO 24 (physical pin 18) and TRIG to GPIO 23 (physical pin 16). Notice we name the arguments (echo=, trigger=) so we cannot mix them up.

Line 7 — distance_m = sensor.distance: Reads the distance attribute of the sensor object. It returns a number in metres, from 0 up to 1 metre by default.

Line 8 — print(round(distance_m * 100, 1), "cm"): Multiplies by 100 to get centimetres and rounds to one decimal place before printing.

Line 9 — sleep(0.5): Waits half a second so we get a steady couple of readings per second rather than a blur.

The Critical Voltage Divider (Read This!)

Careful — this is the most important safety point in the chapter. The HC-SR04 runs on 5 volts, and its ECHO pin sends out a 5 V signal. But the Pi 5's GPIO pins are 3.3 V only and are NOT 5 V-tolerant. Connecting ECHO straight to a GPIO pin pushes 5 V into a pin that can take 3.3 V, and there is no fuse to save it — you can permanently destroy your Pi. You MUST drop the ECHO voltage with a two-resistor voltage divider first. (The TRIG pin is the other way round — the Pi sends 3.3 V out to it, which the sensor reads happily, so TRIG needs no divider.)
In plain words: A voltage divider is just two resistors in a line between the signal and ground. The voltage you want appears at the join between them. By choosing the two resistor values, you choose what fraction of the input voltage comes out — here we turn 5 V into a Pi-safe 2.94 V.

The maths — turning 5 V into 3.3 V (or less)

The voltage at the middle tap of a divider follows one simple formula:

Vout = Vin × R2 ÷ (R1 + R2)

Here R1 is the resistor between the ECHO pin and the middle tap, and R2 is the resistor between the middle tap and ground (GND). The GPIO pin connects to the middle tap. The classic gpiozero recipe uses R1 = 330 Ω and R2 = 470 Ω. Let's plug those in with Vin = 5 V:

Vout = 5 × 470 ÷ (330 + 470) = 5 × 470 ÷ 800 = 2.94 V

2.94 V is comfortably below the 3.3 V limit, yet still high enough for the Pi to read clearly as a HIGH signal. Perfect.

Tip: If you do not have 330 Ω and 470 Ω to hand, any pair with roughly a 2:3 ratio works. For example 1 kΩ (R1) + 2 kΩ (R2) gives 5 × 2000 ÷ 3000 = 3.33 V — right at the limit but commonly used. The 330 Ω/470 Ω pair is gentler, so we prefer it here.
Note: Some makers use a ready-made "logic level shifter" board instead of two resistors. That works too, but the resistor divider is cheaper, uses parts from your starter kit, and teaches you exactly what is happening — so that is what we build.

Parts & Wiring

What you need

  • A Raspberry Pi 5 running Raspberry Pi OS Bookworm
  • 1 × HC-SR04 ultrasonic distance sensor (4 pins: VCC, TRIG, ECHO, GND)
  • 1 × 330 Ω resistor (orange-orange-brown-gold) — this is R1 of the divider
  • 1 × 470 Ω resistor (yellow-violet-brown-gold) — this is R2 of the divider
  • 1 × green LED, 1 × amber/yellow LED, 1 × red LED
  • 3 × 330 Ω resistors — one in series with each LED
  • 1 × active buzzer (a small buzzer that beeps when switched on)
  • 1 × breadboard and a handful of jumper wires (male-to-male and female-to-male)
Careful — power off first. Shut your Pi down fully (Raspberry Pi menu → Shutdown), wait for the green light to go out, and unplug the power lead before touching any wires. Remember: GPIO is 3.3 V logic — never feed 5 V into a GPIO input, which is exactly why the ECHO line must go through the divider. Give every LED its own 330 Ω resistor, and only re-connect power once you have checked everything.

Tip: Build the divider first and double-check it before anything else. The easiest way to wire it on a breadboard: push ECHO into one row, put R1 between that row and an empty middle row, run a jumper from the middle row to GPIO 24, then put R2 between the middle row and the GND rail. If in any doubt, trace it against the diagram above before powering on.

Building the Parking Assistant

Now we bring everything together. The plan: read the distance many times a second, decide which "zone" the object is in, light the matching LED, and beep the buzzer at a speed that depends on how close the object is. To keep the code tidy we will write our own class, ParkingZone, that bundles a zone's name, its distance range, and which light belongs to it.

Step 1 — a class to describe each zone

First, here is the helper class on its own so you can see it clearly. It uses everything from the earlier lessons: a class, an __init__, attributes, and a method that returns a value.

class ParkingZone:
    def __init__(self, name, max_cm, led, beep_gap):
        self.name = name
        self.max_cm = max_cm
        self.led = led
        self.beep_gap = beep_gap

    def contains(self, distance_cm):
        return distance_cm <= self.max_cm

Line 1 — class ParkingZone:: Our own blueprint describing one band of distance, such as "caution".

Line 2 — def __init__(self, name, max_cm, led, beep_gap):: The initialiser takes four pieces of information for each zone: a name, the furthest distance that counts as this zone (max_cm), the led object that lights for it, and beep_gap — how long (in seconds) to pause between beeps in this zone.

Lines 3–6 — self.name = name … : Store each value on the object so it remembers them. Now every ParkingZone object carries its own name, range, LED and beep speed.

Line 8 — def contains(self, distance_cm):: A method that answers a yes/no question: is a given distance inside this zone?

Line 9 — return distance_cm <= self.max_cm: Returns True if the distance is less than or equal to this zone's upper limit, otherwise False. A function returning a True/False value like this is exactly how we map a measurement to a behaviour.

Step 2 — the full program

Open a new file in Thonny, type the whole program below, and save it as parking.py.

from gpiozero import DistanceSensor, LED, Buzzer
from time import sleep, time

# --- the sensor object (ECHO wired through the 330/470 divider!) ---
sensor = DistanceSensor(echo=24, trigger=23, max_distance=1.0)

# --- output objects ---
green = LED(17)
amber = LED(27)
red = LED(22)
buzzer = Buzzer(6)


class ParkingZone:
    def __init__(self, name, max_cm, led, beep_gap):
        self.name = name
        self.max_cm = max_cm
        self.led = led
        self.beep_gap = beep_gap

    def contains(self, distance_cm):
        return distance_cm <= self.max_cm


# Zones are checked closest-first. beep_gap of None means "no beeping".
zones = [
    ParkingZone("STOP",    10,  red,   0.1),
    ParkingZone("Close",   20,  red,   0.25),
    ParkingZone("Caution", 40,  amber, 0.6),
    ParkingZone("Safe",   100,  green, None),
]


def read_distance_cm():
    """Return the current distance in centimetres, rounded to 1 dp."""
    metres = sensor.distance
    return round(metres * 100, 1)


def pick_zone(distance_cm):
    """Return the first ParkingZone whose range contains this distance."""
    for zone in zones:
        if zone.contains(distance_cm):
            return zone
    return zones[-1]   # fall back to the 'Safe' zone


def all_lights_off():
    green.off()
    amber.off()
    red.off()


print("Parking assistant running. Press Ctrl+C to stop.")
last_beep = 0

try:
    while True:
        distance = read_distance_cm()
        zone = pick_zone(distance)

        all_lights_off()
        zone.led.on()

        print(f"{distance:5.1f} cm  ->  {zone.name}")

        if zone.beep_gap is not None:
            if time() - last_beep >= zone.beep_gap:
                buzzer.on()
                sleep(0.05)
                buzzer.off()
                last_beep = time()
        else:
            buzzer.off()

        sleep(0.05)

except KeyboardInterrupt:
    all_lights_off()
    buzzer.off()
    print("\nStopped. Lights off.")

Lines 1–2 — imports: We bring in DistanceSensor, LED and Buzzer from gpiozero, and sleep plus time from Python's time module. time() returns the current time in seconds, which we use to pace the beeps.

Line 5 — sensor = DistanceSensor(echo=24, trigger=23, max_distance=1.0): Builds the sensor object. max_distance=1.0 tells gpiozero we care about distances up to 1 metre, which keeps readings responsive.

Lines 8–11 — output objects: One LED object per light, plus a Buzzer object on GPIO 6. Each is an object created from a class — the same idea as the sensor.

Lines 14–22 — the ParkingZone class: Exactly the helper class from Step 1, pasted in. Defining it here means we can stamp out several zone objects below.

Lines 25–30 — zones = [ ... ]: A list of four ParkingZone objects, ordered closest-first. STOP (≤10 cm) beeps almost continuously; Close (≤20 cm) beeps fast; Caution (≤40 cm) beeps slowly in amber; Safe (everything else) shows green with no beep (None).

Lines 33–36 — read_distance_cm(): A function that returns a value: it reads the sensor's distance attribute (metres), converts to centimetres, rounds it, and hands it back. The triple-quoted line is a docstring describing what the function does.

Lines 39–44 — pick_zone(distance_cm): Walks through the zones from closest to furthest and returns the first one whose contains() method says yes. Because the list is ordered closest-first, the tightest matching zone always wins. If somehow none match, line 44 returns the last (Safe) zone.

Lines 47–50 — all_lights_off(): A small helper that switches all three LEDs off, so we start each loop with a clean slate before lighting just one.

Line 55 — last_beep = 0: Remembers the time of the most recent beep so we can space beeps out by each zone's beep_gap.

Line 57 — try:: Wraps the main loop so that pressing Ctrl+C runs the tidy-up code at the bottom instead of crashing.

Lines 59–60 — read & classify: Each loop we get the distance, then ask pick_zone() which zone we are in. This is the heart of mapping a measurement to a behaviour.

Lines 62–63 — all_lights_off() then zone.led.on(): Clear all lights, then light only the one belonging to the chosen zone. Notice zone.led is the LED object we stored on that zone earlier.

Line 65 — print(f"{distance:5.1f} cm -> {zone.name}"): An f-string showing the live reading. :5.1f formats the number in a tidy 5-character-wide field with one decimal place, so the column does not jump about.

Lines 67–74 — the beeping: If the zone has a beep_gap (not None), and enough time has passed since the last beep, switch the buzzer on for a brief 0.05 s click, then off, and record the time. Closer zones have a smaller beep_gap, so the beeps come faster — exactly the parking-sensor effect.

Lines 75–76 — else: buzzer.off(): In the Safe zone there is no beeping, so we make sure the buzzer is silent.

Line 78 — sleep(0.05): A short pause so the loop runs about 20 times a second — smooth and responsive without hammering the sensor.

Lines 80–83 — except KeyboardInterrupt:: When you press Ctrl+C, this runs: all lights off, buzzer off, and a friendly message. Always leaving hardware in a safe, quiet state is good manners.

Running It

  1. Double-check the divider. Before powering on, trace the ECHO line one more time: ECHO → R1 (330 Ω) → middle tap → GPIO 24, and middle tap → R2 (470 Ω) → GND. This is the step that protects your Pi.
  2. Reconnect power and let the Pi boot to the desktop.
  3. Open parking.py in Thonny and click the green Run button (or press F5).
  4. Watch the console. You should see distance readings scrolling, each labelled with its zone.
  5. Move your hand (or a book) towards the sensor. The lights should step from green to amber to red, and the buzzer should beep faster as you get closer. Pull away and it relaxes back to green.
  6. Press Ctrl+C in the console (or the red Stop button) to end the program cleanly — all lights and the buzzer switch off.
Tip: Ultrasonic sensors like a flat, solid target. A hand works, but a flat book or a wall gives steadier readings. Very soft or angled surfaces can scatter the sound and produce jumpy numbers — that is normal physics, not a bug.

Troubleshooting

Symptom Likely cause Fix
Readings are always 1.0 m (the maximum) or jump wildly ECHO not reaching GPIO 24, or the divider tap is in the wrong place Check the middle tap goes to GPIO 24, R1 is between ECHO and the tap, R2 between tap and GND. A loose jumper is the usual culprit.
No readings at all / sensor seems dead VCC not on 5 V, or GND not shared VCC must be on a 5 V pin (pin 2 or 4), and the sensor GND, divider R2 and Pi GND must all share the same ground rail.
Wrong LED lights for the distance LED wired to the wrong GPIO, or zones out of order Confirm green=17, amber=27, red=22, and that the zones list is ordered closest-first.
Buzzer is silent It's a passive buzzer, or wired backwards This project needs an active buzzer (beeps when simply switched on). Check the + leg goes to GPIO 6.
Buzzer beeps non-stop and won't pace The last_beep timing got skipped Make sure you copied the if time() - last_beep >= zone.beep_gap: line exactly.
No module named 'lgpio' The lgpio backend is missing In a terminal run sudo apt install python3-lgpio, then restart Thonny.
Careful: If your Pi behaves oddly only when the sensor is connected — random reboots, USB devices dropping out — power off immediately and re-check that ECHO is going through the divider and not straight to the GPIO pin. A 5 V signal sneaking onto a 3.3 V pin is the number-one cause of mystery faults here.

Make It Your Own

You now have a complete sensing-and-reacting machine. Here are four ways to take it further:

  • Add a fourth "danger close" tone. Give the STOP zone a different sound by switching to a TonalBuzzer (from Chapter 26) and playing a low note when very close and a high one further away.
  • Smooth the readings with a method. Add a read_average() function that takes five readings and returns their average, so a single odd bounce does not flicker the lights. (Hint: collect readings in a list and return sum(readings) / len(readings).)
  • Make the zones configurable. Because each zone is an object in a list, you can change the ranges, colours or beep speeds just by editing the zones = [ ... ] block — no other code needs to change. Try tuning it for a model car on a desk.
  • Build a "doorway counter". Point the sensor across a doorway and use the distance dropping below a threshold to count people walking past — a neat lead-in to the data logging you will do in the next chapter.
Note: The official gpiozero documentation at gpiozero.readthedocs.io has more on DistanceSensor, including when_in_range and when_out_of_range callbacks — a tidy way to react to crossings without a busy loop, building on the event style you'll meet later.

Key terms

  • Class - a blueprint that bundles related data and actions together (e.g. LED, DistanceSensor, your own ParkingZone).
  • Object - one real thing built from a class, with its own data; led = LED(17) creates an object.
  • Attribute - a piece of data stored on an object, reached with a dot (e.g. sensor.distance).
  • Method - an action an object can perform, also reached with a dot (e.g. led.on()).
  • __init__ - the initialiser method that runs automatically to set up a new object.
  • self - inside a class, refers to "this particular object".
  • return - the keyword that hands a value back from a function so it can be used elsewhere.
  • HC-SR04 - an ultrasonic distance sensor that times the echo of a 40 kHz chirp.
  • DistanceSensor - the gpiozero object for the HC-SR04; .distance gives metres (0–max_distance).
  • TRIG / ECHO - the sensor's trigger (Pi → sensor, 3.3 V, no divider) and echo (sensor → Pi, 5 V, needs a divider) pins.
  • Voltage divider - two resistors that drop a voltage; Vout = Vin × R2 ÷ (R1+R2). 330 Ω + 470 Ω turns 5 V into 2.94 V.
  • Active buzzer - a buzzer that beeps when simply switched on; safe to drive from a GPIO pin via gpiozero's Buzzer.
