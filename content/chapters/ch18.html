Your Raspberry Pi 5 can do far more than run programs you use yourself — it can serve things to other devices on your home network, acting as a tiny, always-on web server or running powerful self-hosted applications. This chapter shows you two practical paths: the quick-and-simple way with a built-in Python trick, and the modern, tidy way using Docker containers.

What Is a Web Server, Really?

When you type a web address into your browser, your browser sends a request over the network asking "Please send me that page." A web server is simply a program sitting on another computer, waiting for those requests and then sending back the web page (an HTML file) in reply. The word "server" just means "something that serves requests" — it has nothing to do with the size or power of the computer. Your Pi 5 is perfectly capable of being a web server for every device on your home Wi-Fi.

In plain words: A web server is a program that listens for browsers asking for pages and hands them back, the same way a library assistant hands you a book when you ask for one.

Every device on your home network has a local address called an IP address — a set of four numbers like 192.168.1.42. Once your Pi is running a web server, any other device on the same Wi-Fi can open a browser and visit http://192.168.1.42 to see whatever page the Pi is serving. (Finding your Pi's IP address was covered in Chapter 5; the quick reminder is to open a Terminal on the Pi and type hostname -I.)

Note: Everything in this chapter works on your home network only, until you deliberately open it to the outside world. That is the safe default — we discuss the outside internet at the end of the chapter.

Part A — Serve a Simple Web Page

There are two easy approaches. The first uses a tool that is already installed; the second installs the professional-grade web server software called Nginx. Both end with you viewing a page from another device.

Method 1: The One-Command Python Server

Python 3 is already installed on Raspberry Pi OS and includes a tiny built-in web server. It takes one command and serves every file in a folder. This is great for a quick demo or sharing files on your home network — but it is not meant to run permanently or to handle heavy traffic.

  1. Open a Terminal on your Pi.
  2. Create a test folder and move into it: 
    mkdir ~/my-website
cd ~/my-website

    mkdir ~/my-website — creates a new folder called my-website inside your home directory. The ~ is a shortcut that always means "my home folder" (usually /home/pi).

    cd ~/my-website — changes your current location to that new folder so the next commands work there.

  3. Create a simple web page: 
    nano index.html

    nano index.html — opens the Nano text editor to create a new file called index.html. A file named index.html is the conventional "home page" that web servers look for first when a visitor arrives at the address without asking for a specific file.

    Type (or paste) this into Nano:

    <!DOCTYPE html>
<html>
  <head><title>My Pi Website</title></head>
  <body>
    <h1>Hello from my Raspberry Pi 5!</h1>
    <p>This page is being served by my Pi.</p>
  </body>
</html>

    This is a minimal HTML web page. The <!DOCTYPE html> declaration tells the browser this is a modern HTML5 document. <h1> creates a large heading; <p> creates a paragraph. The browser will display both. You can write anything you like here — it is your page.

    Press Ctrl + O then Enter to save, then Ctrl + X to exit Nano.

  4. Start the web server: 
    python3 -m http.server 8080

    python3 -m http.server 8080 — tells Python 3 to run its built-in web server module (http.server) and listen on port 8080. A port is like a numbered door on your Pi — different services listen on different door numbers. The standard web port is 80, but we use 8080 here to avoid needing extra administrator permissions.

    You will see a message like Serving HTTP on 0.0.0.0 port 8080. The Terminal is now busy running the server — leave it open.

  5. On any device on your home network (phone, laptop, another computer), open a web browser and go to:

    http://<your-pi-ip>:8080

    Replace <your-pi-ip> with the actual IP address shown by hostname -I on the Pi (for example http://192.168.1.42:8080). The :8080 tells the browser which port to knock on.

    You should see your "Hello from my Raspberry Pi 5!" page.

  6. When you are done, go back to the Terminal and press Ctrl + C to stop the server.
Tip: While the server is running, look back at the Terminal — it prints a line every time a device visits the page, showing the visitor's IP address, the time, and what file was requested. This is exactly what a real web server access log looks like.

Method 2: Nginx — The Proper Web Server

Nginx (pronounced "engine-ecks") is a fast, professional web server used by millions of websites worldwide. Unlike the Python one-liner, it runs as a background service that starts automatically when your Pi boots. This is the right choice if you want a page that is always available.

In plain words: A service (also called a daemon) is a program that runs quietly in the background all the time, without needing a Terminal window open. Your Pi starts its services automatically when it boots up, so you never have to remember to start them.
  1. Open a Terminal and install Nginx: 
    sudo apt update
sudo apt install nginx -y

    sudo apt update — refreshes the list of available software packages from the internet. Always do this before installing something new to make sure you get the latest version.

    sudo apt install nginx -y — downloads and installs Nginx. The -y answers "yes" automatically to the "do you want to continue?" question, so you do not have to type it yourself.

    When the installation finishes, Nginx starts automatically and is immediately listening for web traffic.

  2. Check that it is running: 
    sudo systemctl status nginx

    sudo systemctl status nginx — asks the system service manager (systemctl) to report the current status of the Nginx service. You should see the word active (running) highlighted in green. Press Q to exit the status view.

  3. On your Pi itself, open the Chromium web browser and go to http://localhost. The word localhost always means "this computer itself". You should see the Nginx welcome page — this confirms it is working.
  4. Now replace the default page with your own. The web files Nginx serves live in /var/www/html/. Edit the default page: 
    sudo nano /var/www/html/index.html

    sudo nano /var/www/html/index.html — opens the existing index file in the Nano editor. sudo is needed because the folder is owned by the system, not your user account, and without it Nano would not be able to save your changes.

    Select all the existing text (hold Ctrl + K repeatedly to delete line by line) and replace it with your own HTML — you can use the same simple page from Method 1, or write something new. Save with Ctrl + O, Enter, then Ctrl + X.

  5. From any device on your home network, open a browser and visit:

    http://<your-pi-ip>

    No port number is needed — Nginx listens on the standard web port 80, which browsers use automatically when you just type an http:// address without a colon and number.

    Your page appears! And it will still be there the next time you visit, even after you restart the Pi.

Tip: You can drop any number of HTML files, images, or CSS files into /var/www/html/ and Nginx will serve them all. Create sub-folders for different pages and link between them with normal HTML links — you are building a real website.

Part B — The Modern Way: Docker and Containers

Serving a static HTML page is satisfying, but the real fun begins when you run complete self-hosted applications on your Pi — things like a home dashboard, a private notes app, an uptime monitor, or a media server. The cleanest way to do this in 2025 is with Docker.

What Is Docker?

In plain words: A container is like a pre-packed lunchbox for a program. It contains the program itself plus every library, tool, and configuration file it needs to run — all bundled together. You can drop the lunchbox onto any compatible computer and it just works, without touching or interfering with anything else on the machine. Docker is the most popular tool for creating and running these containers.

Before Docker, installing a server application on Linux could mean following a long list of steps, installing dozens of extra packages, editing configuration files, and hoping nothing clashed with other software already on the machine. With Docker:

  • You pull a ready-made container image from the internet (think of an image as the sealed lunchbox before you open it).
  • Docker runs it in an isolated environment — it cannot accidentally break other things on your Pi.
  • Removing an app is as simple as deleting its container and image — no leftover files scattered everywhere.
  • The same container works the same way every time, on every machine that runs Docker.

Installing Docker

The official and recommended way to install Docker on Raspberry Pi OS is to use a script provided by Docker themselves. Here is how.

Careful: The installation command below downloads a script from the internet and runs it with administrator rights on your Pi. This is only safe because it comes directly from Docker's own website, which is a trusted source. As a rule, never paste commands that run downloaded scripts unless you trust where they come from. In this case, Docker's official documentation recommends exactly this method for Linux systems.
  1. Open a Terminal and download the installer script: 
    curl -fsSL https://get.docker.com -o get-docker.sh

    curl — a command-line tool for downloading files from the internet.

    -fsSL — a combination of flags: -f makes curl fail quietly on server errors, -s hides the download progress bar, -S still shows error messages even in silent mode, and -L follows any redirects automatically.

    https://get.docker.com — the official Docker installation script URL.

    -o get-docker.sh — saves the downloaded content to a file called get-docker.sh on your Pi rather than running it immediately, so you can inspect it first if you wish.

  2. Run the installer: 
    sudo sh get-docker.sh

    sudo sh get-docker.sh — runs the downloaded script with administrator privileges (sudo). This installs the Docker Engine and all its dependencies. You will see a lot of text scrolling past — that is normal. It will take a few minutes.

  3. Add your user account to the docker group. By default, only administrators can run Docker commands. Adding yourself to the docker group means you can run them without typing sudo every time: 
    sudo usermod -aG docker $USER

    sudo usermod — modifies a user account.

    -aG docker — appends (-a) the user to the group (-G) called docker. Using -a is critical: without it, the command would replace all your existing groups instead of adding to them, which could lock you out of things.

    $USER — the shell automatically replaces this with your own username (for example pi).

Careful: Being in the docker group is effectively the same as having administrator access, because Docker can manipulate system files. Only add trusted users to this group on your Pi.
  1. This group change does not take effect in your current Terminal session. You must log out and log back in, or simply reboot: 
    sudo reboot

    sudo reboot — restarts the Pi. After it comes back on (give it about 30 seconds), open a Terminal and your user account will have Docker permissions.

  2. After rebooting, open a Terminal and verify Docker is working: 
    docker --version
docker run hello-world

    docker --version — prints the installed Docker version number. A successful output confirms Docker is installed correctly.

    docker run hello-world — downloads a tiny test container image called hello-world from the internet and runs it. The container prints a friendly success message and then exits on its own. This confirms Docker can pull images from the internet and run containers on your Pi's ARM64 processor.

    You should see a message that includes "Hello from Docker!" — Docker is ready.

Essential Docker Commands

Before running a real app, here are the key commands you will use day-to-day. These are worth bookmarking — you will reach for them often.

Command What it does
docker ps Lists all running containers — their names, what image they are based on, and which ports they are listening on.
docker ps -a Lists all containers, including stopped ones.
docker stop <name> Gracefully stops a running container. Replace <name> with the container's name.
docker start <name> Starts a container that has been stopped.
docker restart <name> Stops then immediately starts a container — useful after changing settings.
docker logs <name> Prints the recent output (messages and errors) from a container — the first place to look when something is not working.
docker logs -f <name> Follows the logs in real time as they are written. Press Ctrl + C to stop watching.
docker rm <name> Deletes a stopped container. Your data in volumes is kept safe — only the container itself is removed.
docker images Lists all downloaded images (the "sealed lunchboxes") on your Pi, with their sizes.
docker rmi <image> Deletes a downloaded image from disk to free up storage space.
docker pull <image> Downloads an image from Docker Hub without running it yet.
docker system prune Cleans up all stopped containers, unused images, and unused networks in one go — useful for reclaiming disk space. It asks for confirmation before deleting anything.
In plain words: A Docker image is the recipe — a sealed, downloadable package. A Docker container is what you get when you actually run that recipe — a live, running instance of the app. You can run the same image multiple times to get multiple separate containers, just as you can bake the same recipe multiple times to get multiple cakes.

Running Your First Real App: Uptime Kuma

Uptime Kuma is a beautiful, free self-hosted monitoring dashboard. You give it a list of websites or services to watch, and it checks them regularly and shows you whether they are up or down — with a clean visual interface and optional alerts. It is a perfect first Docker app because it installs in one command and needs nothing else.

  1. Run Uptime Kuma: 
    docker run -d \
  --name uptime-kuma \
  --restart unless-stopped \
  -p 3001:3001 \
  -v uptime-kuma-data:/app/data \
  louislam/uptime-kuma:1

    docker run — the command to create and start a new container.

    -d — runs the container detached, meaning it runs in the background. You get your Terminal prompt back immediately.

    --name uptime-kuma — gives this container a human-readable name so you can use it in other commands (like docker stop uptime-kuma) instead of a random ID.

    --restart unless-stopped — tells Docker to automatically restart this container if the Pi reboots or if the container crashes, unless you manually stop it with docker stop. This is what makes it feel like a real always-on service.

    -p 3001:3001 — maps port 3001 on your Pi to port 3001 inside the container. The format is always Pi-port:container-port. This is what lets your browser reach the app from outside the container.

    -v uptime-kuma-data:/app/data — creates a named storage area managed by Docker called uptime-kuma-data and links it to the folder inside the container where Uptime Kuma stores its data. Without this, all your settings and monitoring history would be lost every time the container is restarted.

    louislam/uptime-kuma:1 — the image to use. Docker downloads it automatically from Docker Hub (the main public library of images) if it is not already on your Pi. louislam is the developer's account, uptime-kuma is the image name, and :1 is the version tag — the latest version in the 1.x series, which supports ARM64 (your Pi's processor type).

    The backslash \ at the end of each line simply means "this command continues on the next line" — it is there for readability. You could write the whole thing on one line if you preferred.

    Docker will download the image (this may take a minute or two the first time, depending on your internet speed) and then start the container. You will see a long container ID printed — that means it is running.

  2. Check that it is running: 
    docker ps

    docker ps — shows all currently running containers. You should see uptime-kuma in the list with a status of Up and the port 0.0.0.0:3001->3001/tcp shown, which means port 3001 on your Pi is connected to port 3001 inside the container.

  3. On your Pi's browser, or on any device on your home network, open a browser and go to:

    http://<your-pi-ip>:3001

    Replace <your-pi-ip> with your Pi's actual local IP address — for example http://192.168.1.42:3001. The :3001 is the port number you mapped in the -p flag.

    The Uptime Kuma setup page appears. Create an admin account and start adding websites or services to monitor.

Tip: The --restart unless-stopped flag means Uptime Kuma will automatically start again every time you reboot your Pi. You never need to remember to start it manually. To stop it permanently, run docker stop uptime-kuma.

Docker Compose — Managing Multi-Part Apps

Some apps are made of several containers working together — for example, a web application plus a separate database container. Typing a long docker run command for each one is tedious and error-prone. Docker Compose solves this with a single text file that describes all the containers, and one command to start them all.

In plain words: A docker-compose.yml file is a recipe card that lists all the containers an app needs, their settings, and how they connect to each other. Running docker compose up reads the card and starts everything in one go.
Note: Modern Docker (version 20 and later, which is what you just installed) includes Compose built-in. The command is docker compose (two words, no hyphen). If you see older tutorials using docker-compose (with a hyphen), that is an older separate tool — the built-in version works the same way.

Here is an example using Memos, a lightweight private notes app. You type notes into a clean interface and they are stored entirely on your Pi — no third-party server involved.

  1. Create a folder for this app and move into it: 
    mkdir ~/memos && cd ~/memos

    mkdir ~/memos — creates a folder called memos in your home directory.

    && — runs the second command only if the first one succeeded (a safety check).

    cd ~/memos — moves into that new folder so the next commands work there.

  2. Create the Compose file: 
    nano docker-compose.yml

    Opens Nano to create a new file called docker-compose.yml. The name and the .yml extension are important — Docker Compose looks for exactly this filename in the current folder.

    Paste in this content exactly. Indentation matters in YAML files — use spaces, not tabs, and keep the spacing exactly as shown:

    services:
  memos:
    image: neosmemo/memos:stable
    container_name: memos
    restart: unless-stopped
    ports:
      - "5230:5230"
    volumes:
      - ./data:/var/opt/memos

    services: — the top-level section that lists all the containers this Compose file manages.

    memos: — the name we give to this service within Compose. It can be anything you like.

    image: neosmemo/memos:stable — the Docker image to use, pulled automatically from Docker Hub. The :stable tag means the latest stable release.

    container_name: memos — the name Docker will give the running container, so you can use commands like docker logs memos.

    restart: unless-stopped — auto-restart on reboot, same as before.

    ports: - "5230:5230" — maps port 5230 on the Pi to port 5230 inside the container.

    volumes: - ./data:/var/opt/memos — maps a folder called data in the current directory (./data) to the data folder inside the container. Docker will create the data sub-folder for you automatically the first time. This is where your notes are permanently stored — they survive container restarts and updates.

    Save and exit Nano: Ctrl + O, Enter, Ctrl + X.

  3. Start the app: 
    docker compose up -d

    docker compose up — reads the docker-compose.yml file in the current folder and creates and starts all the services listed in it. Docker downloads the image if it is not already on your Pi.

    -d — runs everything in the background (detached), so your Terminal is free again.

  4. Visit it on your network by opening a browser on any device and going to:

    http://<your-pi-ip>:5230

    The Memos sign-up page appears. Create an account and start writing private notes — they are stored on your Pi, not on anyone else's server.

  5. To stop everything in the Compose file (run this from inside the ~/memos folder): 
    docker compose down

    docker compose down — stops and removes all the containers defined in the Compose file. Your notes and data stored in the ./data folder are not deleted — they stay safely on your Pi's storage. Run docker compose up -d again at any time to start the app back up.

Tip: There is a huge community of self-hosted apps with ready-made Docker Compose files. Good places to discover them are Awesome-Selfhosted (a curated list at github.com/awesome-selfhosted/awesome-selfhosted) and the r/selfhosted community on Reddit. Home media servers, password managers, recipe organisers, photo libraries, and hundreds more can be running on your Pi in minutes.

Updating a Docker Container

Docker images are periodically updated by their authors to add features or fix security issues. Updating a container is a three-step process: pull the new image, stop and remove the old container, then run a new container from the updated image. For Compose apps it is even simpler.

For a single container (like Uptime Kuma):

docker pull louislam/uptime-kuma:1
docker stop uptime-kuma
docker rm uptime-kuma
docker run -d \
  --name uptime-kuma \
  --restart unless-stopped \
  -p 3001:3001 \
  -v uptime-kuma-data:/app/data \
  louislam/uptime-kuma:1

docker pull louislam/uptime-kuma:1 — downloads the latest version of the image. Even if the :1 tag has not changed, this fetches any updates published under that tag.

docker stop uptime-kuma — gracefully stops the running container.

docker rm uptime-kuma — removes the old container. Your data is safe because it lives in the named volume uptime-kuma-data, not inside the container itself.

The final docker run block — creates and starts a fresh container from the newly downloaded image, with all the same settings as before. Your data in the volume is automatically reconnected.

For a Compose app (like Memos) — from inside the app's folder:

cd ~/memos
docker compose pull
docker compose up -d

cd ~/memos — moves into the Memos folder so Docker Compose can find the docker-compose.yml file.

docker compose pull — downloads the latest version of every image listed in the Compose file.

docker compose up -d — restarts all services using the newly pulled images. Any container whose image has changed is automatically recreated. Your data in the ./data folder is untouched.

Tip — Portainer, a graphical Docker dashboard: If you prefer clicking over typing commands, Portainer is a free, self-hosted web interface for managing all your Docker containers, images, and volumes through a browser. You can install it with a single docker run command (search for "Portainer CE install" on their official site at portainer.io). It makes updating, starting, and stopping containers as easy as clicking a button, and it is a great way to see everything Docker is doing on your Pi at a glance.

Reaching Your Pi from Outside Your Home Network

Everything so far works only on your home network — devices in your house can reach the Pi, but not anyone on the wider internet. You may wonder: how do I access my Pi when I am away from home, or share something with a friend?

Careful — read this before opening your router to the internet. The most obvious method — opening a port on your home router (called "port forwarding") — directly exposes your Pi and everything running on it to the entire internet. Automated bots constantly scan the internet for open ports and attempt to break in. If your Pi is exposed without proper security measures (HTTPS encryption, strong authentication, firewall rules, and regular updates), it is likely to be compromised within hours or days. Do not attempt port forwarding without significant technical knowledge and careful preparation.

The good news is that there are modern, safer alternatives that do not require opening any router ports at all. These tools create an encrypted tunnel between your Pi and their servers, so you can reach your Pi securely from anywhere without ever exposing a raw port to the internet.

Setting Up Tailscale (Recommended for Beginners)

Tailscale is the easiest option for personal use — install it on your Pi and on your phone or laptop, sign in with a free account, and your devices can reach each other from anywhere securely, with no technical configuration of your router required.

  1. On your Pi, install Tailscale: 
    curl -fsSL https://tailscale.com/install.sh | sudo sh

    curl -fsSL https://tailscale.com/install.sh — downloads the Tailscale installation script from their official servers. The flags mean the same as before: fail on error, silent, show errors, follow redirects.

    | sudo sh — the | (called a "pipe") sends the downloaded script directly into sudo sh to run it as administrator. This is the method Tailscale's own documentation recommends for Linux.

  2. Connect the Pi to your Tailscale account: 
    sudo tailscale up

    sudo tailscale up — starts the Tailscale connection and authentication process. It will print a URL in the Terminal. Open that URL on any device — your phone, laptop, or the Pi's own browser — to log in with your Tailscale account (or create a free one). Once you log in, the Pi joins your private Tailscale network immediately.

  3. Install Tailscale on your phone or laptop too. Free apps are available for Windows, macOS, iOS, and Android. Visit tailscale.com/download and sign in with the same account you used in the previous step.
  4. Find your Pi's Tailscale IP address: 
    tailscale ip -4

    tailscale ip -4 — prints your Pi's private Tailscale IP address. It will look something like 100.x.x.x. This address only works when you are connected to Tailscale on both the Pi and the device you are browsing from, but it works from anywhere in the world — your home, a cafe, or another country — through an encrypted connection, with no router ports open.

    For example, if your Tailscale IP is 100.64.10.5, you could reach Uptime Kuma from anywhere by visiting http://100.64.10.5:3001.

Note: Tailscale's free tier supports up to 3 users and 100 devices — more than enough for personal and family use. If you ever want to share an app publicly with a real https:// web address that anyone can visit without installing Tailscale, look at Cloudflare Tunnel — but that is a more advanced step beyond this chapter.

Key terms

  • Web server — a program that listens for browser requests and sends back web pages in reply.
  • Nginx — a popular, fast, professional web server that runs as a permanent background service on your Pi.
  • IP address — a unique number (like 192.168.1.42) that identifies a device on a network.
  • Port — a numbered "door" on a networked device; different services listen on different port numbers so many services can run on the same machine simultaneously.
  • localhost — a special name that always means "this computer itself"; typing http://localhost in a browser on the Pi reaches the Pi's own web server.
  • Docker — software for running applications inside isolated containers on your Pi.
  • Container — a self-contained, isolated running instance of an application, bundled with everything it needs, that cannot interfere with the rest of the system.
  • Image — the sealed, downloadable package from which a container is created; the recipe that Docker runs to produce a container.
  • Docker Hub — the main public online library where Docker images are stored and downloaded from.
  • Volume — a Docker-managed storage area that keeps your data (settings, databases, files) safe even when a container is stopped, updated, or replaced.
  • Docker Compose — a tool that reads a YAML file describing one or more containers and starts them all with a single command.
  • Port forwarding — a router setting that sends incoming internet traffic to a specific device on your home network; risky without expert-level security measures.
  • Tailscale — a free VPN tool that creates a private, encrypted connection between your devices so you can reach your Pi from anywhere without opening any router ports.
  • Cloudflare Tunnel — a free service that gives a Pi-hosted app a public HTTPS web address without opening any router ports.
  • Service / daemon — a program that runs quietly in the background, starting automatically each time the Pi boots, with no Terminal window required.
  • ARM64 — the processor architecture used by the Raspberry Pi 5. When choosing Docker images, look for ones that support linux/arm64 or arm64/v8 — most popular images do.

Chapter summary

  • A web server is simply a program that responds to browser requests with web pages — your Pi 5 can be one right now with no special hardware.
  • python3 -m http.server 8080 instantly serves any folder as a temporary website — useful for quick tests but stops when you close the Terminal.
  • Nginx is a proper, always-on web server installed with sudo apt install nginx; drop HTML files into /var/www/html/ and they are immediately available on your network, even after a reboot.
  • Docker lets you run self-hosted applications as isolated containers — one command installs a complete app without touching anything else on the Pi.
  • Key Docker habits: always use --restart unless-stopped so apps survive reboots; always use a volume (-v) so your data is preserved; check docker logs <name> first when something goes wrong.
  • Docker Compose describes multi-container apps in a single docker-compose.yml file and starts everything with docker compose up -d; updates are as simple as docker compose pull followed by docker compose up -d.
  • Access your apps on the home network at http://<pi-ip>:<port>; use Tailscale, Cloudflare Tunnel, or Raspberry Pi Connect for safe remote access from outside your home — never open raw router ports without expert security knowledge.
