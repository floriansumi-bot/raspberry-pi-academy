How fast are your reflexes, really? In this project you will build a reaction-timer game: an LED lights up after a random, unpredictable delay, and you must slam a button as quickly as you can. The Pi measures your reaction time in milliseconds and keeps track of your best score across rounds. Building it teaches you a whole cluster of core Python ideas — variables, the random module, the time module, conditionals, while loops and f-strings — plus the electronics of reading a button and taming switch bounce.

What You'll Build & Learn

The finished game runs in the Thonny console and on the breadboard. Each round: a random wait, then the "go" LED lights, you press as fast as you can, and the Pi prints your time and tells you if it is a new best. Here are the fundamentals you will pick up.

The Python fundamentals

  • Variables — named boxes that store values (your start time, your reaction time, your best score) and can change as the game runs.
  • The random module — making the computer pick unpredictable values, here random.uniform() for a random delay so you cannot cheat by anticipating.
  • The time module — time.time() gives the current moment as a number; subtracting two readings tells you how long something took.
  • Conditionals — if / elif / else to make decisions, such as "is this a new best score?"
  • The while loop — repeating the game round after round.
  • f-strings — a clean way to drop values straight into printed text, like f"{ms} ms".

The electronics fundamentals

  • Button input — reading a push button with gpiozero's Button object (default pull_up=True, wired GPIO → button → GND).
  • Switch bounce and debounce — why a single press can register as several, and how bounce_time fixes it.
  • An LED as a signal — using one LED as the "go!" light, with its own 330 Ω resistor.
Note: this chapter follows on from the LED and button basics earlier in the course. We will still explain each part, but it helps if you have lit a single LED before.

Parts List

  • A Raspberry Pi 5 running Raspberry Pi OS Bookworm.
  • 1 × LED — any colour; green suits a "go" light.
  • 1 × 330 Ω resistor — orange-orange-brown-gold, for the LED.
  • 1 × push button — a small tactile switch with four legs.
  • A breadboard.
  • 3 × female-to-male jumper wires — one for the LED's GPIO, one for the button's GPIO, one shared ground.
Careful: power off and unplug your Pi before wiring. Shut down from the menu, wait for the green light to go out, then remove the power lead. The Pi 5 GPIO is 3.3 V logic only — never put 5 V on a GPIO pin. The LED needs its own 330 Ω resistor; the button does not need an external resistor because gpiozero provides one internally.

How a Button Talks to the Pi

A push button is just a switch: press it and two contacts touch, completing a circuit; let go and they spring apart. gpiozero's Button object reads this for you.

By default, Button uses an internal pull-up resistor. That means the GPIO pin is gently held HIGH (3.3 V) when nothing is happening. You wire the button so that pressing it connects the pin to GND, pulling it LOW. gpiozero understands this and reports the press correctly — is_pressed becomes True. The beauty is you only need two wires and no extra resistor.

In plain words: a pull-up resistor keeps a GPIO input pin at a known HIGH value when nothing is pressing the button, so the pin never "floats" and reads random noise. The Pi 5 has these built in; gpiozero switches one on automatically for every Button.
Note: the default is pull_up=True, so the button's other leg goes to GND. If you ever set pull_up=False instead, you would wire that leg to 3.3 V — but for this project, stick with the default and wire to GND. Wiring the button leg straight to 3.3 V while leaving the default pull-up on would be a wiring mistake, so always match the wiring to the setting.

There are two everyday ways to read a button. The first is to ask it directly whether it is pressed, using is_pressed:

from gpiozero import Button
from time import sleep

button = Button(27)

while True:
    if button.is_pressed:
        print("Down")
    else:
        print("Up")
    sleep(0.2)

Line 4 — button = Button(27): a button on GPIO 27 with the default internal pull-up.

Line 7 — if button.is_pressed:: is_pressed is a property that is True while the button is held and False otherwise. This "keep checking" style is called polling.

Line 11 — sleep(0.2): a tiny pause so we are not printing thousands of lines per second.

The second way — the one our game uses — is to wait for a press with button.wait_for_press(), which stops the program at that line until the press happens. That is exactly what we want for timing: the moment wait_for_press() returns is the moment the player reacted.

Switch bounce: the hidden gremlin

When metal contacts inside a button slap together, they do not connect cleanly. For a few thousandths of a second they bounce apart and back, several times, like a dropped ball. The Pi is fast enough to see every one of those bounces, so a single physical press can look like five presses in a row. This is called switch bounce.

The cure is debouncing: after the first change, ignore any further changes for a short window (say 50 milliseconds) — long enough for the bouncing to settle. gpiozero does this for you with the bounce_time argument:

from gpiozero import Button

button = Button(17, bounce_time=0.05)   # ignore bounces within 50 ms

Line 3 — Button(17, bounce_time=0.05): creates a button on GPIO 17 with debouncing. bounce_time=0.05 means "after a change, ignore any more changes for 0.05 seconds (50 ms)." That smooths out the bounce so each press counts once. With no bounce_time (the default None), debouncing is off.

Tip: 50 ms is a good starting value. If a fast double-tap is being merged into one, lower it; if one press still registers twice, raise it a little.

Step-by-step wiring

  1. Power off. Shut down and unplug the Pi before touching the breadboard.
  2. Fit the LED. Push the LED in with its long leg (anode) and short leg (cathode) in different rows across the centre gap.
  3. Add its resistor. One leg of the 330 Ω resistor shares the LED's long-leg row; the other leg goes to a free row for the GPIO wire.
  4. Wire the LED. GPIO 17 (pin 11) to the resistor; the LED's short leg to the − ground rail.
  5. Fit the button straddling the centre gap so its two sides are separate until pressed.
  6. Wire the button. GPIO 27 (pin 13) to one side; the other side to the − ground rail.
  7. Common ground. Run one jumper from the − rail to a GND pin (pin 6).
  8. Re-check and power up only once every wire is confirmed.

Fundamental 1: Variables and f-strings

Let us meet the Python ideas one at a time before the full game. A variable is a labelled box that holds a value. You can put a value in, read it back, and change it later.

best_score = None
attempts = 0

attempts = attempts + 1
print(f"You have had {attempts} go(s). Best so far: {best_score}")

Line 1 — best_score = None: creates a variable best_score and stores None in it. None is Python's word for "nothing yet" — we have not recorded a best score, so the box starts empty.

Line 2 — attempts = 0: a counter variable starting at zero.

Line 4 — attempts = attempts + 1: reads the current value, adds one, and stores the result back. Variables can change — that is what makes them useful for scores and counters.

Line 5 — print(f"...{attempts}...{best_score}"): an f-string (note the f before the quote). Anything inside { } is replaced by the value of that variable. Here it prints the count and best score in a sentence without fiddly string-joining.

In plain words: an f-string is a string with the letter f in front. Inside it, {name} gets swapped for whatever name holds. It is the tidiest way to mix words and values in one line.

Fundamental 2: Random Delays

If the LED always lit after exactly two seconds, you could cheat by counting. The random module makes the wait unpredictable.

import random
from time import sleep

wait = random.uniform(2, 5)   # a random number of seconds between 2 and 5
print(f"Waiting {wait:.2f} seconds...")
sleep(wait)
print("GO!")

Line 1 — import random: brings in Python's built-in randomness module.

Line 4 — random.uniform(2, 5): returns a random decimal number anywhere between 2 and 5 (for example 3.71). uniform means every value in that range is equally likely. We store it in wait.

Line 5 — f"Waiting {wait:.2f} seconds...": the :.2f inside the braces is a format instruction meaning "show this number to 2 decimal places," so 3.71456 prints as 3.71.

Line 6 — sleep(wait): pauses for that random number of seconds, so the player never knows exactly when "GO!" will appear.

Fundamental 3: Timing with the time Module

To measure a reaction, we note the moment the LED lights and the moment the button is pressed, then subtract. The time module gives us those moments.

from time import time

start = time()
# ... player reacts ...
end = time()

reaction_seconds = end - start
reaction_ms = reaction_seconds * 1000
print(f"Reaction time: {reaction_ms:.0f} ms")

Line 3 — start = time(): time() returns the current moment as a number of seconds (a big decimal). We save it as start the instant the LED lights.

Line 5 — end = time(): another reading taken the instant the button is pressed.

Line 7 — reaction_seconds = end - start: subtract the two readings to get how long it took, in seconds. This is a delta — a difference between two times.

Line 8 — reaction_ms = reaction_seconds * 1000: multiply by 1000 to convert seconds to milliseconds, which feels more natural for reaction times.

Line 9 — {reaction_ms:.0f}: :.0f rounds to a whole number, so we print e.g. 312 ms rather than 312.4187 ms.

Fundamental 4: Conditionals and while Loops

To decide whether a score is a new best, and to run round after round, we need conditionals and a while loop.

best = None
rounds = 0

while rounds < 3:
    score = 250        # pretend reaction time in ms
    if best is None:
        best = score
        print("First score recorded.")
    elif score < best:
        best = score
        print("New best!")
    else:
        print("Not your best this time.")
    rounds = rounds + 1

Line 4 — while rounds < 3:: a while loop repeats its block as long as the condition rounds < 3 is true. The < means "less than." When rounds reaches 3, the loop stops.

Line 6 — if best is None:: the first branch of a conditional. If we have no best yet, this score becomes the best.

Line 9 — elif score < best:: elif means "else, if". It is only checked when the if above was false. If this new score is lower (faster) than the best, we have a new record.

Line 12 — else:: runs when none of the above were true — the score was not a new best.

Line 14 — rounds = rounds + 1: count this round so the while loop eventually ends. Forgetting this line would make the loop run forever!

In plain words: if/elif/else is the program making a decision — "if this, do that; otherwise, if something else, do this other thing; otherwise, do the last thing." Only one branch runs.

The Full Game

Now we assemble everything into the reaction-timer game. Open a new file in Thonny, type it in, and save it as reaction.py.

from gpiozero import LED, Button
from time import time, sleep
import random

led = LED(17)
button = Button(27, bounce_time=0.05)   # debounced button to GND

best = None      # best (lowest) reaction time in ms, None until first round
round_number = 0

print("Reaction Timer! Press the button the instant the LED lights.")
print("Press Ctrl+C in the console to quit.\n")

while True:
    round_number = round_number + 1
    print(f"--- Round {round_number} ---")
    print("Get ready...")

    led.off()
    wait = random.uniform(2, 5)     # unpredictable delay
    sleep(wait)

    # Catch a cheat who presses before the light
    if button.is_pressed:
        print("Too soon! Wait for the light. No score.\n")
        sleep(1)
        continue

    led.on()
    start = time()                  # the moment the light came on
    button.wait_for_press()         # block until the player presses
    end = time()                    # the moment they pressed
    led.off()

    reaction_ms = (end - start) * 1000

    if best is None or reaction_ms < best:
        best = reaction_ms
        print(f"Your time: {reaction_ms:.0f} ms  -  NEW BEST!")
    else:
        print(f"Your time: {reaction_ms:.0f} ms  (best: {best:.0f} ms)")

    print()
    sleep(2)

Lines 1–3: import the LED and Button from gpiozero, time and sleep from the time module, and the random module.

Line 5 — led = LED(17): the green "go" LED on GPIO 17.

Line 6 — button = Button(27, bounce_time=0.05): the button on GPIO 27, debounced so one press counts once. Its other leg is wired to GND; the default internal pull-up handles the rest.

Lines 8–9: two variables: best starts as None (no score yet), round_number starts at 0.

Line 14 — while True:: the while loop that plays round after round forever, until you stop the program.

Lines 15–17: count the round and announce it with f-strings.

Lines 19–21 — random delay: turn the LED off, pick a random wait with random.uniform(2, 5), and sleep for it so the "go" moment is unpredictable.

Lines 24–27 — the cheat check: an if conditional. If the player is already holding the button before the light, we print a warning and continue — which jumps straight to the next loop iteration, skipping the timing.

Lines 29–32 — the measurement: light the LED, record start = time(), then button.wait_for_press() pauses until the player presses, at which point we record end = time() and switch the LED off.

Line 34 — reaction_ms = (end - start) * 1000: the time delta in seconds, converted to milliseconds.

Lines 36–40 — score check: an if/else conditional. If there is no best yet, or this time is faster than the best, record a new best and say so; otherwise just show the time alongside the current best. The :.0f rounds to whole milliseconds.

Lines 43–44: a blank line and a short pause before the next round begins.

Running the game

  1. Save as reaction.py in your home folder.
  2. Run with the green ▶ button or F5. Read the instructions printed in the console.
  3. Wait for the LED. After a random pause it lights — press the button as fast as you can.
  4. Read your time in milliseconds. Anything around 200–300 ms is typical for a human; under 200 ms is very sharp.
  5. Keep playing — the game tracks your best score across rounds. Press the red ◼ Stop button (or Ctrl+C in the console) to quit.
Tip: challenge a friend and keep score on paper, or extend the program to track each player's best (see "Make it your own"). Tiredness, caffeine and practice all visibly change your numbers — it makes a fun little science experiment.

Understanding Your Numbers

It is worth pausing on what those millisecond figures mean, because they show why we measured the way we did.

A millisecond (ms) is one thousandth of a second. Human reaction to a sudden light is genuinely slow in computer terms: signals have to travel from your eye to your brain, get processed, then travel back down to your finger muscles. That round trip takes most people somewhere between 200 and 300 ms. A trained gamer or athlete might reach 150 ms; almost nobody beats 100 ms honestly — a "score" much lower than that is a sign of switch bounce or a guessed press, not superhuman reflexes.

This is also why time.time() is good enough here. It measures wall-clock time to a tiny fraction of a millisecond — far finer than human reactions — so any wobble in the measurement is dwarfed by your own variation from press to press.

Tracking Scores Across Rounds

Our game keeps a single best value. But score tracking can be richer, and it is a great excuse to practise variables and lists together. Suppose we want to remember every time, then report the best, the worst and the average at the end. Here is a self-contained example you can try on its own:

times = []                       # an empty list to collect every reaction time

times.append(312)                # pretend three rounds happened
times.append(287)
times.append(341)

best = min(times)                # smallest = fastest
worst = max(times)               # largest = slowest
average = sum(times) / len(times)

print(f"Rounds played: {len(times)}")
print(f"Best:    {best} ms")
print(f"Worst:   {worst} ms")
print(f"Average: {average:.0f} ms")

Line 1 — times = []: creates an empty list — a container that will hold every score in the order they happen.

Lines 3–5 — times.append(312): append adds a value to the end of the list. After three appends, times is [312, 287, 341].

Line 7 — min(times): a built-in function that returns the smallest number in the list — the fastest reaction.

Line 8 — max(times): returns the largest — the slowest reaction.

Line 9 — sum(times) / len(times): sum adds them all up, len counts how many there are, and dividing gives the average. These three built-ins turn raw scores into a useful summary.

Lines 11–14 — the report: f-strings print a tidy round-up, with {average:.0f} rounding the average to a whole number.

Tip: to fold this into the full game, create times = [] before the loop and add times.append(reaction_ms) just after you calculate each round's score. When the player quits, print the summary. This is the basis of the "Best-of-five" idea in the next section.
Note: notice how min, max, sum and len are all functions that return a value — you give them a list and they hand back a single answer. Combining a list with built-in functions like these is one of the most common patterns in all of Python.

From the E-Waste Pile

Both parts of this game are easy to salvage from broken electronics.

  • Push buttons / micro-switches hide inside dead computer mice (the click switches), old remote controls, broken game controllers and keyboards. Desolder one carefully; it behaves exactly like a shop-bought tactile button.
  • LEDs come from old routers, toys and appliance front panels — the longer leg is still the anode.
  • Test salvaged buttons with a multimeter in continuity mode: it should beep only while you hold the button down.
Careful: only salvage from low-voltage, unplugged gadgets — battery toys, USB devices, dead routers. Never open mains adapters, microwave ovens, CRT screens, or anything with big capacitors or lithium batteries; they can store a dangerous or lethal charge even when unplugged.

Make It Your Own

  • Best-of-five. Replace while True with while round_number < 5 and, when it ends, print the best time and an average. Keep a running total in a variable and divide.
  • Two-player duel. Add a second button and LED; whoever presses first after the light wins the round. Compare the two reaction times with an if.
  • Difficulty levels. Use random.uniform(1, 8) for a wider, twitchier delay range, or shrink the LED's on-time to make a "blink and you miss it" mode.
  • Grade the result. Use if/elif/else to print "Lightning!", "Quick!", or "Keep practising" depending on the millisecond bands.

Key terms

  • Variable — a named box that stores a value and can be changed (e.g. best, round_number).
  • random.uniform(a, b) — returns a random decimal between a and b, every value equally likely.
  • time.time() — the current moment as a number of seconds; subtract two readings to measure elapsed time (a delta).
  • Conditional — if / elif / else; the program chooses one branch to run based on tests.
  • while loop — repeats a block while a condition stays true; while True repeats forever.
  • f-string — a string prefixed with f where {value} is replaced by that value; {x:.0f} formats to whole numbers.
  • Button — gpiozero's push-button object; default pull_up=True, so wire the other leg to GND.
  • Pull-up resistor — holds an input pin HIGH at rest so it does not float; built into the Pi and enabled by gpiozero.
  • Switch bounce — the rapid make/break of a switch's contacts that can register as several presses.
  • bounce_time — the gpiozero argument (in seconds) that ignores further changes for a short window to debounce a switch.
  • wait_for_press() — a Button method that pauses the program until the button is pressed.
