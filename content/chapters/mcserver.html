Your Raspberry Pi 5 makes a genuinely good little Minecraft server — a machine that sits quietly in the corner, sips a few watts of power, and lets you and your friends share the same world day and night. In this project you will turn your Pi into a 24/7 Minecraft server, choose the right edition for the people you play with, keep it running automatically, and (carefully) open it up so friends outside your home can join.

Two Editions, Two Paths

Before you install anything, you need to know that "Minecraft" is really two different games that cannot directly play together. Which one your friends own decides which server you build — so this is the most important decision in the whole project.

In plain words: A server is just a program that keeps the shared world running and lets other copies of Minecraft (the clients) connect to it. The server does not need the game's graphics — it only does the bookkeeping — which is exactly why a small computer like the Pi can run it.
Edition Who plays it On the Pi
Bedrock Edition Phones & tablets (iOS/Android), Xbox, PlayStation, Nintendo Switch, and the Windows 10/11 "Minecraft" app Lighter and faster — the easier path, and the best choice if your friends play on consoles or phones
Java Edition PC, Mac, and Linux (the original "Minecraft: Java Edition") Heavier, but runs well with an optimised server called PaperMC — choose this if everyone is on a computer and wants mods or plugins
Note: A Bedrock player and a Java player cannot join the same ordinary server. Pick the edition that matches the devices your group actually uses. This chapter gives you a full, worked path for both — start with whichever fits.

Will Your Pi 5 Handle It?

Comfortably, yes — especially a Pi 5. The thing that limits a Minecraft server most is memory (RAM), and the Pi 5 has plenty. Here is a realistic guide to how many players you can expect.

Your Pi Bedrock Java (with Paper)
Pi 5, 4 GB A handful of players, smooth 2–4 players
Pi 5, 8 GB Many players, very smooth 4–8 players
Pi 5, 16 GB Plenty of headroom for mods & big worlds 8–12+ players
Pi 4 Works, a little slower 2–4 players, modest render distance
Tip: With 8 GB or 16 GB of RAM, your real bottleneck stops being memory and becomes disk speed. A Minecraft world is read and written constantly, and a microSD card is the slowest part of the Pi. Running the server from an SSD (see Chapter 10) removes lag spikes and protects you from the card wearing out. It is the single best upgrade for a busy server.

What You Will Need

  • A Raspberry Pi 5 (4 GB minimum; 8 GB or 16 GB strongly recommended) with the official 27 W power supply.
  • An active cooler or fan — a busy server keeps the processor warm, and a hot Pi throttles (slows itself down). The official Active Cooler is ideal.
  • Fast, roomy storage: a good 32 GB+ microSD card, or — much better — an SSD over USB or the PCIe/NVMe connector.
  • A wired Ethernet connection if you can manage it. Wi-Fi works, but a cable is steadier for a server that is always on.
  • Raspberry Pi OS, already set up, updated, and reachable over the network (Chapters 4 and 9).

You will do everything from the Terminal, so this is also great practice for the command-line skills from Part 2. If your Pi is "headless" (no monitor), connect over SSH (Chapter 9) and follow along exactly the same way.

Tip: Start with a fully updated system. Run sudo apt update && sudo apt full-upgrade -y before you begin.

Path A — A Bedrock Server (Phones, Consoles, Windows)

This is the easiest path. Mojang publishes an official Bedrock Dedicated Server for Linux, and the Pi 5 runs the ARM build well. We will download it, run it once, and connect from a phone or console on the same Wi-Fi.

Step 1 — Make a folder and install a helper

mkdir ~/bedrock-server
cd ~/bedrock-server
sudo apt install -y unzip

Line 1 creates a folder called bedrock-server in your home directory to keep everything tidy. Line 2 moves into it (cd = "change directory"). Line 3 installs unzip, the tool that unpacks the download — the Bedrock server arrives as a single compressed .zip file.

Step 2 — Download the Bedrock server

Open the Chromium web browser on the Pi (or on another computer) and go to the official download page at minecraft.net/en-us/download/server/bedrock. Accept the licence checkbox, then copy the link for the Ubuntu / Linux server. Back in the Terminal, download it with wget, pasting the link you copied in place of the example:

wget https://www.minecraft.net/bedrockdedicatedserver/bin-linux/bedrock-server-1.x.x.x.zip
unzip bedrock-server-*.zip

wget downloads a file straight from a web address to your Pi. unzip then unpacks it, filling your folder with the server program and its configuration files. The * is a wildcard meaning "whatever the version number is", so you do not have to type the long name exactly.

Note: The official server is built for the x86-64 and ARM Linux platforms. On a Pi it runs through the system's ARM support. If you ever see "cannot execute binary file", you downloaded the wrong platform's link — go back and choose the Linux build.

Step 3 — Configure and run it

The file server.properties holds every setting. Open it in the nano editor to set a name and a few basics:

nano server.properties

Opens the settings file. Change server-name to whatever you like, set gamemode (e.g. survival or creative), and pick a difficulty. Save and exit with Ctrl + O, Enter, then Ctrl + X. Every line has a short comment above it explaining what it does.

Now start the server:

LD_LIBRARY_PATH=. ./bedrock_server

The first part, LD_LIBRARY_PATH=., tells the program to look for its support files in the current folder (the dot means "here"). ./bedrock_server then launches it. You will see lines scroll past ending in "Server started." — your world is now live on your home network.

Step 4 — Connect from a phone or console

First, find your Pi's address on the network:

hostname -I

Prints your Pi's IP address — something like 192.168.1.42. The first number is the one you want.

  1. Open Minecraft on your phone, tablet, or console.
  2. Go to Play > Servers, then scroll down and choose Add Server.
  3. Give it any name, enter your Pi's IP address, and leave the port as 19132.
  4. Save, then tap the server to join. You are now playing on your Pi.
Tip: To stop the server cleanly, type stop in the Terminal where it is running and press Enter. This saves the world properly. Never just close the window or pull the power while it is running, or you risk a corrupted world.

Path B — A Java Server with PaperMC

If your friends play on PCs, you want Java Edition. The official Java server runs on the Pi, but a community-built version called PaperMC is dramatically more efficient and is the standard choice for any Pi server. It is a drop-in replacement that plays identically but uses far less of the Pi's resources.

In plain words: Java is the programming language Minecraft's PC edition is written in, so the server needs the Java "runtime" installed to run at all. PaperMC (or just "Paper") is an optimised rebuild of the official server — same game, much better performance, plus support for plugins.

Step 1 — Install Java

Modern Minecraft needs Java 21. Install the headless version (no desktop parts, since a server has no graphics):

sudo apt update
sudo apt install -y openjdk-21-jre-headless

Line 1 refreshes the list of available software. Line 2 installs the Java 21 runtime. The -jre-headless part means "just enough Java to run programs, with none of the graphical extras" — exactly right for a server. Confirm it worked with java -version.

Step 2 — Download PaperMC

mkdir ~/mcserver
cd ~/mcserver

Creates and enters a folder called mcserver to keep the server's files together.

Go to papermc.io/downloads/paper in a browser, choose the latest version, and copy the download link for the newest build. Download it into your folder and rename it to something short:

wget -O paper.jar "https://fill.papermc.io/v3/projects/paper/versions/1.x.x/builds/xxx/downloads/paper-1.x.x-xxx.jar"

wget -O paper.jar downloads the file and saves it under the simple name paper.jar (the -O flag means "output to this name"). Paste the real link you copied between the quotation marks. A .jar file is a packaged Java program — this one is the whole server.

Step 3 — First run and the EULA

Minecraft requires you to agree to its End-User Licence Agreement (EULA) before a server will run. The first launch creates the agreement file and then stops:

java -Xms2G -Xmx6G -jar paper.jar nogui

-Xms2G and -Xmx6G set the smallest and largest amounts of memory the server may use — here, between 2 and 6 gigabytes. -jar paper.jar runs the server program. nogui turns off the little pop-up window, which a headless Pi does not need. The first run will print a message about the EULA and exit.

Open the new eula.txt file, change eula=false to eula=true, and save:

nano eula.txt

Edit the single line so it reads eula=true, which records that you accept Minecraft's licence terms. Save with Ctrl + O, Enter, then exit with Ctrl + X.

Now run the same command again — this time the world generates and the server starts:

java -Xms2G -Xmx6G -jar paper.jar nogui

The server creates your world (this takes a minute the first time) and finishes with "Done!" followed by a timing. It is now listening for players. Type stop and press Enter to shut it down cleanly whenever you need to.

Step 4 — Choosing how much memory to give it

The -Xmx number is the most important tuning choice. Give the server a generous slice but always leave several gigabytes for the operating system itself — never assign all of your Pi's RAM.

Your Pi's RAM Sensible setting
4 GB -Xms1G -Xmx2G
8 GB -Xms2G -Xmx6G
16 GB -Xms4G -Xmx12G
Careful: Do not set -Xmx to your Pi's full memory. The operating system needs its own share, and an over-allocated server will crash or freeze when the Pi runs out. Leaving 3–4 GB free is the safe rule on an 8 GB or 16 GB board.

Step 5 — Connect from a PC

  1. In Minecraft: Java Edition, choose Multiplayer > Add Server.
  2. Enter your Pi's IP address (from hostname -I) as the server address. The default port 25565 is assumed automatically.
  3. Click Done, then double-click the server to join.

Keeping the Server Running with systemd

So far the server only runs while your Terminal window is open — close it, and the server stops. For a real "always-on" server you want it to start automatically when the Pi boots and to keep running in the background. The proper Linux way to do this is a service managed by systemd.

In plain words: systemd is the part of Linux that starts and supervises background programs. Registering your server as a systemd service means the Pi will launch it on boot, restart it if it ever crashes, and keep it running whether or not anyone is logged in.

Create a service definition with nano:

sudo nano /etc/systemd/system/minecraft.service

Opens a new, empty service file in the system folder where services live. You need sudo because this is a protected system location.

Paste the following (this example is for the Paper server; adjust the paths and command if you built a Bedrock server):

[Unit]
Description=Minecraft Server
After=network.target

[Service]
User=pi
WorkingDirectory=/home/pi/mcserver
ExecStart=/usr/bin/java -Xms2G -Xmx6G -jar paper.jar nogui
Restart=on-failure

[Install]
WantedBy=multi-user.target

User=pi and WorkingDirectory tell the Pi which account to run as and which folder the server lives in — change pi to your username if it differs. ExecStart is the exact command to launch the server. Restart=on-failure automatically relaunches it if it crashes. WantedBy=multi-user.target means "start this once the Pi has finished booting".

Save and exit, then enable and start the service:

sudo systemctl daemon-reload
sudo systemctl enable minecraft
sudo systemctl start minecraft

Line 1 tells systemd to re-read its configuration so it notices your new file. Line 2 (enable) sets the server to start automatically every time the Pi boots. Line 3 (start) launches it right now without waiting for a reboot.

You can check on it, stop it, or read its log at any time:

sudo systemctl status minecraft
journalctl -u minecraft -n 50

Line 1 shows whether the server is running and a few recent log lines. Line 2 shows the last 50 lines of its log — the place to look if it will not start. (You met journalctl in the Maintenance chapter.)

Tip: A systemd service runs without an interactive console, so you cannot simply type stop into it. To send commands to a running server you can install a console manager such as screen or tmux and launch the server inside it, or use a server-management tool. For most home setups, sudo systemctl stop minecraft is all you need.

Playing with Friends Over the Internet

Everything so far works for anyone on your home Wi-Fi. To let friends join from their homes, the connection has to reach your Pi from the wider internet — and that takes a little care, because anything reachable from the internet can also be probed by strangers.

Careful: Opening a port to the internet exposes your Pi to the whole world. Before you do, read the security chapter (Chapter 21): use a strong password, keep the Pi updated, and consider a firewall. Never reuse an important password on a machine you expose.

The easy, safe option: a tunnel

The simplest and safest way to let friends in is a tunnel service such as playit.gg, which gives your server a public address without touching your router or exposing your home IP. You install a small program on the Pi, it connects outward to the service, and your friends get an address to join. Because nothing is opened on your router, this avoids the riskiest part of self-hosting.

The traditional option: port forwarding

The classic approach is port forwarding: telling your router to send incoming Minecraft traffic to your Pi.

In plain words: Your router shares one public internet address among every device in your home. Port forwarding is a rule that says "when Minecraft traffic arrives from the internet, send it to the Pi." Without that rule, the router does not know which device the traffic is for, and friends cannot connect.
  1. Give your Pi a fixed (static) IP address on your home network, so the forwarding rule always points to the right place (the same step you would take for Pi-hole in Chapter 15).
  2. Log in to your router's settings page (often 192.168.1.1 in a browser) and find the Port Forwarding section.
  3. Forward the right port to your Pi's fixed IP: TCP 25565 for Java, or UDP 19132 for Bedrock.
  4. Find your home's public IP address (search "what is my IP") and give that to your friends, along with the port.
Note: Most home internet connections change their public IP address from time to time. A free Dynamic DNS service gives you a memorable name (like myworld.example.net) that always points to your current address, so you do not have to keep sending friends a new number.

Backing Up Your World

Your world is just a folder — and a precious one once you have built in it. Backing it up is simply a matter of copying that folder somewhere safe, on a schedule.

cd ~/mcserver
tar -czf ~/world-backup-$(date +%Y-%m-%d).tar.gz world

tar -czf bundles a folder into a single compressed archive: c = create, z = compress, f = to this file. The $(date +%Y-%m-%d) part automatically stamps today's date into the filename, so each backup is separate. world is the folder being saved. For Bedrock the world folder lives under worlds/ instead — adjust the name accordingly.

Tip: Copy the resulting .tar.gz file off the Pi — to a USB drive, another computer, or cloud storage. A backup that lives only on the same SD card as the server will not save you if that card fails. You can automate regular backups with a cron job; see the Maintenance chapter for the idea.

Tuning Performance on the Pi

A few small settings make a big difference to how smooth your server feels on a Pi.

Setting (in server.properties) Suggested value Why
view-distance 6–8 How far players can see. This is the biggest single load on the server — lower it if the world feels laggy.
simulation-distance 4–6 How far the world keeps "ticking" (mobs, crops, redstone). Lower means less work for the Pi.
max-players Match your RAM Be realistic — a Pi 5 with 8 GB is happy with a handful of players, not a hundred.
spawn-protection 0 Disables a small bit of extra processing around the spawn point you probably do not need.
Tip: Watch the Pi's temperature and load while the server runs busy. In a second Terminal, vcgencmd measure_temp shows the processor temperature and htop shows live CPU and memory use (both covered in the Maintenance chapter). If the temperature climbs above 80 °C, improve cooling before doing anything else.

On the Java server, the server console shows a number called TPS (ticks per second). A healthy server runs at 20 TPS. If that number drops, the Pi is struggling — lower the view distance, reduce players, or move the world to an SSD.

Troubleshooting Common Problems

Problem Likely cause Fix
Friends on the same Wi-Fi cannot connect Wrong IP address, or the server is not actually running Re-check hostname -I, confirm the server says "Done!"/"Server started", and that they used the right port (25565 Java, 19132 Bedrock)
"Failed to bind to port" The server is already running, or another program uses that port Stop the duplicate (sudo systemctl stop minecraft) before starting again
Java server crashes on start -Xmx set too high, or wrong Java version Lower -Xmx to leave RAM free; confirm java -version shows 21
"cannot execute binary file" (Bedrock) Downloaded the wrong platform's build Re-download the official Linux server build for ARM
Sudden lag spikes microSD card too slow for constant world writes Lower view-distance; move the server to an SSD (Chapter 10)
World won't load after a power cut The Pi lost power mid-write and the world was corrupted Restore your most recent backup; always stop the server cleanly and use a proper power supply
Friends outside your home cannot join Port forwarding not set, or public IP changed Re-check the router rule and your current public IP, or use a tunnel like playit.gg

Key terms

  • Server — a program that keeps a shared Minecraft world running and lets other copies of the game (clients) connect to it.
  • Bedrock Edition — the version of Minecraft for phones, tablets, consoles, and the Windows app; lighter to host and the easiest path on a Pi.
  • Java Edition — the original PC/Mac/Linux version of Minecraft; heavier to host but best served with PaperMC.
  • PaperMC (Paper) — a community-built, highly optimised replacement for the official Java server; the standard choice for a Raspberry Pi.
  • JRE (Java Runtime Environment) — the software that lets a Pi run Java programs such as the Minecraft Java server.
  • -Xmx / -Xms — the options that set the maximum and minimum memory the Java server may use; leave several gigabytes free for the operating system.
  • EULA — Minecraft's End-User Licence Agreement, which you must accept (by editing eula.txt) before a Java server will run.
  • systemd service — a background program supervised by Linux; registering the server as one makes it start on boot and restart after a crash.
  • Port forwarding — a router rule that sends incoming internet traffic on a given port to a specific device, so friends outside your home can reach your server.
  • Tunnel (e.g. playit.gg) — a service that gives your server a public address without opening ports on your router or exposing your home IP.
  • Dynamic DNS — a memorable name that always points to your home's current (changing) public IP address.
  • TPS (ticks per second) — the heartbeat of a Java server; a healthy value is 20, and lower numbers mean the Pi is overloaded.
  • view-distance — how far players can see; the single biggest load on the server and the first thing to lower if it lags.

Project summary

  • Choose your edition by the devices your friends use: Bedrock for phones/consoles/Windows (the easy path), Java for PCs (use PaperMC).
  • A Pi 5 is a capable host — RAM sets the player count, so 8 GB or 16 GB is ideal; an SSD is the best upgrade for a busy world.
  • For Bedrock, download Mojang's official Linux server, edit server.properties, run it, and connect on port 19132.
  • For Java, install Java 21, download paper.jar, accept the EULA in eula.txt, and connect on port 25565.
  • Give the Java server a generous but safe -Xmx — never all of the Pi's RAM; leave 3–4 GB for the system.
  • Register the server as a systemd service so it starts on boot and restarts after a crash.
  • To let friends join from outside your home, prefer a safe tunnel like playit.gg, or set up port forwarding — and read the security chapter first.
  • Back up your world folder regularly with tar and copy it off the Pi.
  • Tune view-distance and simulation-distance down if the server lags, and watch temperature and TPS.
