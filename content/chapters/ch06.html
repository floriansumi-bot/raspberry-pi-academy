The terminal is probably the most misunderstood tool on any computer — it looks like something from a 1970s science-fiction film, but once you spend ten minutes with it you will wonder how you ever managed without it. This chapter strips away the mystery, teaches you how to read every part of the screen, walks you through the commands you will use every single day, and shows you how to edit files and run commands with administrator privileges — everything you need to feel genuinely at home in the Linux command line.

What is the Terminal, and Why Should You Care?

When you use a normal desktop application, you point at things and click. Behind the scenes, the computer is still receiving text commands — the graphical interface just hides them from you. The terminal (sometimes called the command line or console) lets you type those commands directly. There is no middleman.

In plain words: A terminal is a window that accepts typed commands and shows their output as text. A shell is the program running inside that window — it reads what you type, runs it, and prints the result. Raspberry Pi OS uses a shell called Bash (Bourne Again SHell). Think of the terminal as the telephone handset, and Bash as the person answering at the other end.

Why bother with it when there is already a desktop?

  • Speed. A three-word command can do in one second what would take ten mouse-clicks.
  • Power. Many tools — especially for programming, electronics, and servers — are only available from the command line.
  • Precision. Commands do exactly what you say, every time, with no guessing.
  • Automation. You can save a list of commands in a file and run them all at once.
  • Remote control. You can control your Pi over the network without ever plugging in a keyboard or screen, using only text.
Note: Nothing you type in the terminal can hurt your Pi's hardware. The worst that can happen with the commands in this chapter is deleting a file you did not mean to delete — which we will flag clearly and show you how to avoid.

Opening the Terminal

There are three easy ways to open a terminal window on Raspberry Pi OS:

  1. Look at the taskbar (the bar at the top of the screen). You will see a small black rectangle icon that looks like a screen — click it. A terminal window opens instantly.
  2. Click the Raspberry Pi menu (top-left corner, the raspberry icon) → Accessories → Terminal.
  3. Press the keyboard shortcut Ctrl + Alt + T — if nothing happens, use method 1 instead.

A dark window appears with some text and a blinking cursor. Do not worry about what it says yet — we will read it carefully in the next section.

Reading the Prompt — Every Part Explained

Before you can type anything, the shell prints a prompt: a short line of text that tells you who you are, which machine you are on, and where you are in the file system. It looks something like this:

pi@raspberrypi:~$
This is your prompt. It is made of four pieces joined together:
pi — your username (the account you are logged in as). The default user on Raspberry Pi OS is pi, though you may have chosen a different name when you first set up the Pi.
@ — just the "at" symbol, meaning "logged in at".
raspberrypi — the hostname of the machine (its name on the network). You can change this in Settings.
: — a colon separating the machine name from the current folder.
~ — a tilde symbol, which is a shortcut meaning "your home folder" (more on this in a moment).
$ — the dollar sign signals "I am ready; type your command here." If you ever see a # instead, it means you are running as the all-powerful root administrator — proceed carefully.

So the full prompt pi@raspberrypi:~$ means: "You are the user called pi, on the machine called raspberrypi, currently sitting in your home folder, and I am waiting for your command."

The Filesystem: a Single Tree Starting at /

On Windows your files live on drives such as C:\ and D:\. Linux (and therefore Raspberry Pi OS) works differently: there is exactly one big tree, and everything hangs off a single root.

In plain words: The filesystem is the way your operating system organises files into folders. On Linux the entire structure is one big upside-down tree. The very top of that tree is called root and is written as a single forward slash: /. Every folder and every file on the system lives somewhere below that slash.

The key folders you will encounter are:

Folder path What lives there
/ The very top of the tree — "root". Every path starts here.
/home Personal folders for all user accounts on the machine.
/home/pi (or your username) Your personal home folder. This is where your documents, downloads, and projects live. Also written as ~.
/etc System-wide configuration files — Wi-Fi settings, user lists, service settings.
/var "Variable" data: log files, print queues, emails — things that change while the system runs.
/usr Installed programs and their shared files live here (think of it as the equivalent of C:\Program Files).
/tmp Temporary files. The system wipes this on every reboot — never save anything important here.
/boot/firmware Files the Pi reads when it first powers on, including the kernel and configuration. Leave this alone unless a guide specifically tells you to edit something here.
/dev Device files — the terminal, USB drives, the GPIO pins, etc. Everything on Linux is treated as a file, including hardware.
/proc A virtual folder showing live information about running processes and hardware. Not real files — they are generated on the fly by the kernel.

The Anatomy of a Command

Every command you type follows the same pattern:

command  -options  argument(s)
command — the name of the program you want to run (e.g. ls, cp, mkdir).
-options (also called flags) — extra instructions that modify how the command behaves. They usually start with a hyphen and a single letter (-l) or two hyphens and a word (--help). They are optional.
argument(s) — the thing(s) the command should act on: a filename, a folder path, some text. Also optional depending on the command.

For example: ls -l /home/pi — the command is ls (list files), the option is -l (long format), and the argument is /home/pi (the folder to list).

Tip: Linux is case-sensitive. ls and LS are two different things. File names work the same way: Notes.txt and notes.txt are different files. Always type commands in lower case unless told otherwise.

Your First Commands

pwd — Where Am I?

pwd stands for Print Working Directory. It answers the question "which folder am I currently in?"

pwd
pwd — prints the full path of the folder you are currently in. When you first open the terminal this will be your home folder, so the output will be something like /home/pi.

ls — List What is in a Folder

ls stands for list. It shows you the contents of a folder, just like opening a folder in the file manager but in text form.

ls
ls -l
ls -a
ls -lah
ls — lists all visible files and folders in your current folder. Folders are usually shown in a different colour (blue by default).
ls -l — long format. Shows one item per line with extra detail: permissions, owner, file size, and the date it was last changed.
ls -a — shows all files, including hidden ones. Hidden files have names that start with a dot (e.g. .bashrc). They are hidden by default to keep the home folder tidy.
ls -lah — combines three flags at once: long format (-l), all files (-a), and human-readable file sizes (-h, so you see "4.0K" instead of "4096"). You can combine most single-letter flags like this.
In plain words: Permissions are rules that control who is allowed to read, change, or run a file. You will see a string like -rwxr-xr-x at the start of each line in ls -l output. For now, just know they exist — Chapter 8 covers them fully.

cd — Change Directory (Move Between Folders)

cd is how you "walk" through the filesystem tree. Think of it as double-clicking a folder, but in text form.

cd Documents
cd /home/pi/Downloads
cd ~
cd ..
cd -
cd Documents — move into the Documents folder that is inside your current folder. This is a relative path (relative to where you already are).
cd /home/pi/Downloads — move to Downloads using an absolute path (starting from /, the very top of the tree). Absolute paths always work regardless of where you currently are.
cd ~ — go straight back to your home folder, no matter where you are. The tilde (~) always means "my home folder". Typing cd with no argument does the same thing.
cd .. — go up one level to the parent folder. Two dots (..) always means "the folder above this one". Type it twice (cd ../..) to go up two levels.
cd - — go back to wherever you just were. A hyphen on its own means "the previous folder". Very handy when you are jumping between two distant locations.
Tip: After every cd, type pwd to confirm you are where you expected to be, until the habit becomes second nature.

clear — Tidy the Screen

clear
clear — scrolls all the previous output off the screen so you have a clean slate. Nothing is deleted; you can still scroll up to see the old output. The keyboard shortcut Ctrl + L does exactly the same thing.

mkdir — Make a New Folder

mkdir projects
mkdir -p projects/python/hello
mkdir projects — creates a new folder called projects inside your current folder. The name can be anything you like (avoid spaces — use underscores or hyphens instead, e.g. my-projects).
mkdir -p projects/python/hello — the -p flag means "create parent folders too, if they do not already exist". Without -p, this would fail if projects or projects/python did not already exist. With -p, all three folders are created in one go.

touch — Create an Empty File

touch hello.txt
touch hello.txt — creates a new, completely empty file called hello.txt in the current folder. If the file already exists, touch simply updates its "last modified" timestamp without changing its contents. It is the quickest way to create a blank file ready to be edited.

echo — Print Text (and Put it in a File)

echo Hello, Raspberry Pi!
echo Hello, world! > hello.txt
echo Another line >> hello.txt
echo Hello, Raspberry Pi! — prints the text Hello, Raspberry Pi! to the screen. Useful for checking values and for simple messages in scripts.
echo Hello, world! > hello.txt — the > symbol is called a redirect. It sends the output into a file instead of printing it to the screen. This creates (or overwrites) hello.txt with the text Hello, world!.
echo Another line >> hello.txt — a double >> means "append": add this text to the end of the file without destroying what is already there.
Careful: A single > will erase the existing contents of a file and replace them. Use >> if you want to add to the file instead. There is no undo.

cat — Read a File

cat hello.txt
cat hello.txt — prints the entire contents of hello.txt straight to the screen. The name comes from "concatenate" (join together) — you can pass multiple filenames and it will print them one after another. It is perfect for short files but impractical for long ones (see less below).

less — Read a Long File One Page at a Time

less /etc/os-release
less /etc/os-release — opens the file /etc/os-release (which contains information about your OS version) in a scrollable viewer. Navigate with: Space bar to scroll down one page, B to go back up, the arrow keys to move line by line, and Q to quit and return to the prompt.
Tip: Inside less, you can also search: press /, type the word you are looking for, and press Enter. Press N to jump to the next match.

cp — Copy a File or Folder

cp hello.txt hello-backup.txt
cp hello.txt Documents/
cp -r projects/ projects-backup/
cp hello.txt hello-backup.txt — makes a copy of hello.txt called hello-backup.txt in the same folder. The original is untouched.
cp hello.txt Documents/ — copies hello.txt into the Documents folder. The destination ends in / to make it clear it is a folder.
cp -r projects/ projects-backup/ — the -r flag stands for recursive: copy the folder and everything inside it, including sub-folders. Without -r, cp refuses to copy a folder.

mv — Move or Rename a File or Folder

mv hello.txt greetings.txt
mv greetings.txt Documents/
mv hello.txt greetings.txt — renames hello.txt to greetings.txt. There is no separate "rename" command in Linux — moving a file to a new name in the same folder is the same thing.
mv greetings.txt Documents/ — moves greetings.txt into the Documents folder. Unlike cp, the original is gone from its current location.

rm — Delete a File or Folder

Careful: The rm command permanently deletes files. There is no Recycle Bin, no undo, and no "are you sure?" prompt by default. Once you run rm, the file is gone. Always double-check your command before pressing Enter. When in doubt, move the file somewhere else with mv rather than deleting it outright.
rm hello-backup.txt
rm -r old-projects/
rm hello-backup.txt — permanently deletes the file hello-backup.txt. No second chance.
rm -r old-projects/ — deletes the folder old-projects and everything inside it recursively. This is the most powerful (and dangerous) form of the command. Triple-check the folder name before pressing Enter.
Tip: Add the -i flag to make rm ask "are you sure?" before each deletion: rm -i hello-backup.txt. Type y and Enter to confirm, or n and Enter to skip. Recommended while you are still learning.

Editing Files in the Terminal with nano

Sometimes you need to create or edit a text file without leaving the terminal — for example when following a guide that says "edit this configuration file". The easiest text editor built into Raspberry Pi OS is called nano. Unlike some other terminal editors, nano tells you what every key does at the bottom of the screen, so you never feel lost.

In plain words: nano is a terminal-based text editor. It opens a file inside the terminal window itself, lets you type and edit like a basic notepad, and saves the file when you tell it to — all without using a mouse.

Opening and Editing a File with nano

nano notes.txt
nano notes.txt — opens (or creates, if it does not exist) a file called notes.txt in the nano editor. The terminal screen changes: the file contents appear in the middle, your cursor is at the top, and two rows of keyboard shortcuts appear at the bottom. The caret symbol (^) in those shortcuts means Ctrl — so ^X means Ctrl + X.

Once nano is open, the essential key combinations are:

Key What it does
Arrow keysMove the cursor around
Ctrl + O then EnterSave the file ("Write Out")
Ctrl + XExit nano (it will ask you to save if you made changes)
Ctrl + KCut the current line
Ctrl + UPaste the cut line
Ctrl + WSearch for text (type your search word, then press Enter)
Ctrl + GOpen the full help page inside nano
Tip: The simplest way to save and exit is: press Ctrl + X, then when nano asks "Save modified buffer?", press Y, then press Enter to confirm the filename. Three key presses and you are done.

A Quick nano Practice

  1. Type nano mynote.txt and press Enter. Nano opens with a blank file.
  2. Type a few lines of text — anything you like.
  3. Press Ctrl + O to save. Nano shows the filename at the bottom — press Enter to confirm.
  4. Press Ctrl + X to exit. You are back at the normal prompt.
  5. Type cat mynote.txt to verify the file was saved correctly.

sudo — Running Commands as Administrator

Some tasks on your Pi — installing software, changing system settings, editing configuration files outside your home folder — require administrator privileges. On Raspberry Pi OS, the way to do this is to put the word sudo in front of your command.

In plain words: sudo stands for "superuser do". It temporarily grants your command the power of the root (system administrator) account. Without sudo, the system refuses to touch files that belong to it. With sudo, you become, for just that one command, the most powerful user on the machine.
Careful: sudo bypasses all normal safety checks. A sudo command can delete system files, change passwords, or break the operating system if used incorrectly. Only use sudo when a guide or command specifically requires it, and always double-check what you are typing before you press Enter.

How sudo Works

sudo apt update
sudo — run the following command with administrator (root) privileges.
apt update — refresh the Pi's list of available software packages from the internet. This command is explained fully in Chapter 7, but it serves as a perfect example: it needs to write to system folders, so it requires sudo.
The first time you use sudo in a session, the terminal will ask for your own password (not a separate admin password). Type it and press Enter — the characters will not appear on screen as you type, which is normal. Your password is remembered for a few minutes, so you will not be asked again immediately.
Note: On Raspberry Pi OS, the default user (the account you set up on first boot) is automatically granted sudo access. You do not need to do anything special to enable it.

Editing a System File with sudo nano

A very common pattern in Pi guides is using sudo together with nano to edit a configuration file that belongs to the system:

sudo nano /etc/hostname
sudo — open the following file with administrator rights, so nano is allowed to save changes to it.
nano /etc/hostname — opens the file /etc/hostname, which contains a single line: your Pi's network name. Without sudo, nano would open the file but refuse to save it, because ordinary users are not allowed to change system files. With sudo, you can edit and save it normally. Use the same Ctrl + O / Ctrl + X steps as before.
Tip: If you ever see a message like Permission denied when running a command, the fix is usually to put sudo in front of it. But think first: does it make sense for this command to need administrator access? If you are just editing a file in your home folder, Permission denied usually means you typed the wrong path instead.

Pipes and grep — Connecting Commands Together

One of the most powerful features of the Linux terminal is the ability to chain commands together so that the output of one command flows directly into the next. The symbol that joins them is called the pipe: | (the vertical bar on your keyboard, usually above the backslash key).

In plain words: A pipe is a connection between two commands. Whatever the first command would normally print to the screen is instead handed directly to the second command as its input. You can chain as many commands as you like with pipes.

grep — Search for Text

grep searches for a word or pattern in a file (or in output piped to it) and prints only the matching lines. It is one of the most useful commands in the terminal.

grep "raspberry" /etc/os-release
grep -i "raspberry" /etc/os-release
grep "raspberry" /etc/os-release — search the file /etc/os-release for lines that contain the word "raspberry" (case-sensitive) and print only those lines.
grep -i "raspberry" /etc/os-release — the -i flag makes the search case-insensitive, so it matches "raspberry", "Raspberry", "RASPBERRY", etc. Quote your search word if it contains spaces.

Using Pipes to Filter Output

Now combine ls with grep using a pipe:

ls /usr/bin | grep python
ls /usr/bin — lists everything in the /usr/bin folder, which contains hundreds of installed programs. On its own, the output would scroll off the screen.
| — the pipe: sends that long list to the next command instead of printing it.
grep python — filters the list, printing only the lines that contain the word "python". This lets you instantly see which Python-related programs are installed, without scrolling through hundreds of lines. 
history | grep sudo
history — produces your full command history as a list of lines.
| — pipes that list to grep.
grep sudo — shows only the lines from your history that contained the word "sudo". Useful for finding a complex command you typed earlier.

Getting Help at Any Time

--help — Quick Reference

Almost every command accepts a --help flag that prints a short summary of what it does and which options are available.

ls --help
ls --help — prints a concise description of the ls command and all its flags, right in the terminal. Scroll up to read it all. Replace ls with any other command name to get help for that command instead.

man — The Full Manual

In plain words: A man page (short for manual page) is the built-in documentation for a command. Every standard Linux command has one. They are detailed and sometimes quite technical, but they are always accurate.
man ls
man ls — opens the full manual page for ls. Navigate it the same way as less: Space to scroll down, B to go back, / to search, Q to quit. Replace ls with any command name to read its manual.
Note: Man pages can look intimidating because they are written for experienced users. Scroll past the dense "SYNOPSIS" section at the top and look for the "DESCRIPTION" and "EXAMPLES" sections — those are usually much more readable.

Working Smarter: Shortcuts That Save Typing

The terminal has several built-in features that make typing much faster. Use these from your very first session — they become automatic very quickly.

Tab Auto-completion

This is perhaps the single most useful feature in the terminal. When you start typing a command or a filename and press the Tab key, the shell tries to complete it for you automatically.

cd Doc
Type cd Doc and then press Tab (do not press Enter yet). If there is only one folder starting with "Doc", the shell will complete it to cd Documents instantly. If there are several matches (say Documents and Downloads), press Tab a second time to see a list of all options. Then type enough extra letters to make it unique and press Tab once more.
Tip: Tab-completion works for command names too, not just file and folder names. Type mk and press Tab twice to see all commands that start with "mk".

The Up Arrow — Command History

The shell remembers every command you have typed in this session (and across sessions). Press the Up arrow key to scroll back through previous commands. Press Down arrow to go forward again. Press Enter to run the selected command, or edit it first if you want to change something.

history — See Your Full Command History

history
history 20
history — prints a numbered list of all the commands you have typed, most recent at the bottom. Each line has a number on the left.
history 20 — shows only the last 20 commands. Replace 20 with any number you like.
Tip: You can re-run any command from the history list by typing ! followed by its number. For example, if command number 42 was ls -lah Documents, typing !42 and pressing Enter runs it again instantly. Or type !! to repeat the very last command.

Ctrl + C — Stop a Running Command

Sometimes a command gets stuck, takes too long, or you just change your mind. Ctrl + C sends a "stop" signal to whatever is currently running in the terminal and returns you to the prompt.

ping google.com
ping google.com — checks whether your Pi can reach google.com over the internet, printing one line per second indefinitely. To stop it, press Ctrl + C. You will see a summary line and then your prompt returns. Ctrl + C is safe to use on any command that has "gone quiet" or seems stuck.
Note: Ctrl + C in the terminal is completely different from Ctrl + C in Windows (which copies selected text). In the terminal, copying selected text is usually done with Ctrl + Shift + C, and pasting is Ctrl + Shift + V.

Putting it All Together: A Practice Session

The best way to learn these commands is to use them. Open a terminal and follow these steps — you cannot break anything here:

  1. Open the terminal. Check where you are: type pwd and press Enter. You should see /home/pi (or your username).
  2. List what is already in your home folder: type ls and press Enter. Then try ls -lah to see hidden files and file sizes.
  3. Create a practice folder: type mkdir terminal-practice and press Enter.
  4. Move into it: type cd ter then press Tab to auto-complete, then Enter.
  5. Confirm you are inside it: type pwd. You should see /home/pi/terminal-practice.
  6. Create a file with echo: type echo My first terminal file > notes.txt and press Enter.
  7. Read it back: type cat notes.txt. You should see My first terminal file.
  8. Add a second line: type echo A second line >> notes.txt then cat notes.txt again.
  9. Open the file in nano: type nano notes.txt. Add a third line, then press Ctrl + O, Enter to save, then Ctrl + X to exit.
  10. Search inside the file: type grep "line" notes.txt to see only the lines containing the word "line".
  11. Make a copy: type cp notes.txt notes-backup.txt. Then ls to see both files.
  12. Rename the backup: type mv notes-backup.txt backup.txt. Then ls again.
  13. Delete the backup: type rm backup.txt. Then ls to confirm it is gone.
  14. Go back to your home folder: type cd ~.
  15. Clear the screen: press Ctrl + L.

If you made it through all of those without an error message, you already know more about the Linux command line than many people who use computers every day. Well done.

Key terms

  • Terminal — a window in which you type commands and read their text output.
  • Shell — the program that runs inside the terminal, reads your commands, and executes them. Raspberry Pi OS uses Bash.
  • Bash — the most common Linux shell; the one you are using on your Pi.
  • Prompt — the line of text the shell prints before your cursor, showing your username, machine name, and current folder.
  • Root (/) — the very top of the Linux filesystem tree. Every path starts here.
  • Home folder (~) — your personal folder, usually /home/pi. The tilde is a shortcut for it.
  • Path — the address of a file or folder. An absolute path starts with /; a relative path starts from wherever you currently are.
  • Flag / option — a modifier added to a command (e.g. -l, --help) that changes its behaviour.
  • Argument — the thing a command acts on — usually a file name or folder path.
  • Tab completion — pressing Tab to let the shell finish typing a filename or command for you.
  • man page — the built-in manual for a command, opened with man <commandname>.
  • Redirect (>, >>) — sending a command's output into a file instead of the screen. > overwrites; >> appends.
  • Pipe (|) — connects two commands so the output of the first becomes the input of the second.
  • grep — a command that searches text for lines matching a word or pattern, printing only the matching lines.
  • nano — a beginner-friendly text editor that runs inside the terminal. Save with Ctrl + O, exit with Ctrl + X.
  • sudo — a prefix that runs a command with full administrator (root) privileges. Use only when required.
  • Ctrl + C — the keyboard shortcut to stop any running command and return to the prompt.

Chapter summary

  • The terminal is a text window where you type commands directly; Bash is the shell (the "brain") that runs inside it.
  • The prompt tells you your username, machine name, and current folder; the $ sign means "ready for input".
  • The entire Linux filesystem is one tree starting at /; your personal files live in /home/pi, written as ~.
  • Every command follows the pattern: command -options arguments.
  • The essential navigation commands are pwd (where am I?), ls (what is here?), and cd (take me somewhere).
  • You can create files with touch and echo, read them with cat and less, edit them with nano, copy with cp, move/rename with mv, and delete with rm — but remember rm has no undo.
  • Use sudo in front of a command when you need administrator privileges; your own password will be requested and remembered briefly.
  • The pipe character | connects commands together; grep filters output to show only matching lines — together they are incredibly powerful.
  • Tab auto-completion and the Up arrow key save enormous amounts of typing; use them from day one.
  • Get help for any command with --help for a quick summary or man <command> for the full manual.
  • Press Ctrl + C to stop any command that is running or seems stuck.
