This chapter tackles one of the most exciting things you can do with your 16 GB Raspberry Pi 5: run a genuine artificial-intelligence language model entirely on your own device, with no internet connection required, no cloud subscription, and nothing leaving your home. It is genuinely remarkable — and with honest expectations about speed, completely achievable.

What is an AI language model, in plain English?

You have probably heard of ChatGPT, Google Gemini, or similar tools that you type questions to and receive surprisingly thoughtful answers. Behind the scenes, each of those services runs a large language model — a piece of software that has been trained to understand and generate human language.

In plain words: A "large language model" (LLM) is a program that has read an enormous amount of text — books, websites, articles — and learned the patterns of how words and ideas connect. When you ask it a question, it predicts, word by word, what a useful and sensible answer looks like. It does not truly "think" or "know" things the way a person does, but the results can be remarkably helpful for writing, answering questions, summarising text, and generating code.

The difference between what you see on the internet and what you can run on your Pi comes down to model size. The biggest commercial models (the ones powering ChatGPT and Gemini) have hundreds of billions of parameters and require vast data centres filled with specialised hardware. The ones you can run at home are much smaller — but still impressively capable.

In plain words: "Parameters" are the millions or billions of internal numbers that a language model learned during training. Think of them like the settings on a very complicated machine. More parameters generally means a smarter model — but also one that needs more memory and runs more slowly. A model with 3 billion parameters is a small, efficient machine; a model with 70 billion parameters is a much larger one that needs far more RAM.

How models are measured — and what fits on a Pi

Model sizes are described in billions of parameters, written as "B". Common sizes you will encounter include 1B, 3B, 7B, 8B, and 13B. As a rough guide, the bigger the number, the smarter the answers — but also the more RAM needed and the slower it runs.

There is a clever technique called quantisation that makes models much more practical for home hardware.

In plain words: "Quantisation" is a form of compression applied to an AI model. The original model stores each parameter as a precise 32-bit or 16-bit number. Quantisation rounds those numbers down to 4 bits or 8 bits each — losing a tiny amount of accuracy but shrinking the model to roughly one quarter or one eighth of its original size. A 7B model that would normally need about 14 GB of RAM can, after 4-bit quantisation, fit in around 4–5 GB. The quality difference is usually small enough that you will not notice it for everyday tasks.

Your Pi 5 has 16 GB of RAM — four times more than the standard 4 GB model, and twice as much as the 8 GB version. This genuinely matters, because it allows you to run models in the 7B–8B range comfortably, while leaving enough memory for the operating system to run smoothly alongside them. Most other Pis can only manage 1B–3B models without grinding to a halt.

Model size Approx. RAM needed (4-bit quantised) Fits on your 16 GB Pi? Speed (tokens/second, approx.)
1B parameters ~1 GB Yes, easily 15–30 tokens/sec (fast)
3B parameters ~2–3 GB Yes, easily 8–15 tokens/sec (comfortable)

Note: "Tokens per second" is how AI speed is measured. A token is roughly three quarters of a word on average — so 5 tokens per second is about 4 words per second. That is slower than a fast typist but perfectly readable as the text appears on screen, one word at a time.

Setting honest expectations before you start

Before installing anything, please read this section — it will save you frustration.

  • Speed: Your Pi 5 runs AI on its main processor (CPU), not on a specialised AI chip. Expect text to appear at a readable pace — roughly like watching someone type — not instantly. A 7B model generating a paragraph may take 15–30 seconds. Smaller models are noticeably faster.
  • No image generation: Generating photorealistic images (like Stable Diffusion does) requires a powerful graphics card. The Pi 5 cannot do this at any practical speed. What we cover here is text — asking questions and getting answers.
  • Context length: Small models have a limited "memory" within a conversation. If you have a very long chat, the model may forget what was said at the beginning.
  • Accuracy: Small local models can make mistakes or "hallucinate" (confidently state something false). Always verify important facts from other sources.
  • Privacy: This is the genuine superpower. Everything stays on your device. No company sees your prompts, no data is sent anywhere, and it works with no internet connection at all. For sensitive documents, personal questions, or offline environments, this is a real advantage.

Installing Ollama

Ollama is a free, open-source tool that makes running AI models on your own computer as simple as typing one command. It handles downloading models, setting them up, and providing a straightforward way to chat with them. It also runs a small local web server in the background so that programs (like Python scripts) can send it questions and receive answers automatically.

Open a Terminal window (click the black screen icon in the taskbar, or go to the Applications menu and look under Accessories). Then type the following command exactly and press Enter:

curl -fsSL https://ollama.com/install.sh | sh

This is a single command split into two parts connected by a pipe (|):

  • curl -fsSL https://ollama.com/install.sh — curl is a program that fetches content from the internet. The flags -fsSL tell it to fail silently if something goes wrong (-f), suppress the progress bar (-s), still show errors if they occur (-S), and follow any web redirects (-L). The result is the Ollama installation script, downloaded directly into memory.
  • | sh — the pipe sends that downloaded script straight to sh (the shell, your command interpreter), which runs it immediately. This is a common one-line installation pattern in Linux.

In plain English: download the official Ollama installer and run it. The script detects that you are on a Raspberry Pi (Linux, 64-bit ARM) and installs the correct version automatically. You will see progress messages scrolling past. When you see your terminal prompt (pi@raspberrypi:~ $) again, installation is complete.

Careful: Running a script piped directly from the internet grants it full control over your system. Only do this for trusted, well-known projects. Ollama is a reputable open-source project at ollama.com — but as a general rule, always check the URL carefully before running such a command.

Confirm the installation was successful by asking Ollama for its version number:

ollama --version

ollama --version — runs the ollama program with the --version flag, which asks it to print which version is installed. If you see something like ollama version 0.9.x, everything worked. If you see "command not found", close the terminal window, open a fresh one, and try again — a new terminal session picks up the newly installed program.

Note: Ollama also installs itself as a background service that starts automatically every time your Pi boots. This means the AI server will always be ready when you want to use it, without any extra steps.

Pulling your first model

Ollama uses the word "pull" to mean "download a model from the internet and store it on your Pi". You only need to do this once per model — afterwards it lives on your microSD card and works completely offline.

In plain words: "Pulling" a model is similar to downloading an app. Once downloaded, you run it locally — no internet needed to use it, only to download it the first time.

Start with a small, fast model to make sure everything works. Gemma 3 1B is Google's efficient 1-billion-parameter model, quantised to fit in about 800 MB. It downloads quickly and is a good first test:

ollama pull gemma3:1b

ollama pull gemma3:1b — tells Ollama to download the Gemma 3 model at the "1b" (1 billion parameter) size. The part after the colon (:1b) is the tag, which selects which size or variant you want. Ollama will display a download progress bar. The file is about 815 MB, so on typical home broadband this takes one to three minutes.

Once that has downloaded, try a more capable model. Llama 3.2 3B is Meta's 3-billion-parameter model — noticeably smarter than Gemma 1B but still quick on your Pi:

ollama pull llama3.2:3b

ollama pull llama3.2:3b — downloads Meta's Llama 3.2 model at the 3-billion-parameter size. This is around 2 GB and takes a few minutes. It gives clearly better answers than the 1B model for most everyday tasks, while still running at a comfortable speed.

If you want the best quality that fits comfortably in your 16 GB Pi, you can pull an 8-billion-parameter model. This takes longer to download (around 5 GB) and generates text more slowly, but produces impressively thorough answers. The recommended 8B model is Llama 3.1 8B (note: Meta's Llama 3.2 series only goes up to 3B; the 8B model belongs to the Llama 3.1 series):

ollama pull llama3.1:8b

ollama pull llama3.1:8b — downloads the 8-billion-parameter Llama 3.1 model. At approximately 4.7 GB download size, it uses around 5–6 GB of RAM while running — well within your 16 GB Pi's capacity. Many users find this the best balance of quality and speed for a home device. Expect the download to take 15–30 minutes on typical home broadband.

Note: Model names and available tags change over time as new models are released. To see the full catalogue, visit ollama.com/library in your web browser. Popular choices for beginners include gemma3, llama3.2, llama3.1, phi4 (Microsoft — very strong for its size), and mistral (excellent for summarisation). Each model has different strengths; feel free to experiment.

To see all the models you have downloaded so far:

ollama list

ollama list — displays a table of every AI model currently stored on your Pi, including its name, tag, file size, and when it was last used. Use this to keep track of what you have downloaded and how much space each model takes.

Chatting with a model in the terminal

Now comes the rewarding part. To start a conversation with a model, use ollama run followed by the model name:

ollama run llama3.2:3b

ollama run llama3.2:3b — loads the Llama 3.2 3B model into your Pi's RAM and starts an interactive chat session right in the terminal. The first time you run a model after a reboot, there may be a short pause of a few seconds while it is loaded into memory. Once you see the >>> prompt appear, the model is ready and waiting for your message.

After a brief loading pause, you will see a prompt like this:

>>> Send a message (/? for help)

The >>> is Ollama's interactive chat prompt. Type your question or message and press Enter. The model will begin generating a response, word by word. When it finishes, the >>> prompt returns and you can ask another question. The model remembers everything said earlier in the session, so you can have a natural back-and-forth conversation.

Try typing something like this at the prompt:

>>> Explain what a Raspberry Pi is, in two sentences, for someone who has never heard of one.

Type this (or any question you like) after the >>> prompt and press Enter. Words will appear one by one at a comfortable reading pace. On a 3B model, a two-sentence answer typically takes about 5–10 seconds. On the 8B model, expect 15–25 seconds for the same question.

When you want to end the conversation and return to the normal terminal, type:

/bye

/bye — a special Ollama command (note the slash at the start, which distinguishes it from a question you would type to the model) that ends the chat session, unloads the model from memory, and returns you to the normal terminal prompt. You can also press Ctrl + D to exit.

Tip: Inside an Ollama chat session, type /? and press Enter to see all available slash commands. Useful ones include /clear (start a fresh conversation, making the model forget everything said so far), /show info (display technical details about the currently loaded model), and /set system "..." (give the model a persona or background instructions, for example /set system "You are a friendly French tutor").

Controlling the model from a Python script

Chatting in the terminal is enjoyable, but the real power comes from writing Python programs that can talk to the AI model automatically. Ollama runs a small web server in the background at all times while it is installed — your programs can send it questions and receive answers using simple web requests.

In plain words: A "web server" is a program that listens for requests and sends back responses — just like a website, but running locally on your own Pi. Ollama's built-in server listens at the address http://localhost:11434. "Localhost" means "this very machine" — the request never leaves your Pi. Your Python script sends a prompt to that address, and Ollama sends back the AI's answer.

Open Thonny (the Python editor — find it in the Programming section of the Applications menu). Create a new file, paste in the script below, and save it as ai_chat.py in your home folder. This script uses only Python's built-in libraries, so no extra installation is needed.

import urllib.request
import json

MODEL = "llama3.2:3b"

def ask(prompt):
    url = "http://localhost:11434/api/generate"
    data = {
        "model": MODEL,
        "prompt": prompt,
        "stream": False
    }
    body = json.dumps(data).encode("utf-8")
    req = urllib.request.Request(
        url,
        data=body,
        headers={"Content-Type": "application/json"},
        method="POST"
    )
    with urllib.request.urlopen(req) as response:
        result = json.loads(response.read().decode("utf-8"))
    return result["response"]

question = "What are three good reasons to learn Python programming?"
print("Asking the AI:", question)
print()
answer = ask(question)
print("AI says:")
print(answer)

Here is what each part of this script does:

  • import urllib.request — loads Python's built-in tool for making web requests. We use this to talk to Ollama's local server. Using the built-in library means no extra packages need to be installed.
  • import json — loads Python's built-in JSON tool. JSON (JavaScript Object Notation) is a simple text format used to package data — it looks like {"key": "value"}. Ollama communicates using JSON.
  • MODEL = "llama3.2:3b" — stores the model name in a variable so it is easy to change in one place. To use a different model, just update this line.
  • def ask(prompt): — defines a reusable function called ask. You give it a question (the prompt) and it returns the AI's answer. Everything indented below this line is part of the function.
  • url = "http://localhost:11434/api/generate" — this is Ollama's local web address for text generation. localhost means "this Pi", 11434 is the port Ollama listens on (a port is like a numbered door on a server), and /api/generate is the specific endpoint that accepts prompts.
  • data = {...} — creates a Python dictionary (a collection of labelled values) containing the request. model tells Ollama which model to use, prompt is the question, and "stream": False tells Ollama to wait until the full answer is ready before sending it back all at once (rather than word by word).
  • body = json.dumps(data).encode("utf-8") — converts the Python dictionary into a JSON-formatted text string, then encodes it into bytes (the raw binary format needed for sending over a network).
  • req = urllib.request.Request(...) — builds a web request object specifying the URL, the data to send, a header telling Ollama the data is in JSON format, and POST as the HTTP method (meaning "send data to this address and expect a response").
  • with urllib.request.urlopen(req) as response: — sends the request to Ollama and opens the response. The with keyword ensures the network connection is cleanly closed when we are done reading.
  • result = json.loads(response.read().decode("utf-8")) — reads the raw bytes of the response, decodes them into a text string, and parses the JSON into a Python dictionary we can work with.
  • return result["response"] — extracts just the AI's text answer from the dictionary and returns it. Ollama's reply contains several fields; the actual generated text is under the key "response".
  • question = "What are three good reasons..." — stores the question we want to ask. Change this to anything you like.
  • print("Asking the AI:", question) — prints the question to the screen so you can see what was sent.
  • answer = ask(question) — calls our ask function, sending the question to Ollama and waiting for the answer. This may take 10–30 seconds depending on the model and question length.
  • print("AI says:") / print(answer) — prints the AI's response to the output panel at the bottom of Thonny.
Note: Before running this script, make sure Ollama is running in the background. Because Ollama installs as a system service, it starts automatically when your Pi boots. You can verify it is running by opening a terminal and typing ollama list — if it shows your models without an error, the server is ready.

To run the script in Thonny, click the green Run button (the triangle) in the toolbar, or press F5. After a wait of 10–30 seconds, you should see the AI's answer printed in the panel at the bottom of Thonny.

Tip: Change the question variable to anything you like — ask it to summarise a paragraph of text you paste in, suggest a recipe, explain a concept, or help you draft an email. To use a smaller, faster model, change MODEL to "gemma3:1b". For more thoughtful answers at the cost of extra waiting time, change it to "llama3.1:8b".

Using the official Ollama Python library (optional)

The script above uses only Python's built-in libraries, which is great for learning. However, if you want a cleaner way to work with Ollama in Python, there is an official ollama library that simplifies the code considerably. Because Raspberry Pi OS Bookworm manages system Python packages carefully, the safest way to install it is inside a virtual environment.

In plain words: A "virtual environment" is a self-contained folder that holds a private copy of Python and any extra libraries you install into it. It keeps your project's packages separate from the rest of the system, avoiding conflicts. Think of it as a clean, isolated workbench just for one project.
  1. Open a terminal and create a folder for your AI project, then create a virtual environment inside it: 
    mkdir ~/ai-project
cd ~/ai-project
python3 -m venv venv
    • mkdir ~/ai-project — creates a new folder called ai-project in your home directory (~ is a shortcut for your home folder).
    • cd ~/ai-project — moves into that new folder.
    • python3 -m venv venv — creates a virtual environment in a subfolder called venv. The -m venv part tells Python to run its built-in virtual environment tool.
  2. Activate the virtual environment and install the Ollama library: 
    source venv/bin/activate
pip install ollama
    • source venv/bin/activate — activates the virtual environment. Your terminal prompt will change to show (venv) at the start, confirming it is active. While active, any pip install commands install packages only inside this private environment, not system-wide.
    • pip install ollama — downloads and installs the official Ollama Python library from the Python Package Index (PyPI). This is safe inside a virtual environment.
  3. Create a new Python file called ai_simple.py in the same folder with the following content: 
    import ollama

response = ollama.generate(
    model="llama3.2:3b",
    prompt="Explain in two sentences what the Raspberry Pi 5 is good for."
)
print(response["response"])
    • import ollama — loads the Ollama library you just installed.
    • response = ollama.generate(...) — sends a prompt to your locally running Ollama server and waits for the full answer. The model and prompt arguments work just like in the manual version earlier.
    • print(response["response"]) — prints the AI's text answer to the screen.
  4. Run the script from the terminal (make sure the virtual environment is still active): 
    python3 ai_simple.py

    python3 ai_simple.py — runs your Python script. After 10–30 seconds, the AI's answer will be printed in the terminal. When you have finished working in the virtual environment, type deactivate and press Enter to return to the normal terminal.

Note: When you return to this project in the future, you will need to activate the virtual environment again before running your scripts: navigate to the folder (cd ~/ai-project) and then run source venv/bin/activate. Your prompt will show (venv) to confirm it is active.

Managing your models — saving space

Each AI model takes up significant space on your microSD card — anywhere from 800 MB to 5 GB or more. To see how much space is currently used, run:

ollama list

ollama list — shows all downloaded models with their sizes. Use this to decide which models to keep and which to remove.

If you want to remove a model you no longer use, simply run:

ollama rm llama3.1:8b

ollama rm llama3.1:8b — deletes the specified model from your Pi, freeing up the disk space it was using. Replace llama3.1:8b with whichever model name you want to remove. You can always re-download it later with ollama pull.

Tip: If your microSD card is getting full, start by removing larger models you do not use regularly. The 8B model takes nearly 5 GB, while the 1B model is under 1 GB. Keep whichever model you use most, and re-download others as needed.

Other on-device AI: speech-to-text with Whisper

Language models are not the only AI you can run locally. Whisper, made by OpenAI and released as open-source software, is a speech-to-text system — it listens to an audio recording and converts it to written text. A fast compiled version called whisper.cpp runs well on the Pi 5 CPU without needing any cloud service.

In plain words: "Speech-to-text" means automatically turning spoken words into written ones — like live captions or a dictation tool. "Compiling from source code" means downloading the program as raw instructions and building it into a runnable application on your own computer. It takes a few minutes but is a one-time step.

Installing whisper.cpp requires building it from source code. Here are the full steps:

  1. Install the build tools needed to compile the program: 
    sudo apt install -y build-essential git
    • sudo apt install -y build-essential git — installs two packages. build-essential provides the compiler (the tool that turns source code into a runnable program), and git is a tool for downloading source code from the internet. The -y flag automatically confirms all prompts.
  2. Download the whisper.cpp source code to your Pi: 
    git clone https://github.com/ggerganov/whisper.cpp
    • git clone https://github.com/ggerganov/whisper.cpp — copies (clones) the entire whisper.cpp project from GitHub onto your Pi into a new folder called whisper.cpp. This is the source code you will compile in the next step.
  3. Enter the folder and compile the program: 
    cd whisper.cpp
make -j4
    • cd whisper.cpp — moves into the newly downloaded folder.
    • make -j4 — compiles the source code into a runnable program. The -j4 flag tells make to use all four CPU cores of your Pi 5 simultaneously, which speeds up the build significantly. This step typically takes 2–5 minutes. You will see many lines of output scrolling past — this is normal.
  4. Download a small English speech model: 
    bash ./models/download-ggml-model.sh base.en
    • bash ./models/download-ggml-model.sh base.en — runs the download script included with whisper.cpp to fetch the "base" English model. base.en is a fast, reasonably accurate model optimised for English speech. It is about 140 MB. Larger models (small.en, medium.en) are more accurate but slower.
  5. Transcribe an audio file (it must be in WAV format): 
    ./build/bin/whisper-cli -m models/ggml-base.en.bin -f your_recording.wav
    • ./build/bin/whisper-cli — runs the whisper.cpp transcription program that was built in step 3. The ./ prefix means "in the current folder".
    • -m models/ggml-base.en.bin — tells whisper.cpp which model file to use (the one downloaded in step 4).
    • -f your_recording.wav — specifies the audio file to transcribe. Replace your_recording.wav with the actual filename of your audio file. The file must be in WAV format (you can convert MP3 or other formats using the ffmpeg tool: sudo apt install -y ffmpeg, then ffmpeg -i input.mp3 output.wav).
Note: Whisper can also transcribe other languages and even detect the language automatically, using larger multilingual models (remove the .en from the model name, e.g. base instead of base.en). It is useful for transcribing voice memos, meeting recordings, or interview audio — entirely on your own device, with no data sent anywhere.

Simple image recognition with TensorFlow Lite

For basic image recognition (identifying everyday objects in photographs), the Pi 5's VideoCore VII graphics processor can accelerate lightweight models using TensorFlow Lite, which is available directly through the apt package manager.

In plain words: "Image recognition" means teaching a computer to identify what is in a photograph — a cat, a car, a banana. TensorFlow Lite is a lightweight version of Google's machine-learning framework, designed specifically for small devices like the Raspberry Pi. It uses pre-trained models, meaning the AI has already been taught to recognise thousands of objects; you just need to give it a photo.
sudo apt install -y python3-tflite-runtime

sudo apt install -y python3-tflite-runtime — installs TensorFlow Lite for Python 3 directly from the official Raspberry Pi OS software repository. This is the recommended method on Bookworm because it uses the system package manager rather than pip, avoiding any conflicts with the system Python. The -y flag automatically confirms the installation.

With TensorFlow Lite installed, you can run pre-trained image classification models to identify everyday objects in photos taken with a Raspberry Pi Camera or loaded from files. The Raspberry Pi Foundation's official documentation at raspberrypi.com/documentation/computers/camera_software.html contains complete step-by-step examples with sample code.

Tip: A good beginner project combining TensorFlow Lite and the Pi Camera is a "bird feeder identifier" — a Pi with a camera pointed at a bird feeder that automatically logs which species visit, entirely without a cloud service.

The Raspberry Pi AI HAT+ — optional hardware for serious speed

If you find that the Pi 5's CPU speed is too slow for your AI ambitions, there is an optional add-on board made by the Raspberry Pi Foundation called the AI HAT+. It contains a Hailo-8L neural network accelerator chip that connects to the Pi's PCIe slot.

In plain words: A "neural network accelerator" is a chip specially designed to perform the mathematical operations that AI models need, far faster than a general-purpose CPU can. Think of it as adding a dedicated AI co-processor to your Pi. The PCIe slot (a small connector on the underside of the Pi 5 board) is a high-speed data connection; the AI HAT+ uses it to communicate at maximum speed.

The AI HAT+ provides up to 13 TOPS (Tera Operations Per Second) of AI processing power, which is roughly 10–20 times faster than the Pi 5 CPU alone for vision tasks. It is designed particularly for real-time video analysis — detecting people, vehicles, faces, or objects in a live camera stream at full frame rates.

Task type Best approach on Pi 5 Why
Chat / text generation (LLMs) Ollama on CPU LLMs run on CPU RAM; AI HAT+ does not accelerate them significantly
Real-time object detection in video AI HAT+ (optional) HAT+ is 10–20× faster for vision models; CPU is too slow for real-time video
Speech-to-text (Whisper) CPU (whisper.cpp) Works well on Pi 5 CPU; HAT+ does not help here
Image classification (TensorFlow Lite) CPU or AI HAT+ CPU fine for single images; HAT+ needed for live video classification
Note: The AI HAT+ is available from official Raspberry Pi retailers for approximately £50–70 (around €55–80 in mainland Europe). Installation involves fitting it onto the 40-pin GPIO header and connecting a short ribbon cable to the PCIe slot — straightforward but it adds significant height, so check your case has room (an open-top or tall case works best).

Privacy: why running AI locally matters

Cloud AI services — ChatGPT, Copilot, Gemini, and others — are powerful, but every question you type is sent to servers owned by a company, stored, potentially used to improve future models, and subject to that company's privacy policy, data protection laws, and any future policy changes.

When you run AI on your Pi:

  • Your prompts never leave your home network.
  • Your questions are not stored or logged by any company.
  • It works with no internet connection at all — useful on a train, in a remote location, or anywhere connectivity is limited or expensive.
  • There is no subscription fee. Once downloaded, the model is yours to use indefinitely.
  • You are in complete control of what model is running and how it behaves.

This makes local AI genuinely useful for tasks involving personal information — summarising private documents, asking questions about medical or financial topics you would rather keep private, or working with confidential text.

Tip: If you would like a proper graphical chat interface (similar to the ChatGPT website, but talking to your local models), search for Open WebUI — a free, open-source web application that connects to Ollama and runs on your Pi. You access it by opening a browser on your Pi and going to http://localhost:3000 after installation. Full instructions are at openwebui.com.

Troubleshooting common problems

Ollama says "command not found" after installation

Close your terminal window and open a fresh one. The installation adds Ollama to your PATH (the list of locations the terminal searches for commands), and a new terminal session picks up the change automatically. If the problem persists, type the following and try again:

source ~/.bashrc
ollama --version
  • source ~/.bashrc — reloads your shell configuration file without closing and reopening the terminal. This picks up any changes made to your PATH during installation.
  • ollama --version — checks whether Ollama is now found and prints its version number. If this still fails, try restarting your Pi (sudo reboot) and trying again.

The model download is very slow

AI models are large files — 1–5 GB is normal. On a typical home broadband connection this takes anywhere from 5 minutes to half an hour. Connect your Pi via an Ethernet cable rather than Wi-Fi for a faster and more reliable download. Downloads can be resumed — if a download is interrupted, just run the same ollama pull command again and it will continue from where it left off.

Running a model makes the Pi very sluggish

While a large model is generating text, it uses most of the Pi's CPU. This is normal and expected — wait for the response to finish and the Pi will return to its normal responsiveness. If things are uncomfortably slow, switch to a smaller model (for example, gemma3:1b instead of llama3.1:8b). You can also close other applications while the model is generating.

The Python script says "Connection refused"

Ollama's background server may not be running. Check its status with:

sudo systemctl status ollama

sudo systemctl status ollama — checks whether the Ollama background service is currently running. You will see either Active: active (running) highlighted in green, meaning all is well, or a stopped or failed status. If it is not running, start it with the next command.

If it is stopped, start it manually:

sudo systemctl start ollama

sudo systemctl start ollama — starts the Ollama service immediately. To make it start automatically every time the Pi boots (which is the default after installation), run sudo systemctl enable ollama.

The model gives wrong or strange answers

This is a known limitation of all current language models, especially smaller ones. It is called hallucination — the model confidently produces text that sounds plausible but is factually incorrect. Always verify important information from a reliable source. Smaller models hallucinate more often than larger ones. Providing more context in your prompt often helps: instead of "What is the boiling point of water?", try "You are a physics teacher. Please explain the boiling point of water at sea level."

Make sure build-essential and git are installed (run sudo apt install -y build-essential git again). Also ensure you have enough free disk space — the build process temporarily needs several hundred megabytes. Run df -h ~ to check how much free space you have on your microSD card.

df -h ~

df -h ~ — shows the disk usage of the filesystem where your home folder lives. The -h flag makes the sizes human-readable (showing GB or MB rather than raw bytes). The "Available" column tells you how much free space remains. You need at least 1 GB free for the build, plus space for model files.

Key terms

  • Large Language Model (LLM) — a type of AI program trained on vast amounts of text, capable of understanding and generating human language.
  • Parameters — the numerical values learned during AI training; measured in billions (e.g. 7B = 7 billion). More parameters generally means a more capable but larger, slower model.
  • Quantisation — a compression technique that reduces a model's file size and RAM usage by storing its numbers at lower precision, with only a small loss of quality.
  • Ollama — a free, open-source tool for downloading and running AI language models locally on your own device.
  • Tag — the part after the colon in an Ollama model name (e.g. :3b, :8b) that specifies which size or variant of a model to download.
  • Token — roughly three quarters of a word; the unit AI models use internally. "Tokens per second" measures how fast a model generates text.
  • Localhost — a special network address meaning "this computer itself". Ollama's local server is accessed at http://localhost:11434, which never leaves your Pi.
  • Port — a numbered "door" on a server that allows different services to listen on the same machine. Ollama uses port 11434.
  • API — Application Programming Interface; a defined way for programs to talk to each other. Ollama provides an API so Python scripts can send prompts and receive answers automatically.
  • Virtual environment — a self-contained folder holding a private copy of Python and its installed packages, keeping a project's dependencies separate from the rest of the system.
  • Hallucination — when an AI model confidently generates text that is factually incorrect. A known limitation of all current language models, more common in smaller models.
  • Whisper / whisper.cpp — an open-source speech-to-text AI made by OpenAI; whisper.cpp is a fast compiled version that runs efficiently on the Pi 5 CPU.
  • TensorFlow Lite — a lightweight machine-learning framework for small devices, used for image classification and other AI tasks on the Pi without a cloud service.
  • AI HAT+ — an optional Raspberry Pi add-on board containing a Hailo neural network accelerator chip, dramatically speeding up real-time vision AI tasks.
  • PCIe — a high-speed hardware connection on the Pi 5 used by add-on boards like the AI HAT+ to communicate at fast data rates.
  • TOPS — Tera Operations Per Second; a measure of AI chip performance. The AI HAT+'s Hailo chip delivers up to 13 TOPS.

Chapter summary

  • A large language model (LLM) is an AI program trained on text; it generates answers word by word based on patterns it learned during training.
  • Model size is measured in billions of parameters (1B, 3B, 7B, 8B…); larger models give better answers but need more RAM and run more slowly.
  • Quantisation compresses models to roughly a quarter of their original size with minimal quality loss, making 7B–8B models practical on home hardware.
  • Your 16 GB Pi 5 can comfortably run 7B–8B quantised models — far more capable than what fits in the 4 GB or 8 GB versions.
  • Ollama installs with a single terminal command and handles downloading, storing, and running models automatically; it also starts as a background service on every boot.
  • Use ollama pull <name> to download a model, ollama run <name> to chat interactively, and ollama list to see what is stored.
  • Note that Llama 3.2 only comes in 1B and 3B sizes; the recommended 8B model is llama3.1:8b.
  • A Python script using only built-in libraries can send prompts to Ollama's local API and display the AI's answers; the optional ollama Python library simplifies this further when used inside a virtual environment.
  • Whisper.cpp provides offline speech-to-text; TensorFlow Lite enables image recognition — both run on the Pi CPU without any cloud service.
  • The optional Raspberry Pi AI HAT+ (Hailo accelerator) dramatically speeds up vision tasks like real-time object detection; it does not significantly help text generation.
  • Running AI locally means complete privacy — your prompts never leave your device, no subscription is needed, and it works with no internet connection.
  • Expect text to appear at a readable but modest pace; small models can hallucinate (state incorrect facts confidently), so always verify important information elsewhere.
