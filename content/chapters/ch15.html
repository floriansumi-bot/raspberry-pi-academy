Adverts and tracking scripts slow down web pages, clutter your screen, and quietly follow you around the internet. In this chapter you will turn your Raspberry Pi into a network-wide ad blocker called Pi-hole — a free, open-source tool that protects every phone, tablet, laptop, and smart TV in your home without installing anything on those devices.

How the internet "looks up" websites — and how Pi-hole exploits that

Before you install anything, it helps to understand the clever trick that makes Pi-hole work.

DNS: the internet's phone book

In plain words: DNS stands for Domain Name System. When you type www.bbc.co.uk into your browser, your computer does not actually know where that is. It first asks a special server — called a DNS resolver — to translate the human-readable name into a numerical address (like 151.101.0.81). That numerical address is an IP address — the internet's equivalent of a postal code for a computer. Only once your device has that number can it actually connect to the site.

Every time you load a web page, dozens of these look-ups happen in the blink of an eye — one for the main site, and more for every advert, tracking pixel, and analytics script the page tries to load. Your home router normally forwards all of these look-up requests out to a DNS server run by your internet provider (or Google, or Cloudflare).

What Pi-hole does differently

Pi-hole installs itself as your home network's DNS server. Instead of forwarding every request straight to the internet, it first checks each domain name against a list of known advertising and tracking domains. If the name is on the list, Pi-hole returns a harmless "not found" answer — so the advert or tracker simply never loads. If the name is legitimate (like bbc.co.uk), Pi-hole forwards the request normally and your browser gets the page.

The beauty of this approach is that nothing needs to be installed on your phone, tablet, or smart TV. As long as those devices use your Pi as their DNS server, they are automatically protected. Pi-hole also keeps detailed logs, so you can see exactly what domains are being blocked — or which device in your home is the chattiest tracker-loader.

Before you start: what you need

  • Your Raspberry Pi 5, already set up with Raspberry Pi OS Bookworm and connected to your home network (wired Ethernet is strongly recommended — a Pi running a network service works best with a cable, not Wi-Fi).
  • Your Pi's current IP address. You can find this by opening a terminal and typing hostname -I — write it down, you will need it throughout this chapter.
  • Access to your router's settings page (usually by opening a browser and visiting 192.168.0.1 or 192.168.1.1). If you do not know your router's address, look for it printed on the back of the router.
  • Your router's admin username and password (also usually on a sticker on the router).
Tip: Running Pi-hole over a wired Ethernet connection is much more reliable than over Wi-Fi. If your router is in a different room, a powerline adapter (a pair of plugs that send network data through your house's mains wiring) is a cheap way to get a wired connection without running a cable across the floor.
Note — Pi-hole version: This chapter covers Pi-hole version 6, which became the default install from 2025 onwards and is the version you will get when following the instructions below on Raspberry Pi OS Bookworm. Pi-hole v6 has a modernised command-line interface and a refreshed web dashboard. If you find older guides online that use commands beginning with pihole -a, pihole -g, or pihole -up, those are Pi-hole v5 commands and will not work on a fresh install today.

Step 1 — Give your Pi a fixed IP address

Pi-hole is going to act as your network's DNS server. Every device in your home will be told to send its DNS requests to a specific IP address — the address of your Pi. If that address ever changes (which it can, because home routers normally hand out addresses at random), all those devices would suddenly lose the ability to look up websites. So the first job is to make sure your Pi always gets the same IP address.

There are two common ways to do this:

Option A — Reserve the address in your router (recommended)

Most home routers let you look at the list of connected devices and "reserve" (or "pin") an address to a specific device's network identity (called its MAC address — a unique identifier permanently built into every network adapter). Once reserved, the router always gives that device the same address. This is called a DHCP reservation or a static lease.

In plain words: DHCP (Dynamic Host Configuration Protocol) is the system your router uses to automatically give IP addresses to devices that join the network. By default it hands them out however it likes, but you can tell it "always give this device this address". That is a DHCP reservation.

The exact steps depend on your router's brand, but in general:

  1. Log in to your router's admin page in a browser (for example http://192.168.1.1).
  2. Look for a section called "Connected Devices", "LAN", "DHCP", or "IP & MAC Binding".
  3. Find your Raspberry Pi in the list (it may be labelled "raspberrypi" or show its current IP).
  4. Click the option to reserve or pin that IP address to the Pi's MAC address.
  5. Save the settings. Your Pi will keep that address from now on.
Note: If your router does not have this feature (some very basic models do not), you can set a static IP directly on the Pi itself using the Raspberry Pi OS network settings. Right-click the network icon in the top-right corner of the desktop, choose "Wireless & Wired Network Settings", select your connection, and fill in a fixed IP address, the router's address as the gateway, and a DNS server (use 8.8.8.8 temporarily — you can update this later once Pi-hole is running). Check your router's documentation or look at the addresses your router is currently handing out to choose an address that will not clash with other devices.

Option B — Set a static IP on the Pi using the terminal (alternative)

If you prefer to configure the static IP from the Pi's terminal rather than the router interface, open a terminal and use the NetworkManager command-line tool. Type each of the following commands one at a time, pressing Enter after each.

nmcli con show

Lists all network connections that NetworkManager knows about on your Pi. Look for the name of your wired connection (typically something like Wired connection 1) — you will use that exact name in the next command.

Note: The long command below is split across several lines using the \ backslash character at the end of each line. This just means "the command continues on the next line" — it is one single command. Type it exactly as shown, including the backslashes, or paste it all in one go.
sudo nmcli con mod "Wired connection 1" \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 8.8.8.8 \
  ipv4.method manual

sudo — runs the command with administrator (superuser) privileges, which are needed to change network settings.

nmcli con mod "Wired connection 1" — tells NetworkManager to modify the named connection. Replace the name in quotes with whatever your connection is actually called (as shown by the previous nmcli con show command).

ipv4.addresses 192.168.1.100/24 — sets the fixed IP address you want. Replace 192.168.1.100 with an address that is on your network but not already in use. The /24 is the network mask — it means this is a typical home network where the first three numbers are shared and the last can range from 1 to 254.

ipv4.gateway 192.168.1.1 — tells the Pi the address of your router (the gateway to the wider internet). Adjust this to match your actual router address.

ipv4.dns 8.8.8.8 — sets a temporary DNS server (Google's public DNS) so the Pi can look up websites during the Pi-hole installation. You will point this at Pi-hole itself later.

ipv4.method manual — switches this connection from "automatic" (DHCP) to "manual" (static), meaning it will use the values you just provided instead of asking the router for an address.

sudo nmcli con up "Wired connection 1"

Activates the updated connection settings so the change takes effect immediately, without needing to reboot the Pi. Replace the name in quotes with the actual name of your connection if it is different.

Careful: If you change the Pi's IP address while connected remotely over SSH, your SSH session will disconnect because the Pi is now at a different address. You will need to reconnect using the new IP address. If you are working directly at the Pi with a keyboard and screen attached, this is not a problem.

Step 2 — Install Pi-hole

Pi-hole has an official automated installer. It is a shell script — a file containing a sequence of commands — that is downloaded from the internet and run on your Pi. The installer handles everything: it installs all the required software, sets up Pi-hole as a background service, and prepares the web dashboard.

In plain words: A shell script is simply a text file full of commands, just like the ones you type in a terminal. Instead of typing them one by one, you run the whole file at once. The Pi-hole installer is a very long shell script maintained by the Pi-hole team.
Note — should you trust piping a script to bash? The install command below uses a pattern called "piping to bash": it downloads a script and immediately runs it. You should only ever do this for software from a project you trust, from its official website, and over a secure https:// connection. Pi-hole is a well-known, open-source project maintained by a large community; its installer is publicly readable on GitHub; and the download uses HTTPS. If you are uneasy, you can download the script first with curl -O https://install.pi-hole.net/install.sh, inspect it with nano install.sh, and then run it manually with bash install.sh. For most beginners, running the one-liner from the official documentation is perfectly reasonable.

  1. Open a terminal on your Raspberry Pi (or SSH into it from your main computer — see Chapter 10 if you need a reminder of how to do this).

  2. Make sure your Pi's software is up to date before installing:

    sudo apt update && sudo apt full-upgrade -y

    sudo apt update — refreshes the list of available software packages from the internet.

    && — means "only run the next command if the previous one succeeded".

    sudo apt full-upgrade -y — installs all available updates. The -y flag answers "yes" automatically to any prompts, so you do not have to watch it.

  3. Run the Pi-hole installer:

    curl -sSL https://install.pi-hole.net | sudo bash

    curl — a command-line tool for downloading files from the internet.

    -sSL — three options combined: -s runs silently (hides the progress bar), -S still shows errors if something goes wrong, -L follows any web redirects automatically.

    https://install.pi-hole.net — the official Pi-hole installer URL, served securely over HTTPS.

    | — the "pipe" symbol; it takes the output of the command on the left (the downloaded script text) and passes it directly as input to the command on the right.

    sudo bash — runs the received script as an administrator using the bash shell. Administrator access is necessary because the installer needs to change system settings, install packages, and configure background services.

  4. The installer will print progress messages as it works — downloading components, configuring the DNS service, and setting up the web interface. This usually takes two to five minutes depending on your internet speed. You do not need to interact with it during this time.

    Note: Pi-hole version 6 (the current version) runs its installer entirely in the background without interrupting you with dialogue boxes. When it is finished, it will print a short summary including your Pi's IP address and a temporary admin password. Copy or write down that password immediately — you will need it to log in to the dashboard for the first time.

  5. When the installer finishes, it prints something like this (with your actual IP address and a different password):

      [✓] Installation complete!

  Pi-hole Web Interface: http://192.168.1.100/admin
  Admin password:        AbCd1234XyZ

    This is a summary message printed by the installer — not a command you type. It tells you the address of your Pi-hole dashboard and the randomly generated password for the admin account. Write both down now.

Tip: If you miss the password or scroll past it, do not worry — you can reset it at any time using pihole setpassword in the terminal, which is covered later in this chapter.

Step 3 — Complete the initial setup in the web dashboard

Pi-hole v6 completes its configuration through its own web interface rather than during the installer. Open a browser on any device on your home network and go to:

http://192.168.1.100/admin

Replace 192.168.1.100 with the actual IP address of your Pi — the one you noted down or fixed in Step 1. This opens Pi-hole's administration dashboard in your browser.

Log in with the temporary password shown by the installer. Once logged in, the dashboard will walk you through a short setup wizard. Here is what each step asks and what to choose:

Setup step What it is asking What to choose
Network interface Which network connection should Pi-hole listen on? Choose eth0 for wired Ethernet (recommended). If you are using Wi-Fi only, choose wlan0.
Upstream DNS provider When a domain is not blocked, which DNS server should Pi-hole forward requests to? Choose Cloudflare (1.1.1.1 — fast and privacy-respecting) or Google (8.8.8.8). Either works well; you can change this later in Settings.
Blocklists Which default list of ad/tracker domains should Pi-hole use? Leave the default list enabled (StevenBlack's unified list) — it is a well-maintained, comprehensive starting point blocking around 150,000 known ad and tracker domains.
Query logging Should Pi-hole keep a log of every DNS look-up? Leave this on — it is very useful for spotting what is being blocked and why, and for troubleshooting when a site stops working.
Privacy mode How much detail should the log show about individual clients? Choose Show everything — since this is your own home network, full detail is helpful for troubleshooting.

After the wizard, you may also want to change the admin password to something more memorable. Go to Settings → Web Interface (or use the terminal command described later in this chapter).

Step 4 — Point your router's DNS at Pi-hole

Pi-hole is now installed and running on your Pi, but your other devices do not know it exists yet. You need to tell your router to use the Pi as its DNS server. Once you do that, the router will pass on the Pi's address to every device on the network, so they all automatically use Pi-hole.

In plain words: Your router acts like a post room for your home network. When a device joins, the router tells it several things: "Here is your address, here is where the gateway to the internet is, and here is the phone-book server (DNS) you should use." By changing that last item to your Pi's address, all devices automatically use Pi-hole as their phone book — without you needing to do anything on each device individually.
  1. Log in to your router's admin page (for example http://192.168.1.1) using your router's admin username and password.
  2. Find the DHCP settings. These are often under a section called "LAN", "DHCP Server", "Network Settings", or "Advanced".
  3. Find the field labelled "Primary DNS" (sometimes called "DNS Server 1").
  4. Change that field to your Pi's fixed IP address (for example 192.168.1.100).
  5. For the "Secondary DNS" (or "DNS Server 2") field, consider leaving it blank. If you enter a secondary DNS server (such as 8.8.8.8), some devices may bypass Pi-hole and use the secondary server directly — especially if your Pi is slow to respond. Leaving it blank means every DNS request goes through Pi-hole, though it also means that if your Pi is powered off, internet browsing will stop working for all devices until the Pi comes back on.
  6. Save and apply the settings. Some routers need a restart. Wait a minute, then test that the internet still works on another device (your phone, for example).
Note: Changes to DHCP settings only take effect on a device after it renews its "lease" — essentially, after it asks the router for its settings again. This usually happens automatically within a day, but you can speed it up immediately. On Windows, open a Command Prompt and type ipconfig /release followed by ipconfig /renew. On macOS, turn Wi-Fi off and back on, or open System Settings → Network and click Renew DHCP Lease. On Linux, toggle the network connection off and on. On a phone, turn Wi-Fi off and back on, or forget the network and reconnect.

Alternative: set DNS per device instead

If you do not have access to your router (for example if it belongs to a landlord or a shared household), you can instead set the DNS server individually on each device you want to protect. On Windows 11, go to Settings → Network & Internet → Wi-Fi → [Your network] → Properties and set DNS to "Manual" with your Pi's IP. On macOS, go to System Settings → Network → [Your network] → Details → DNS and add your Pi's IP as a DNS server. On Linux, open your network connection's settings, switch the IPv4 DNS to "Manual" (or "Automatic (Addresses only)"), and enter your Pi's IP. On iPhone/iPad, tap the (i) next to your Wi-Fi network, then tap "Configure DNS" and switch to "Manual". On Android, go to Wi-Fi settings, long-press your network, and look for "Advanced options" where you can set a Static IP and DNS.

Step 5 — Confirm that it is working

  1. On any device on your home network, open a browser and go to http://192.168.1.100/admin (using your Pi's IP address). The Pi-hole admin dashboard should appear.
  2. Log in with the admin password.
  3. Browse to a few websites on your phone or laptop. Return to the Pi-hole dashboard and watch the query counter go up and the live graph begin to show activity — this confirms those devices are now routing their DNS look-ups through Pi-hole.
  4. If nothing appears in the dashboard, the device has not yet received the new DNS setting from the router. Try turning Wi-Fi off and on, or use the lease-renewal trick for your computer described in the Note above (on Windows, ipconfig /release then ipconfig /renew).
Tip: On the Pi-hole dashboard home page you will see a figure like "23% of queries blocked" after a few minutes of browsing. Most homes settle somewhere between 15% and 40%, depending on which sites and apps are in use. The higher the percentage, the more ads and trackers were silently trying to reach your devices.

Using the admin dashboard

The Pi-hole admin dashboard at http://<your-pi-ip>/admin is your control centre. Here is a quick tour of the main sections:

Dashboard section What it shows / lets you do
Summary (home page) Total queries today, percentage blocked, number of domains on the blocklist, and a live traffic graph.
Query Log A real-time list of every DNS look-up made by every device. Green = allowed, red = blocked. Click any entry to add that domain to your allowlist or denylist instantly.
Top Blocked Domains The ad/tracker domains being blocked most often — often reveals hundreds of hidden trackers you never knew about.
Allowlist / Denylist Manually add domains you want to always allow (allowlist, formerly "whitelist") or always block (denylist, formerly "blacklist"), beyond the automatic blocklists.
Group Management Create groups of devices and apply different blocklists to each group — for example, a stricter content-filtering list for a child's tablet.
Lists Add additional blocklists (many are maintained by the community) and update or disable existing ones.
Settings Change the upstream DNS provider, manage Pi-hole's own IP, configure logging, change the admin password, and more.

Resetting or changing the admin password

If you lose the password or just want to set something more memorable, open a terminal on the Pi and run:

pihole setpassword

pihole — the Pi-hole command-line management tool, installed automatically as part of the Pi-hole setup.

setpassword — prompts you to type a new password for the web admin interface (you will be asked to type it twice to confirm). If you just press Enter twice without typing anything, Pi-hole removes the password requirement entirely — useful on a private home network where you are not concerned about other household members accessing the dashboard.

Note: You can also change the password through the dashboard itself: go to Settings → Web Interface and look for the password change option.

Allowing a domain when something breaks

Occasionally Pi-hole will block a domain that a website or app genuinely needs, and things will stop working in an unexpected way. Symptoms include: a website that loads with missing images or buttons, a video service that will not start, or an app that cannot connect to its servers. When this happens, Pi-hole is the first thing to check.

How to diagnose and fix a blocked domain

  1. Open the Pi-hole dashboard and click Query Log.
  2. Try using the broken website or app again, then immediately look at the query log. Filter by your device's IP address if needed. Look for red (blocked) entries that appeared at the same moment as the problem. The domain name shown is the one being blocked.
  3. To allow that domain, click the green circle-with-plus icon next to it in the query log, or go to Allowlist, type the domain, and click "Add to Allowlist".
  4. Refresh the page or restart the app that was broken — it should now work normally.

You can also add a domain to the allowlist from the command line:

pihole allow example.com

pihole — the Pi-hole management tool.

allow — adds the specified domain to the allowlist (the list of domains that will always be permitted through, regardless of any blocklist).

example.com — replace this with the actual domain name you want to permit, for example cdn.somesite.com.

To permanently block a specific domain that is not on any blocklist (for example, a distracting social media site):

pihole deny example.com

pihole — the Pi-hole management tool.

deny — adds the specified domain to the denylist, which means Pi-hole will always block it, even if it does not appear on any of the subscribed blocklists.

example.com — replace this with the domain you want to block, for example www.tiktok.com.

Tip: If you suspect Pi-hole is causing a problem but are not sure, you can temporarily pause it from the dashboard by clicking Disable on the home page (options include 10 seconds, 30 seconds, 5 minutes, or indefinitely). If things start working with Pi-hole disabled, Pi-hole is responsible — use the query log to find out which domain to add to the allowlist.

Keeping Pi-hole up to date

The list of ad and tracker domains that Pi-hole blocks is constantly being updated by the community, and Pi-hole itself receives software improvements. Updating is a single command:

pihole update

pihole — the Pi-hole management tool.

update — checks for a newer version of Pi-hole itself and installs it if available. It will print progress messages as it works and usually finishes within a minute or two.

To refresh your blocklists (making Pi-hole download the latest versions of all the ad-domain lists you have subscribed to):

pihole gravity

pihole — the Pi-hole management tool.

gravity — runs Pi-hole's "gravity" process: it downloads the latest version of every blocklist you have subscribed to, combines them, removes duplicate entries, and builds an efficient lookup database. Pi-hole calls this process "gravity" because it pulls in all your lists and compresses them into one. Pi-hole runs this automatically on a weekly schedule, but you can run it manually at any time — for example after adding a new blocklist.

Tip: Pi-hole automatically updates its blocklists on a schedule, so you do not need to run pihole gravity every day. Running pihole update once a month is plenty to keep the core software current.

Adding more blocklists

The default blocklist (StevenBlack's unified list) is a solid starting point. But the community maintains many more lists you can add for broader or more specific protection:

  • OISD Big list — a very comprehensive, actively maintained list. URL: https://big.oisd.nl
  • HAGEZI DNS Blocklists — multiple tiers from light to ultra-aggressive. Find them at https://github.com/hagezi/dns-blocklists
  • Malware and phishing domain lists — many lists exist that block known malicious sites, adding a useful security layer on top of ad blocking.

To add a list, go to Lists in the Pi-hole dashboard, paste the URL into the "Address" field, and click "Add". Then run the gravity update to download the new list and incorporate it into the blocklist:

pihole gravity

Same as above — downloads and merges all your subscribed blocklists into the active blocking database. Any new list you just added in the dashboard will be included.

Careful: Adding very large or very aggressive blocklists can accidentally block websites or services you legitimately use. Start with one or two extra lists and monitor the query log for unexpected breakage before adding more.

Honest limits: what Pi-hole cannot block

Pi-hole is genuinely impressive, but it is important to understand what it cannot do, so you are not disappointed:

  • YouTube adverts: YouTube (and the YouTube app on phones and TVs) serves its adverts from the same domain as the actual videos. Pi-hole cannot block those adverts without also blocking the videos themselves. For YouTube ad-blocking you need a browser extension like uBlock Origin (in a desktop browser) or a modified app on mobile devices.
  • Adverts embedded in apps: Some apps serve adverts from their own servers on the same domain as their content, making it impossible for Pi-hole to tell an advert from legitimate app data.
  • Encrypted DNS (DNS over HTTPS / DoH): Newer devices and apps can sometimes use DNS over HTTPS, which routes DNS requests through an encrypted channel that bypasses Pi-hole entirely. You can configure your router to block DoH if this becomes a concern, though it requires additional steps beyond this chapter.
  • It is not a VPN or firewall: Pi-hole only operates on DNS look-ups. It does not encrypt your internet traffic, hide your IP address, or block non-DNS connections to tracking servers.
  • Brand-new advertising domains: Domains that have not yet been added to any blocklist will slip through until the community adds them and you run a gravity update.
Note: Despite these limits, most users find that Pi-hole blocks 20–30% of all network requests in their home. Pages load noticeably faster, many types of cross-site tracking are stopped entirely, and some smart-TV channels that previously interrupted viewing with adverts become much cleaner. It is not a silver bullet, but it is one of the most effective and easy-to-maintain privacy tools available.

Useful Pi-hole commands at a glance

All of these commands are typed in a terminal on the Raspberry Pi itself.

Command What it does
pihole status Shows whether Pi-hole is running and actively blocking, or has been paused.
pihole enable Re-enables blocking if you previously disabled or paused it.
pihole disable Disables blocking indefinitely (DNS requests are still answered, but nothing is blocked). Use pihole enable to turn blocking back on.
pihole disable 5m Disables blocking for 5 minutes, then automatically re-enables. Replace 5m with 30s for 30 seconds or 1h for one hour.
pihole setpassword Set or reset the admin dashboard password.
pihole allow domain.com Add a domain to the allowlist (always let it through, even if it is on a blocklist).
pihole deny domain.com Add a domain to the denylist (always block it, even if it is not on any blocklist).
pihole update Update the Pi-hole software itself to the latest version.
pihole gravity Download and apply the latest versions of all subscribed blocklists.
pihole tail Show a live stream of DNS queries in the terminal as they happen (press Ctrl+C to stop).
pihole restartdns Restart the Pi-hole DNS service — useful if you have changed settings and want them to take effect immediately.

Troubleshooting common problems

The internet stopped working after setting up Pi-hole

First, check that the Pi is powered on and connected to the network. Open a terminal on the Pi and run pihole status — if Pi-hole itself is not running, restart it with pihole restartdns or reboot the Pi with sudo reboot. If the Pi is powered off, any device that has no secondary DNS server configured will lose the ability to browse the internet until the Pi comes back. As a short-term fix, you can temporarily put your router's original DNS address back in the router's DHCP settings while you investigate.

Devices are still not using Pi-hole

Force a DHCP renewal: on the affected device, disconnect from Wi-Fi and reconnect. On a Mac, turning Wi-Fi off and on (or clicking Renew DHCP Lease in System Settings → Network) does the same thing; on Linux, toggle the network connection off and on. On Windows, run the following two commands in a Command Prompt (not a terminal on the Pi — this is done on your Windows computer):

ipconfig /release
ipconfig /renew

These are Windows commands, not Pi commands — type them into a Command Prompt on your Windows PC. (On macOS or Linux, just toggle the network connection off and on instead, as described above.)

ipconfig /release — tells Windows to give up its current IP address and network settings (including the DNS server address).

ipconfig /renew — asks the router to issue fresh network settings, which should now include your Pi's IP address as the DNS server.

After renewing, open the Pi-hole query log in your browser — if queries from that device now appear there, it is correctly using Pi-hole.

A specific website is partially broken

Open the Pi-hole query log and search for your device's IP address in the client column. Look for red blocked entries that appeared at the same moment you loaded the broken page. Whitelist — or in Pi-hole v6, allow — the blocked domain and reload the page. Many news and media sites rely on sub-domains (for example cdn.example.com) that can end up on blocklists even though they serve legitimate content rather than adverts.

I forgot the Pi-hole admin password

Open a terminal on the Pi and run pihole setpassword to set a new one.

Pi-hole says it is running but blocking percentage stays at 0%

This usually means your devices are not yet using Pi-hole as their DNS server. Check the router's DHCP settings again to make sure the Pi's IP address is set as the Primary DNS, and force a DHCP renewal on your devices as described above.

Key terms

  • DNS (Domain Name System) — the internet's phone book; it translates human-readable domain names (like bbc.co.uk) into numerical IP addresses that computers use to find each other on the internet.
  • IP address — a numerical label (such as 192.168.1.100) that uniquely identifies a device on a network, like a postal address for a computer.
  • Pi-hole — free, open-source software that acts as a DNS server for your home network, automatically blocking known advertising and tracking domains before they can load on any device.
  • Blocklist — a list of domain names that Pi-hole refuses to answer look-up requests for, causing ads and trackers that use those domains to simply never load.
  • Allowlist (formerly whitelist) — a list of domains that Pi-hole always allows through, even if they appear on a blocklist; used to restore access to sites accidentally broken by over-enthusiastic blocking.
  • Denylist (formerly blacklist) — a list of domains you manually tell Pi-hole to always block, even if they do not appear on any subscribed blocklist.
  • DHCP (Dynamic Host Configuration Protocol) — the system your router uses to automatically assign IP addresses and settings (including the DNS server address) to devices that connect to your network.
  • DHCP reservation (static lease) — a router setting that always gives a specific device the same IP address, identified by the device's unique MAC address.
  • MAC address — a permanent, unique identifier built into every network adapter (Wi-Fi card or Ethernet socket), used by the router to recognise individual devices.
  • Upstream DNS — the external DNS server that Pi-hole forwards legitimate (non-blocked) queries on to; common choices are Cloudflare (1.1.1.1) or Google (8.8.8.8).
  • Gravity — Pi-hole's term for the process of downloading and combining all subscribed blocklists into a single, efficient local lookup database.
  • DNS over HTTPS (DoH) — a modern protocol that encrypts DNS requests so they are invisible to intermediate servers including Pi-hole; some devices and browsers use it automatically, potentially bypassing Pi-hole.
  • Shell script — a text file containing a sequence of terminal commands that can be run all at once; the Pi-hole installer is a shell script.

Chapter summary

  • Pi-hole works by placing itself between your home devices and the internet as a DNS server, silently blocking look-ups for known advertising and tracking domains before they even reach the internet.
  • Every device on your network benefits automatically once you point your router's DNS setting at the Pi's IP address — nothing needs to be installed on phones, tablets, or smart TVs.
  • Giving the Pi a fixed (static) IP address — either via a DHCP reservation in the router or by setting a static IP on the Pi itself using nmcli — is essential before installing Pi-hole.
  • The official installer is launched with a single curl -sSL https://install.pi-hole.net | sudo bash command; note the randomly generated admin password it displays when it finishes.
  • Pi-hole v6 (the current version on Bookworm) uses a web-based setup wizard at http://<pi-ip>/admin and a modernised command line: pihole allow, pihole deny, pihole update, pihole gravity, and pihole setpassword.
  • The admin dashboard provides real-time graphs, a query log showing every DNS look-up, and tools for managing allowlists, denylists, and additional blocklists.
  • Pi-hole cannot block YouTube in-app adverts or ads served from the same domain as legitimate content, but it typically blocks 20–30% of all home network requests, noticeably speeding up page loads.
  • When a site breaks, check the Query Log for red entries at the time of the breakage and use pihole allow domain.com to restore access to that domain.
