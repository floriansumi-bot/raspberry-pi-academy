Your Raspberry Pi 5 is on all day and all night, quietly sipping just a few watts of electricity — so why not put it to work as a proper home server? In this chapter you will turn your Pi into a network file share that every computer in your home — Windows, macOS, or Linux — can see, and then go a step further by installing your very own private cloud — your files, your photos, your calendar, all stored on hardware you own and control.

Note: This chapter has two independent parts. You can follow Part A (Samba file sharing) without ever doing Part B (Nextcloud), or do both. Read through a whole section before typing anything.

Part A — A Home File Server with Samba

What is a file server, and why do you want one?

Right now, if you want to move a photo from your laptop to your Pi, you probably copy it to a USB stick and carry it across the room. A file server fixes that. Once it is running, a shared folder on the Pi appears inside your computer's file browser — Windows File Explorer, macOS Finder, or a Linux file manager — just like any other drive. You drag files in, you drag files out, across the home network, with no cable required.

In plain words: A file server is a computer that holds files and lets other computers on the same network open, save, and copy those files as if they were on a local drive. "Server" just means "the one that serves the others".

The software that makes this possible on Linux is called Samba. Samba speaks the standard file-sharing language that Windows uses (called SMB, or "Server Message Block") — and which macOS and Linux speak too — so your computer and your Pi understand each other perfectly, whichever operating system you use.

In plain words: Samba is free, open-source software that lets a Linux computer speak Windows' own file-sharing language. It has been around since 1992 and is rock-solid.

What you will need

  • Your Pi 5, connected to the same home router as your main computer (by Ethernet cable or Wi-Fi — either works, but a cable is faster and more reliable for a file server).
  • A USB hard drive or USB stick to use as the shared storage (optional but recommended — keeps the shared data off the microSD card and allows much larger capacity).
  • A terminal window open on the Pi (or an SSH connection from your main computer — see Chapter 12).
Tip: Using a USB hard drive rather than the microSD card for shared storage is strongly recommended. microSD cards are not designed for constant read/write activity and can wear out faster. A cheap USB hard drive or a good-quality USB SSD will last far longer and hold far more.

Step 1 — Attach and mount a USB drive

Plug your USB drive into one of the Pi's blue USB 3.0 ports. Wait five seconds, then find out what name the Pi gave it:

lsblk

lsblk — "list block devices". It prints a tree of all storage devices the Pi can see. You are looking for your USB drive, which will appear as something like sda with a partition below it called sda1.

You should see output a bit like this:

NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINT
sda           8:0    1 119.2G  0 disk
└─sda1        8:1    1 119.2G  0 part
mmcblk0     179:0    0  59.6G  0 disk
├─mmcblk0p1 179:1    0   512M  0 part /boot/firmware
└─mmcblk0p2 179:2    0  59.1G  0 part /

sda — your USB drive (the whole physical device).

sda1 — the first partition on the USB drive. This is the part that actually holds files.

mmcblk0 — your microSD card. Leave this alone.

The MOUNTPOINT column shows where (if anywhere) the drive is currently accessible. sda1 may already be mounted automatically by Raspberry Pi OS.

Note: If your USB drive already has a MOUNTPOINT shown (such as /media/pi/MY-DRIVE), Raspberry Pi OS has already mounted it for you and you can skip the manual mount step below. Note the exact path shown — you will need it when configuring Samba.

If the MOUNTPOINT column for sda1 is blank, create a folder to attach it to and mount it manually:

sudo mkdir -p /mnt/usbdrive
sudo mount /dev/sda1 /mnt/usbdrive

sudo mkdir -p /mnt/usbdrive — creates a new empty folder at /mnt/usbdrive. The -p flag means "create any missing parent folders too; do not error if it already exists". sudo is needed because /mnt is a system folder.

sudo mount /dev/sda1 /mnt/usbdrive — "attaches" the USB partition to that folder. After this, any file you put into /mnt/usbdrive is actually written to the USB drive.

Now create the folder that you will actually share over the network, and give it the right permissions:

sudo mkdir -p /mnt/usbdrive/shared
sudo chown -R $USER:$USER /mnt/usbdrive/shared
sudo chmod 775 /mnt/usbdrive/shared

sudo mkdir -p /mnt/usbdrive/shared — creates a folder called shared inside the USB drive.

sudo chown -R $USER:$USER /mnt/usbdrive/shared — makes your Pi user account the owner of the folder. $USER is a variable that automatically fills in your current username (e.g., pi), so you do not need to type it manually.

sudo chmod 775 /mnt/usbdrive/shared — sets the folder's permissions so that the owner and group can read and write files, and others can read. This is the right balance for a home file server.

Careful: Some guides suggest chmod 777 for shared folders. This gives every account on the Pi (including any that might be compromised) full read/write access. Using chmod 775 combined with correct Samba user settings (which we set up next) is more secure and is the right approach for a home server.

Step 2 — Install Samba

sudo apt update
sudo apt install samba -y

sudo apt update — refreshes the Pi's list of available software from the internet. Always do this before installing something new.

sudo apt install samba -y — downloads and installs Samba. The -y flag automatically answers "yes" to the "do you want to continue?" question, so you do not have to type it.

Confirm it installed correctly:

samba --version

Prints the Samba version number. If you see something like Version 4.17.x or higher, the install succeeded. On Bookworm the version will be 4.17 or newer.

Step 3 — Configure the shared folder

Samba's configuration lives in a single text file: /etc/samba/smb.conf. You are going to add a section at the very bottom of that file describing your share. First, take a backup of the original file so you can always restore it:

sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak

Copies the original configuration file to a backup file called smb.conf.bak. If anything goes wrong, you can restore the original with sudo cp /etc/samba/smb.conf.bak /etc/samba/smb.conf.

Now open the file in the Nano text editor:

sudo nano /etc/samba/smb.conf

Opens the Samba configuration file in Nano, a simple terminal text editor. sudo is required because this is a system file that only the administrator may change.

Use the arrow keys to scroll all the way to the very bottom of the file. Then type the following block exactly as shown (spacing does not matter much, but the square brackets, equals signs, and exact keywords do):

[PiShare]
   comment = Raspberry Pi Shared Folder
   path = /mnt/usbdrive/shared
   browseable = yes
   writable = yes
   guest ok = no
   valid users = %S
   force user = pi
   create mask = 0664
   directory mask = 0775

[PiShare] — the name of the share. This is what appears when you connect from another computer (for example, \\raspberrypi\PiShare on Windows, or smb://raspberrypi then the PiShare folder on macOS and Linux). You can name it anything you like, but do not use spaces.

comment — a friendly description that Windows shows when browsing the network.

path — the actual folder on the Pi that this share points to.

browseable = yes — the share shows up automatically when Windows browses the network.

writable = yes — connected users can save and delete files, not just read them.

guest ok = no — anonymous access is not allowed; a password is required.

valid users = %S — only the user who authenticated to this share may connect (%S is a Samba variable meaning "the current share name's user"). You can also write valid users = pi if you prefer to be explicit.

force user = pi — any file written through the share is owned by the pi account on the Pi. Replace pi with your actual username if it is different.

create mask = 0664 — new files created through the share get sensible read/write permissions.

directory mask = 0775 — new folders created through the share also get sensible permissions.

Save and close: press Ctrl + O, then Enter to confirm the filename, then Ctrl + X to exit Nano.

Note: If your Pi username is not pi, check it by typing whoami in a terminal. Replace pi in the force user line with whatever your username is.

Check that your edited file has no typos:

testparm

testparm — a built-in Samba tool that reads your smb.conf and reports any errors. If it ends with "Loaded services file OK", your configuration is valid. If you see errors, open the file again with sudo nano /etc/samba/smb.conf and check your typing carefully.

Step 4 — Set a Samba password

Samba keeps its own password list separately from your Linux login password. You need to add your Pi user to that list:

sudo smbpasswd -a pi

sudo smbpasswd -a pi — adds the user pi to Samba's password database. The -a flag means "add". You will be prompted to type a new password twice. Choose something you will remember — you will need to enter it on Windows when connecting. Replace pi with your actual username if it is different.

Tip: Your Samba password does not have to be the same as your Linux login password. Many people keep them the same for simplicity, but they are stored in two separate places by Samba.

Step 5 — Restart Samba

sudo systemctl restart smbd
sudo systemctl enable smbd

sudo systemctl restart smbd — stops and starts the Samba service (smbd stands for "Samba Daemon") so it picks up your new configuration.

sudo systemctl enable smbd — tells the Pi to start Samba automatically every time it boots, so you do not need to restart it manually after a reboot.

Check it is running:

sudo systemctl status smbd

Shows whether the Samba service is active. You want to see active (running) highlighted in green. Press q to exit the status view and return to the command prompt.

Step 6 — Find your Pi's name or IP address

You will need either the Pi's hostname or its IP address to connect from your main computer. Run:

hostname
hostname -I

hostname — prints your Pi's network name. By default this is raspberrypi.

hostname -I — prints the Pi's IP address on your home network, for example 192.168.1.42. The first address shown is the one you want. Write it down — you will use it in the next step.

Step 7 — Connect from your computer

Connecting works the same way in spirit on every operating system: you point your file browser at the Pi using its hostname or IP address, then log in with your Samba username and password. Follow the steps for whichever computer you are using. In each case you can connect either by hostname (raspberrypi — works if your router supports name resolution) or by IP address (192.168.1.42 — always works; replace with your actual IP).

Windows

  1. Open File Explorer (the folder icon in the taskbar, or press Win + E).
  2. Click in the address bar at the top and type one of the following, then press Enter:
    • \\raspberrypi\PiShare — using the hostname
    • \\192.168.1.42\PiShare — using the IP address
  3. Windows will ask for a username and password. Enter pi (or your actual Pi username) and the Samba password you set in Step 4. Tick "Remember my credentials" so you do not need to log in every time.

macOS

  1. In Finder, choose Go → Connect to Server (or press Cmd + K).
  2. Type smb://raspberrypi (or smb://192.168.1.42 using the IP address) and click Connect.
  3. When prompted, choose Registered User, enter pi (or your actual Pi username) and the Samba password from Step 4, then pick the PiShare share. Tick Remember this password in my keychain to skip logging in next time.

Linux

  1. Open your Files manager and choose Other Locations (or press Ctrl + L to get an address bar).
  2. Type smb://raspberrypi/PiShare (or smb://192.168.1.42/PiShare using the IP address) and press Enter.
  3. When prompted, enter pi (or your actual Pi username) and the Samba password from Step 4. Choose Remember forever if you do not want to log in every time.

Once connected, the shared folder opens. You can drag and drop files into it, create folders, and save documents directly from any application — just as if it were a local drive.

Tip: You can make the share reconnect automatically so it is always there when you start your computer. On Windows, right-click the share in File Explorer after connecting, choose Map network drive, pick a letter (like Z:), and tick Reconnect at sign-in. On macOS, add the share to System Settings → General → Login Items so it mounts at login. On Linux, add a line for the share to /etc/fstab or bookmark it in your Files manager for one-click access.

Making the USB drive mount automatically on boot

At the moment, if the Pi restarts the USB drive may not mount automatically, and Samba will not be able to find the shared folder. Fix this by adding the drive to the Pi's startup mount list.

First, find the drive's unique identifier (called a UUID):

sudo blkid /dev/sda1

sudo blkid /dev/sda1 — prints details about the partition, including its UUID, which looks something like UUID="A1B2-C3D4" for a FAT32 drive or UUID="a1b2c3d4-e5f6-..." for a Linux-formatted drive. Copy this string carefully — you will need it in the next step. The output also shows the filesystem type (e.g., TYPE="vfat", TYPE="ntfs", TYPE="exfat", TYPE="ext4").

Note: Make a note of both the UUID and the TYPE shown by blkid. You will need both for the next step. Common types you might see: vfat = FAT32 (typical for drives formatted on Windows up to 32 GB), exfat = exFAT (Windows drives over 32 GB), ntfs = NTFS (Windows drives formatted for large files), ext4 = Linux format.

If your drive is exFAT formatted, install the tools to support it (they are not installed by default on Bookworm):

sudo apt install exfatprogs -y

Installs the exfatprogs package, which gives the Pi the ability to read and write exFAT-formatted drives. Only needed if your drive is exFAT. Skip this step if your drive is FAT32, NTFS, or ext4.

If your drive is NTFS formatted, install the NTFS support package:

sudo apt install ntfs-3g -y

Installs ntfs-3g, the open-source driver that lets Linux read and write NTFS drives (the format used by most Windows drives). Only needed for NTFS drives.

Now open the file system table to add the drive to the boot-time mount list:

sudo nano /etc/fstab

/etc/fstab — the "file system table". This is the list of drives the Pi mounts automatically on startup. You are adding your USB drive to this list so it is always available when the Pi boots.

Add a new line at the very bottom of the file. Use the correct TYPE you noted above. Examples for each format are shown — use only the one that matches your drive:

# FAT32 drive (vfat):
UUID=XXXX-XXXX  /mnt/usbdrive  vfat  defaults,nofail,uid=1000,gid=1000  0  0

# exFAT drive:
UUID=XXXX-XXXX  /mnt/usbdrive  exfat  defaults,nofail,uid=1000,gid=1000  0  0

# NTFS drive:
UUID=XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX  /mnt/usbdrive  ntfs-3g  defaults,nofail,uid=1000,gid=1000  0  0

# Linux ext4 drive:
UUID=XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX  /mnt/usbdrive  ext4  defaults,nofail  0  0

# FAT32 drive (vfat): — lines beginning with # are comments (ignored by the system). These are just labels to help you pick the right line.

UUID=XXXX-XXXX — replace this with your actual UUID from the blkid output. This identifies the drive by its permanent ID rather than its device name (which can change).

/mnt/usbdrive — the folder where the drive will be mounted (you created this earlier).

vfat / exfat / ntfs-3g / ext4 — the filesystem type. Use the one that matches your drive. Note that NTFS uses ntfs-3g (not just ntfs) so that the full-featured driver is used.

defaults,nofail — use standard settings; nofail is critical — it means "if the drive is missing at boot, do not panic or halt — just continue booting normally".

uid=1000,gid=1000 — makes the drive's files owned by the main user account (user ID 1000 is the first user created on Raspberry Pi OS, which is your account). This option applies to FAT32, exFAT, and NTFS — not ext4, which stores ownership in the filesystem itself.

0 0 — tells the Pi not to dump or automatically check this drive at startup.

Add only the one line relevant to your drive type, replacing XXXX-XXXX with your actual UUID. Save with Ctrl + O, Enter, Ctrl + X. Then test the entry without rebooting:

sudo mount -a

sudo mount -a — attempts to mount everything listed in /etc/fstab that is not already mounted. If there is a typo in your fstab entry, this command will show an error immediately so you can fix it before rebooting. If it runs silently with no errors, your entry is correct.

Careful: A typo in /etc/fstab can prevent the Pi from booting into a full desktop. Always run sudo mount -a immediately after editing to test for errors. If you do accidentally break the boot, remove the USB drive and reboot — with nofail set, the Pi should boot anyway without that drive and let you log in to fix the file.

Part B — Your Own Private Cloud with Nextcloud

What is Nextcloud and why would you want it?

Samba is brilliant for accessing files on your home network, but it has one limitation: it only works when you are connected to that same network at home. Nextcloud is a full personal cloud platform — think of it as a self-hosted version of Dropbox or Google Drive. It gives you:

  • A web browser interface to upload, download, and manage files from any device.
  • Automatic photo backup from your phone (Android and iPhone both supported).
  • A shared calendar and contacts that sync to your phone and PC.
  • Notes, tasks, and dozens of optional add-on apps.
  • Total privacy — your data lives on your hardware, not on anyone else's servers.
In plain words: Nextcloud is free, open-source software that gives you all the features of Google Drive or Dropbox, but stores everything on your own Pi. Nobody else can access your files.

Samba vs Nextcloud — which should you use?

Feature Samba (Part A) Nextcloud (Part B)
Access from home network Yes — fast and seamless Yes
Access from outside home No (not without complex setup) Yes (with port forwarding — see Chapter 21)
Phone app / auto photo backup No Yes (iOS and Android)
Calendar and contacts sync No Yes
Browser-based file manager No Yes
Difficulty to set up Easy Medium (we use the easiest route)
Resource usage Very light Moderate (runs comfortably on any Pi 5; more RAM helps if you have it)
Best for Simple local file sharing Full personal cloud, remote access, phone backup
Note: You can run both Samba and Nextcloud at the same time on the same Pi. They do not conflict with each other. Many people use Samba for everyday local file access and Nextcloud for phone backups and browser-based access.

The easiest installation route: Snap

There are several ways to install Nextcloud. The simplest for beginners is a snap package — a self-contained bundle that installs Nextcloud and everything it needs (a web server, a database, background workers) in one single command, without you having to configure any of those pieces separately.

In plain words: A snap is a type of software package that bundles an application together with all the extra software it depends on, so you do not have to install or configure those pieces yourself. Think of it as buying a ready-made meal rather than cooking from scratch.

First, make sure the snap system is installed and up to date:

sudo apt update
sudo apt install snapd -y

sudo apt update — refreshes the package list.

sudo apt install snapd -y — installs the snap package manager. If it is already present, this does nothing harmful.

Careful: After installing snapd for the first time, you must reboot before installing any snap package. Snap will not work correctly until the Pi has restarted. Run sudo reboot now and wait for the Pi to come back up before continuing.
sudo reboot

Restarts the Pi. Wait about 30 seconds for it to come back up, then open a new terminal or reconnect via SSH before continuing. This reboot is required for snapd to fully initialise itself.

After the Pi has restarted, install Nextcloud:

sudo snap install nextcloud

Downloads and installs the Nextcloud snap package. This will take several minutes as it is a large download (several hundred megabytes). You will see a progress indicator. When it finishes you will see a message like nextcloud 28.x.x from Nextcloud✓ installed.

Note: The snap version of Nextcloud is maintained by the Nextcloud team themselves and is regularly updated. It bundles the Apache web server, a MySQL-compatible database, and PHP — all the parts Nextcloud needs — so you do not have to install or configure any of them separately.

Step 1 — Create your admin account

The snap installs Nextcloud but waits for you to choose an administrator username and password before it starts. Run the following command, replacing the placeholders with your choices:

sudo nextcloud.manual-install admin YourStrongPasswordHere

sudo nextcloud.manual-install — runs the Nextcloud first-run installer that is included in the snap.

admin — the administrator username you will use to log in. You can change this to anything you like (for example, your first name).

YourStrongPasswordHere — your admin password. Choose something strong — at least 12 characters with a mix of upper and lower case letters, numbers, and symbols. This is what protects your entire cloud.

Careful: Do not use the example password shown above. Choose your own strong password and write it down somewhere safe. If you lose the admin password, recovering access is a technical process and can result in losing access to your files.

Step 2 — Allow your home network to access Nextcloud

By default Nextcloud only accepts connections from the Pi itself (called "localhost"). You need to tell it to also accept connections coming from your home network, using the Pi's IP address.

First, check your Pi's IP address if you have not done so already:

hostname -I

Prints the Pi's IP address on your local network. Note the first address shown — it will be something like 192.168.1.42. Use your actual address in the commands below.

Now add your Pi's IP address as a trusted domain for Nextcloud:

sudo nextcloud.occ config:system:set trusted_domains 1 --value=192.168.1.42

sudo nextcloud.occ — the Nextcloud command-line management tool, included in the snap. occ stands for "ownCloud Console" — Nextcloud evolved from a project called ownCloud and kept the tool name.

config:system:set trusted_domains 1 — adds a second trusted domain entry (slot 0 is already set to localhost). Slot 1 is the first one you are adding.

--value=192.168.1.42 — replace this with your Pi's actual IP address. This tells Nextcloud "it is safe to serve web pages to browsers that connect using this address".

Also add your Pi's hostname so you can connect using either the name or the IP address:

sudo nextcloud.occ config:system:set trusted_domains 2 --value=raspberrypi

Adds raspberrypi (the Pi's default hostname) as a third trusted domain (slot 2). After this you can reach Nextcloud at either http://192.168.1.42 or http://raspberrypi from any device on your home network.

Step 3 — Point Nextcloud at your USB drive for storage

By default the Nextcloud snap stores all uploaded files on the microSD card. For a home server holding photos and documents, you almost certainly want it to use your larger, more durable USB drive instead. Do this now — before you upload any files — because moving the data directory after files have been added is more complex.

Make sure your USB drive is mounted at /mnt/usbdrive (as set up in Part A). Then create a dedicated folder for Nextcloud's data:

sudo mkdir -p /mnt/usbdrive/nextcloud-data

Creates a folder on the USB drive that Nextcloud will use to store all uploaded files, photos, and documents. The -p flag prevents an error if the folder already exists.

Set the correct permissions on that folder so the Nextcloud snap can write to it:

sudo chown -R www-data:www-data /mnt/usbdrive/nextcloud-data
sudo chmod 750 /mnt/usbdrive/nextcloud-data

sudo chown -R www-data:www-data /mnt/usbdrive/nextcloud-data — sets the owner and group of the folder to www-data. This is the user account that the Nextcloud snap's web server runs as. Without this, Nextcloud cannot write files there.

sudo chmod 750 /mnt/usbdrive/nextcloud-data — sets permissions so that www-data has full access, other accounts in the same group can read, and everyone else is locked out. This is the correct, secure setting for a Nextcloud data folder.

Careful: The ownership (www-data) matters. If you used chown root:root or your own username, Nextcloud will fail silently and uploads will not work. Use www-data exactly as shown.

Now tell Nextcloud to use this folder as its data directory:

sudo nextcloud.occ config:system:set datadirectory --value=/mnt/usbdrive/nextcloud-data

Updates Nextcloud's configuration to point its data storage at the new folder on the USB drive. From now on, every file you upload through Nextcloud will be saved there.

Restart Nextcloud to apply all changes:

sudo snap restart nextcloud

Stops and restarts all the components bundled in the Nextcloud snap — the web server, database, and background job workers. This is necessary for the new configuration to take effect.

Step 4 — Open Nextcloud in a browser

  1. On any device on your home network (your computer, your phone, your tablet), open a web browser.
  2. Type your Pi's IP address into the browser's address bar and press Enter: http://192.168.1.42 (use your actual IP address).
  3. The Nextcloud login page appears. Log in with the admin username and password you chose in Step 1.
  4. Nextcloud may show a short "first run" wizard — follow the prompts or click Skip to go straight to your files.
  5. You are inside your private cloud. Click the Files icon to see your file storage. Click the + (upload) button to upload your first file.
Tip: Nextcloud works on any device with a modern web browser — Windows, Mac, Android, iPhone. There is nothing to install on the other devices to use the web interface. Just open a browser and go to your Pi's address.

Step 5 — Install the Nextcloud phone app

The real power of having a personal cloud on your phone is automatic photo backup — every photo you take is silently copied to your Pi in the background, giving you a private alternative to iCloud or Google Photos.

  1. On your Android phone, open the Play Store and search for Nextcloud. On iPhone, open the App Store. Install the free official Nextcloud app (blue icon).
  2. Open the app. Tap Log in.
  3. When asked for the server address, enter: http://192.168.1.42 (your Pi's IP address). Note that you must be on the same home Wi-Fi network as the Pi for this to work. Tap Next.
  4. Log in with your admin username and password.
  5. To enable auto backup: on Android, tap the three-line menu, then Auto upload. On iPhone, tap the Photos tab. Enable automatic upload and choose Wi-Fi only to avoid using mobile data.

From this point on, every photo or video you take will automatically back itself up to your Pi the next time your phone is connected to your home Wi-Fi network.

Tip: The Nextcloud app also lets you access all your Pi files from your phone — you can open documents, play music, and view photos stored on the Pi without them taking up space on your phone's internal storage.

Keeping Nextcloud updated

Because you installed Nextcloud as a snap, updates are handled automatically in the background by the snap system. If you ever want to check for or apply an update manually:

sudo snap refresh nextcloud

Checks whether a newer version of the Nextcloud snap is available and installs it if so. This is safe to run at any time. If Nextcloud is already up to date, it will tell you so and do nothing.

Security: keep your cloud private

Careful: The setup in this chapter makes Nextcloud accessible only on your home network. Do not open your router's firewall to expose Nextcloud to the internet without first reading Chapter 21, which covers HTTPS encryption certificates, firewall rules, and using a reverse proxy or VPN tunnel. Exposing a web service to the open internet without those protections could allow strangers to attempt to log in to your cloud or access your files.

As long as Nextcloud is reachable only on your home Wi-Fi (the default after following this chapter), it is protected by your router's built-in firewall. Visitors to your home cannot reach it unless they are connected to your Wi-Fi.

Keeping everything backed up

A home server is only as useful as its backups. The Pi and the USB drive are in your home — a power surge, a flood, or a fire could wipe everything out. Always follow the 3-2-1 backup rule:

In plain words: The 3-2-1 rule says: keep 3 copies of your data, on 2 different types of storage, with 1 copy stored somewhere physically separate (offsite or in the cloud). For example: original on the Pi's USB drive (copy 1), a second USB drive stored in a cupboard (copy 2), and a copy uploaded to a free cloud service or held at a family member's house (copy 3).

A simple way to back up the Nextcloud data folder to a second USB drive (which you would mount at /mnt/backup-drive):

sudo rsync -av /mnt/usbdrive/nextcloud-data/ /mnt/backup-drive/nextcloud-backup/

sudo rsync — "remote sync", a powerful and efficient tool for copying files. It only copies files that have changed since the last run, so after the first full copy, subsequent runs are very fast.

-a — "archive mode": preserves file permissions, ownership, timestamps, and copies all subdirectories recursively.

-v — "verbose": prints the name of each file as it copies it, so you can see what is happening.

/mnt/usbdrive/nextcloud-data/ — the source folder (your Nextcloud data). The trailing slash is important — it means "copy the contents of this folder", not the folder itself.

/mnt/backup-drive/nextcloud-backup/ — the destination folder on a second USB drive. You would need to mount that second drive at /mnt/backup-drive first.

You can automate this backup to run every night using cron — the scheduling tool covered in Chapter 15.

Keeping the Pi powered safely

Careful: A home server needs reliable power. If the Pi loses power while writing files, those files can become corrupted. Consider plugging the Pi's power supply into a small UPS (Uninterruptible Power Supply) — a battery backup box available for around £30–60 that keeps the Pi running for 10–30 minutes during a power cut, giving it time to finish what it is doing and shut down gracefully.
Note: When you want to switch the Pi off properly, always shut it down from the desktop menu or by typing sudo shutdown -h now in a terminal, then wait for the activity light to stop blinking before unplugging the power. Never just pull the power cable — this is the most common cause of microSD card corruption.

Troubleshooting common problems

Your computer cannot see the Pi on the network

  • Make sure both devices are on the same network (same router, same Wi-Fi network name).
  • Try connecting by IP address (\\192.168.1.42\PiShare on Windows, or smb://192.168.1.42 on macOS and Linux) rather than by hostname — some routers do not pass hostnames between devices.
  • Check Samba is running: sudo systemctl status smbd
  • Check whether the Pi's firewall is active and blocking Samba: sudo ufw status. If it shows as active, allow Samba through with: sudo ufw allow samba
  • On Windows, make sure "Network discovery" is turned on. Open Settings → Network & Internet → Advanced network settings → Advanced sharing settings and enable network discovery. (On macOS and Linux you connect to the share directly using the Connect to Server / Other Locations steps from Step 7, so no equivalent setting is needed.)

Nextcloud shows a warning about "insecure connection" or "not secure"

This is expected when using plain http:// rather than encrypted https://. Within your home Wi-Fi, the connection is acceptable — your router already encrypts the Wi-Fi signal itself. If you want a proper padlock in the browser bar (which is especially important before enabling access from outside your home), Chapter 21 explains how to add a proper HTTPS certificate.

Nextcloud is very slow

  • Check the Pi is not overheating: run vcgencmd measure_temp in a terminal. If the temperature is above 80°C, improve ventilation around the Pi or check the active cooler fan is spinning.
  • Make sure the USB drive is plugged into one of the blue USB 3.0 ports (the two at the back of the board), not the black USB 2.0 ports. USB 3.0 is around ten times faster for large file transfers.
  • The first time Nextcloud scans the data folder or processes a large photo album, it will be briefly slow — this is normal and will speed up after the initial indexing is complete.

Nextcloud shows "Could not connect to database"

The snap's internal database service may not have started yet. Wait 60 seconds after a reboot and try again, or manually restart the snap: sudo snap restart nextcloud

The shared USB drive does not appear after a reboot

  • Check the /etc/fstab entry you added. Open it with sudo nano /etc/fstab and look for typos.
  • Run sudo mount -a and watch for any error messages — they will tell you exactly what is wrong.
  • Make sure you have the correct filesystem type. If in doubt, run sudo blkid /dev/sda1 again to check. Remember to use ntfs-3g (not just ntfs) for NTFS drives, and make sure ntfs-3g is installed.

Key terms

  • Samba — free software that lets a Linux computer speak the standard SMB file-sharing language, making the Pi's folders appear as network drives on any computer — Windows File Explorer, macOS Finder, or a Linux file manager.
  • SMB (Server Message Block) — the network protocol Windows uses to share files and printers across a local network. Samba implements this protocol on Linux.
  • File server — a computer whose main job is to store files and make them available to other computers on the same network.
  • Nextcloud — free, open-source personal cloud software that gives you a private Dropbox/Google Drive on your own hardware, with browser access, phone backup, and calendar sync.
  • Snap — a self-contained software package that bundles an application with all its dependencies, simplifying installation and updates.
  • Mount / mounting — attaching a storage device (like a USB drive) to the Linux file system at a specific folder, so the operating system can read and write it.
  • UUID (Universally Unique Identifier) — a permanent identifier assigned to a storage partition. Using a UUID in /etc/fstab ensures the correct drive is always mounted, even if device names change between reboots.
  • fstab — the file /etc/fstab that tells Linux which drives to mount automatically at startup, and how.
  • nofail — an fstab option that tells the Pi to continue booting normally even if a listed drive is missing or cannot be mounted.
  • www-data — the user account that web servers on Linux (including Nextcloud's bundled Apache server) run as. Files that a web server needs to write must be owned by this account.
  • trusted_domains — a Nextcloud security setting that lists the addresses from which it will accept web connections. Addresses not on this list are refused.
  • rsync — a command-line tool for efficiently copying and synchronising files, only transferring data that has changed since the last run.
  • 3-2-1 backup rule — keep three copies of your data, on two different media types, with one copy stored offsite or in a separate physical location.
  • UPS (Uninterruptible Power Supply) — a battery backup box that keeps a device running for a short time during a power cut, preventing file corruption from sudden shutdowns.

Chapter summary

  • Samba turns the Pi into a file server that any computer can reach: install it with apt, add a share block to /etc/samba/smb.conf, set a Samba password with smbpasswd, restart the service, and connect using the Pi's IP address from Windows File Explorer (\\pi-ip), macOS Finder, or a Linux file manager (smb://pi-ip).
  • A USB hard drive connected to the Pi's blue USB 3.0 port gives the shared folder far more space and longevity than the microSD card alone.
  • Adding the USB drive to /etc/fstab with the nofail option ensures it mounts automatically on every boot without risking startup failures if the drive is absent.
  • Use the correct filesystem type in fstab: vfat for FAT32, exfat for exFAT (install exfatprogs first), ntfs-3g for NTFS (install ntfs-3g first), or ext4 for Linux-formatted drives.
  • After installing snapd, you must reboot the Pi before installing any snap package — this is a required step often missed by beginners.
  • Nextcloud, installed as a single snap package, gives you a full personal cloud: browser-based file access, phone photo backup, and calendar and contacts sync — all stored on your own hardware.
  • The Nextcloud data folder must be owned by the www-data user — not root or your own account — for the snap to write files correctly.
  • The Nextcloud phone app (free, iOS and Android) can automatically back up every photo you take to the Pi whenever your phone is on home Wi-Fi.
  • Keep Nextcloud accessible only on your home network until you have read Chapter 21 on HTTPS and firewall security — never expose it directly to the internet without those protections.
  • Always shut the Pi down gracefully before unplugging it, and consider a UPS to protect against sudden power cuts corrupting your files.
  • Follow the 3-2-1 backup rule — at least one copy of your important data should be stored offsite or on a separate physical drive.
